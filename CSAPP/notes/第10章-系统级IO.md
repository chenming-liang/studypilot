## 1. 两套 I/O：系统级与标准级

C 程序面对两套 I/O 接口，它们的功能有重叠：

- **Unix I/O**（系统级，`open`/`read`/`write`/`close`…）：内核提供的**基本操作**，最大控制、最少便利，**可在信号处理程序中使用**、**可用于网络连接**；
- **标准 I/O**（C 库，`fopen`/`fread`/`fscanf`/`fgets`…）：更少的控制、更多的便利，**在信号处理程序中不安全**、**不适合网络连接**。

两者不是并列的：标准 I/O 是**建立在 Unix I/O 之上**的封装。讲义用"反汇编级"的视角展示：

```c
// fopen 内部就是 open + fdopen
FILE *fopen(const char *fname, const char *mode) {
    int fd = open(fname, __mode2flags(mode), DEFFILEPERMS);
    if (fd == -1) return NULL;
    return fdopen(fd, mode);
}

// fputs 内部就是循环 write
int fputs(const char *s, FILE *fp) {
    size_t n = strlen(s);
    while (n > 0) {
        ssize_t written = write(fp->fd, s, n);
        if (written < 0) return EOF;
        n -= written;
        s += written;
    }
    return 0;
}

// close 的汇编：系统调用号 3 放 %eax，syscall，返回值与 -4096 比较判断错误
.globl close
close:
    mov $3, %eax
    syscall
    cmp $-4096, %rax
    jae __syscall_error
    ret
```

**为什么有两套**：系统级 I/O 直接、底层；标准 I/O 方便、带缓冲。你甚至可以自己写一套高层函数（CS:APP 的 RIO 包就是例子，见 §13）。

## 2. Unix I/O 基础

**文件** = 一个字节序列 $B_0, B_1, \dots, B_k, \dots, B_{m-1}$。

**有趣的事实 1：所有 I/O 设备都被表示为文件**——`/dev/sda2`（磁盘分区）、`/dev/tty2`（终端）、`/dev/null`（丢弃所有写入、读出空文件）。
**有趣的事实 2：内核数据结构也被暴露为文件**——`cat /proc/$$/status`、`ls -l /proc/$$/fd/`、`ls -RC /sys/devices`（"一切皆文件"）。

内核为**所有文件**提供一组基本操作：
- 打开与关闭：`open()` / `close()`
- 读与写：`read()` / `write()`
- 查询文件信息（大小、类型、最后修改时间…）：`stat()` / `lstat()` / `fstat()`
- 改变当前文件位置（下一次读写的偏移，即当前文件位置 = k，位于字节 k−1 与 k 之间）：`lseek()`

## 3. 文件类型、目录与路径

**文件类型 (file type)** 指示文件在系统中的角色：
- **普通文件 (regular file)**：存储任意数据；
- **目录 (directory)**：一组相关文件的索引；
- **socket**：与另一台机器上的进程通信；
- 范围之外的类型：命名管道 (FIFO)、符号链接、字符/块设备。

**普通文件**：应用常区分**文本**与**二进制**（文本 = 人类可读；二进制 = 其余一切，如目标文件、JPEG）——但**内核不关心**，全是字节。文本文件是文本行的序列；文本行是以**行结束指示符（EOL）终止**（不是分隔！）的字符序列。EOL 指示符：Unix 用单字节 `0x0A`（LF）；DOS/Windows 用两字节 `0x0D 0x0A`（CR LF），许多 Internet 协议也用 CRLF；C 库统一翻译为 `'\n'`。

**目录**：条目（也称链接，link）数组，每个条目把一个**文件名**映射到一个**文件**。每个目录至少有两个条目：`.`（映射到目录自身）和 `..`（映射到父目录）。操作：`mkdir` 建空目录、`ls` 查看、`rmdir` 删空目录。

**目录层级**：所有文件组织成以根目录 `/` 为锚的层级；内核为每个进程维护**当前工作目录 (cwd)**（用 `cd` 修改）。路径名分两种：**绝对路径名**（以 `/` 开头，从根出发，如 `/home/droh/hello.c`）与**相对路径名**（从 cwd 出发，如 `../droh/hello.c`）。

## 4. 打开、关闭、读、写

**打开文件**：告知内核准备访问该文件，返回小整数**文件描述符 (file descriptor)**；`fd == -1` 表示出错。每个进程开始时自带三个打开文件：**0 标准输入 (stdin)、1 标准输出 (stdout)、2 标准错误 (stderr)**——它们可能是文件、管道、终端甚至网络连接。

```c
int fd;
if ((fd = open("/etc/hosts", O_RDONLY)) < 0) {
    perror("open");
    exit(1);
}
```

**open 的多种调用形式**：`flags` 必须且只能包含一个访问模式 `O_RDONLY` / `O_WRONLY` / `O_RDWR`，可用 `|` 组合修饰：`O_CREAT`（不存在则创建）、`O_APPEND`（写都到末尾）、`O_TRUNC`（删除已有内容）、`O_CLOEXEC`（`execve` 时关闭）、`O_EXCL`（文件已存在则失败）等。

**第三个参数**：open 接受两个或三个参数（C 里用变长参数实现，可翻 `/usr/include/fcntl.h`）。当 `flags` 含 `O_CREAT` 时**必须**给出第三个参数——新文件的默认访问权限，受 **umask** 影响；除非有特殊理由，用 `DEFFILEMODE`（`sys/stat.h`）。

**关闭文件**：告知内核用完该文件。注意：
- **不要重复关闭**同一个文件（就像不要对同一指针 free 两次）；
- **close 也可能失败**！不检查可能静默丢数据。

```c
if (close(fd) < 0) {
    fprintf(stderr, "%s: write error: %s", filename, strerror(errno));
    exit(1);
}
```

**读文件**：把字节从当前文件位置复制到内存，然后更新文件位置。返回值 `ssize_t`（有符号整数）：`< 0` 表示错误；**short count（读到的字节 < 请求的字节）是可能发生的，且不是错误**。

```c
char buf[512];
int fd;                 /* file descriptor */
int nbytes;             /* number of bytes read */
if ((nbytes = read(fd, buf, sizeof(buf))) < 0) {
    perror("read");
    exit(1);
}
```

**写文件**：把字节从内存复制到当前文件位置并更新位置。与读一样，short count 可能发生且不是错误。

**逐字节拷贝 stdin → stdout**（第一个版本——**永远要检查系统调用的返回码**）：

```c
#include <unistd.h>
int main(void) {
    char c;
    while (read(STDIN_FILENO, &c, 1) != 0)
        write(STDOUT_FILENO, &c, 1);
    return 0;
}
```

健壮版（处理 EOF 与错误）：

```c
#include <unistd.h>
#include <stdio.h>
int main(void) {
    char c;
    for (;;) {
        ssize_t nread = read(STDIN_FILENO, &c, 1);
        if (nread == 0) return 0;          /* EOF */
        else if (nread < 0) { perror("stdin"); return 1; }
        if (write(STDOUT_FILENO, &c, 1) < 1) {
            perror("stdout: write error");
            return 1;
        }
    }
}
```

用 **Stevens 包装 (wrapper)** 的版本（`Read`/`Write` 首字母大写）更短——但**它们不让你从错误中恢复**。

## 5. Short Counts

**会发生 short count 的情况**：
- 读时遇到文件末尾 (EOF)；
- 从终端读文本行；
- 读写网络 socket、管道等。

**绝不会发生 short count 的情况**：
- 读磁盘文件（除 EOF 外）；
- 写磁盘文件。

**最佳实践：永远为 short count 留出余地**——这是网络编程的起点（CS:APP 的 RIO 包就是为此而生，见 §13）。

## 6. 标准 I/O 与缓冲

C 标准库（`libc.so`）提供高层标准 I/O 函数：`fopen`/`fclose`、`fread`/`fwrite`、`fgets`/`fputs`、`fscanf`/`fprintf`（K&R 附录 B 有文档）。

**流 (stream)**：标准 I/O 把打开的文件建模为"文件描述符 + 内存缓冲区"的抽象。程序开始时自带三个流：`stdin`、`stdout`、`stderr`（`stdio.h` 中定义，对应描述符 0/1/2）。

**为什么需要缓冲**：应用经常**逐字符**读写（`getc`/`putc`/`fgets`）。若每次都走 Unix I/O，就是每次一个内核调用——**超过 10,000 个时钟周期**。解法：用一次 Unix `read` 抓一大块字节进缓冲区，用户函数从缓冲区逐字节取；缓冲区空了再补充。

**标准 I/O 的缓冲行为**：缓冲在遇到 `'\n'`、调用 `fflush`、`exit`、或从 `main` 返回时**冲刷 (flush)** 到输出 fd。用 `strace` 可以看到真相：

```
linux> strace ./hello
write(1, "hello\n", 6) = 6
```

——五个 `printf("h")`/`printf("e")`… 最终只产生**一次** `write` 系统调用。另外：**内核还有一层缓冲**（页缓存/块缓冲），用户缓冲之上还有内核缓冲。

## 7. 该用哪套 I/O

**Unix I/O 的优点**：最通用的 I/O 形式（其他所有 I/O 包都建立在它之上）；提供访问文件元数据的函数；**异步信号安全 (async-signal-safe)**，可在信号处理程序中安全使用。
**Unix I/O 的缺点**：处理 short count 麻烦易错；高效读文本行需要自己写缓冲，同样麻烦易错。

**标准 I/O 的优点**：缓冲减少 read/write 系统调用次数、提高效率；**自动处理 short count**。
**标准 I/O 的缺点**：不提供文件元数据访问；**不是异步信号安全**，不适合信号处理程序；**不适合网络 socket 的 I/O**（流上有些文档不全的限制与 socket 的限制互相冲突，见 CS:APP 3e §10.11）。

**选择规则**：
- 通用规则：**能用多高层就用多高层**——多数 C 程序员靠标准 I/O 就能完成所有工作，但要理解所用函数；
- 用标准 I/O：处理"普通"文件时；
- 用裸 Unix I/O：在信号处理程序里（异步信号安全）；读写网络 socket 时（专门的缓冲网络 I/O 库更好：CS:APP 的 `rio_*`、libevent、libuv…）；极少数需要绝对最高性能时。

**二进制文件警示**：绝不要对二进制文件用**面向文本的函数**（`fgets`、`scanf`、`rio_readlineb`——它们会解释 EOL 字符；改用 `rio_readn`/`rio_readnb`），也绝不要用**字符串函数**（`strlen`/`strcpy`/`strcat`——它们把字节值 0 当特殊意义）。

## 8. 文件元数据

**元数据 (metadata)** 是关于数据的数据（这里是关于文件数据的数据），由内核按文件维护，用户通过 `stat`/`fstat` 访问：

```c
struct stat {
    dev_t     st_dev;      /* Device */
    ino_t     st_ino;      /* inode */
    mode_t    st_mode;     /* Protection and file type */
    nlink_t   st_nlink;    /* Number of hard links */
    uid_t     st_uid;      /* User ID of owner */
    gid_t     st_gid;      /* Group ID of owner */
    dev_t     st_rdev;     /* Device type (if inode device) */
    off_t     st_size;     /* Total size, in bytes */
    unsigned long st_blksize; /* Blocksize for filesystem I/O */
    unsigned long st_blocks;  /* Number of blocks allocated */
    time_t    st_atime;    /* Time of last access */
    time_t    st_mtime;    /* Time of last modification */
    time_t    st_ctime;    /* Time of last change */
};
```

用法（判断类型与读权限）：

```c
if (S_ISREG(stat.st_mode))        /* Determine file type */
    type = "regular";
else if (S_ISDIR(stat.st_mode))
    type = "directory";
else
    type = "other";
if ((stat.st_mode & S_IRUSR))     /* Check read access */
    readok = "yes";
else
    readok = "no";
```

运行效果：`./statcheck statcheck.c` → `type: regular, read: yes`；`chmod 000` 后 → `read: no`；`./statcheck ..` → `type: directory, read: yes`。

## 9. 内核如何表示打开文件

内核用**三张表**表示一个进程的打开文件：

1. **描述符表 (descriptor table)**：**每个进程一张**，表项是文件描述符到打开文件表项的指针；
2. **打开文件表 (open file table)**：**所有进程共享**，每个表项包含：当前**文件位置 (file pos)**、访问模式、引用计数 (refcnt) 等；文件位置按"每个打开文件"维护；
3. **v-node 表 (v-node table)**：**所有进程共享**，每个表项包含 `stat` 结构里的信息（文件大小、类型、访问权限）和指向实际文件的指针。

> 直觉：描述符表是"个人通讯录"（每进程一份，记着 fd 号对应哪个打开文件）；打开文件表是"通话记录"（全局，记录着每个打开文件的当前位置）；v-node 表是"通讯录底册"（全局，文件的真实身份信息）。**文件位置记在打开文件表里**——这是理解共享与重定向的关键。

## 10. 文件共享与 fork

**情形 A：两个描述符指向两个不同的打开文件**（fd 1 → 终端，fd 4 → 磁盘文件）：三个表项互相独立，各自有文件位置。

**情形 B：同一磁盘文件被打开两次**（两次 `open` 同一个文件名）：产生**两个不同的打开文件表项**（各自独立的文件位置），但 v-node 表项相同——"不同逻辑、同一物理文件"。各自 read 会从各自的位置读。

**情形 C：fork 之后**：子进程**继承**父进程的打开文件——复制描述符表，且每个共享的打开文件表项 **refcnt + 1**。父、子的 fd 指向**同一个打开文件表项**，即**共享同一个文件位置**。（`exec` 不会改变这一局面，可用 `fcntl` 修改。）

## 11. I/O 重定向：dup2

**问题**：shell 怎么实现 `ls > foo.txt`？**答案**：`dup2(oldfd, newfd)`——把（每进程的）描述符表条目 `oldfd` **复制**到条目 `newfd`。

`dup2(4, 1)` 的效果：fd 1 不再指向原来的文件 A，而是指向 fd 4 指向的文件 B（文件 A 的打开文件表项 refcnt 减到 0，被关闭；文件 B 的 refcnt 变为 2）。此后写到 stdout（fd 1）的内容进入文件 B——这就是重定向。

**重定向的完整两步**：
1. `open` 要重定向到的目标文件（在子进程 exec 之前做）——fd 4 指向文件 B；
2. `dup2(4, 1)`——fd 1 与 fd 4 指向同一文件 B；"两个描述符指向同一个文件"。

## 12. 两个经典综合例子

讲义用两个程序把"文件位置"这条主线串起来：第一个看 `dup2` 如何让两个 fd 共享位置，第二个看 `fork` 如何让两个进程共享位置。

### ffiles1：dup2 共享文件位置

文件 `abcde.txt` 内容为 `abcde`：

```c
#include "csapp.h"
int main(int argc, char *argv[]) {
    int fd1, fd2, fd3;
    char c1, c2, c3;
    char *fname = argv[1];
    fd1 = open(fname, O_RDONLY, 0);
    fd2 = open(fname, O_RDONLY, 0);
    fd3 = open(fname, O_RDONLY, 0);
    dup2(fd2, fd3);          /* fd3 与 fd2 共享同一个打开文件表项 */
    read(fd1, &c1, 1);
    read(fd2, &c2, 1);
    read(fd3, &c3, 1);
    printf("c1 = %c, c2 = %c, c3 = %c\n", c1, c2, c3);
    return 0;
}
```

**输出：`c1 = a, c2 = a, c3 = b`**。推导：fd1、fd2 各自 open → 两个独立打开文件表项（位置都从 0 开始）；`dup2(fd2, fd3)` 使 fd3 与 fd2 指向**同一个**表项；`read(fd1)` 读走 `a`（fd1 的位置 → 1）；`read(fd2)` 读走 `a`（fd2 的位置 → 1）；`read(fd3)` 读的是 **fd2/fd3 共享的位置 1** → `b`（位置 → 2）。

### ffiles2：fork 共享文件位置

```c
#include "csapp.h"
int main(int argc, char *argv[]) {
    int fd1;
    int s = getpid() & 0x1;
    char c1, c2;
    char *fname = argv[1];
    fd1 = open(fname, O_RDONLY, 0);
    read(fd1, &c1, 1);            /* c1 = 'a'，位置 → 1 */
    if (fork()) {                 /* Parent */
        sleep(s);
        read(fd1, &c2, 1);
        printf("Parent: c1 = %c, c2 = %c\n", c1, c2);
    } else {                      /* Child */
        sleep(1 - s);
        read(fd1, &c2, 1);
        printf("Child: c1 = %c, c2 = %c\n", c1, c2);
    }
    return 0;
}
```

**两种输出都可能**：`Parent: c1 = a, c2 = b` + `Child: c1 = a, c2 = c`，或两者互换。推导：fork 后父、子共享**同一个打开文件表项**（位置同为 1）；`s = getpid() & 0x1` 保证父、子各睡 0 秒和 1 秒（顺序确定）——**先醒的那个**从位置 1 读到 `b`，另一个随后读到 `c`。父/子谁先谁后取决于 PID 奇偶，所以两种输出都可能。关键：**fork 共享文件位置，因此两个进程的读取是"接力"而非"各读各的"**。

## 13. RIO 包

**RIO（Robust I/O）** 是 CS:APP 提供的一组包装函数，为**容易遭遇 short count** 的应用（如网络程序）提供高效且健壮的 I/O。两类函数：

**无缓冲的二进制数据 I/O**（接口与 Unix read/write 相同）：

```c
ssize_t rio_readn(int fd, void *usrbuf, size_t n);
ssize_t rio_writen(int fd, void *usrbuf, size_t n);
/* 返回：成功传输的字节数；0 表示 EOF（仅 rio_readn）；-1 表示错误 */
```

- 特别适合网络 socket 传输数据；`rio_readn` **只有遇到 EOF 才返回 short count**（只在知道要读多少字节时用）；`rio_writen` **永不返回 short count**；两者可在同一描述符上任意交错。

**带缓冲的文本行/二进制输入**：

```c
void rio_readinitb(rio_t *rp, int fd);
ssize_t rio_readlineb(rio_t *rp, void *usrbuf, size_t maxlen);
ssize_t rio_readnb(rio_t *rp, void *usrbuf, size_t n);
/* 返回：成功读取的字节数；0 表示 EOF；-1 表示错误 */
```

- `rio_readlineb` 从 fd 读最多 `maxlen` 字节的一行文本存入 `usrbuf`——特别适合从网络 socket 读文本行；停止条件：读满 `maxlen` 字节 / 遇到 EOF / 遇到 `'\n'`；
- `rio_readnb` 读最多 `n` 字节；停止条件：读满或 EOF；
- 缓冲的 RIO 函数**线程安全**，`rio_readlineb` 与 `rio_readnb` 可在同一描述符上任意交错；**警告：不要与 `rio_readn` 交错使用**。

代码可从 http://csapp.cs.cmu.edu/3e/code.html 下载（`src/csapp.c` 与 `include/csapp.h`）。
