## 1. 基本概念

### 指令集体系结构（ISA, Instruction Set Architecture）

ISA 是**程序员可见的指令集抽象**，它规定了处理器能执行的指令、寄存器、内存模型等。

常见的 x86 系列 ISA：

- **IA32**：Intel 32 位体系结构
- **x86-64**：64 位扩展，也称为 **x64** 或 **AMD64**
- 与之对比：**ARM**（精简指令集，常用于移动设备）

> **ISA vs 微结构**：ISA 是接口规范（如 x86-64），微结构（microarchitecture）是具体实现（如 Intel Core / AMD Zen）。同一 ISA 可以有不同微结构。

### CPU 中程序员可见的状态

每条指令执行时，CPU 中**程序员可见**的状态包括以下三个组件（内存是独立于 CPU 的存储系统）：

| 组件 | 作用 |
|------|------|
| **PC（程序计数器）** | 存放下一条指令的地址（在 x86-64 中为 `%rip`） |
| **寄存器文件（Registers）** | 16 个通用寄存器，存储最常使用的程序数据 |
| **条件码（Condition Codes）** | 记录最近一次算术或逻辑运算的状态信息（如是否为零、是否溢出） |

### 数据类型的字节数

| 类型 | 大小（字节） |
|------|-------------|
| 整数（int） | 4 |
| 长整数（long） | 8 |
| 指针 | 8 |
| 单精度浮点（float） | 4 |
| 双精度浮点（double） | 8 |
| 代码（指令） | 变长字节序列 |

> **核心结论**：ISA 是程序员可见的指令集抽象（x86-64/IA32/ARM）；程序员可见状态 = PC + 寄存器文件 + 条件码。

## 2. 从 C 到汇编

将 C 代码转换为汇编和机器代码的过程：

```bash
# 生成汇编代码（.s 文件）
gcc -Og -S sum.c          # -Og 表示 O1 级别的优化，适合调试

# 生成目标文件后反汇编
gcc -Og -c sum.c          # 生成 sum.o
objdump -d sum.o          # 反汇编目标文件，查看机器码对应的汇编
```

> `-Og` 是 CSAPP 全书使用的优化级别，它产生的汇编代码与 C 代码的结构对应关系最清晰，适合学习。

> **核心结论**：gcc -Og -S 生成汇编、objdump -d 反汇编；-Og 的汇编与 C 结构对应最清晰，适合学习。

## 3. 寄存器

x86-64 有 **16 个通用寄存器**，每个 64 位：

| 64 位 | 32 位 | 16 位 | 8 位 | 用途说明 |
|-------|-------|-------|------|---------|
| `%rdi` | `%edi` | `%di` | `%dil` | 第 1 个参数 |
| `%rsi` | `%esi` | `%si` | `%sil` | 第 2 个参数 |
| `%rdx` | `%edx` | `%dx` | `%dl` | 第 3 个参数 |
| `%rcx` | `%ecx` | `%cx` | `%cl` | 第 4 个参数 |
| `%r8` ~ `%r15` | `%r8d` ~ `%r15d` | `%r8w` ~ `%r15w` | `%r8b` ~ `%r15b` | 第 5~6 个参数及临时变量 |
| `%rax` | `%eax` | `%ax` | `%al` | 返回值 |
| `%rsp` | `%esp` | `%sp` | `%spl` | **栈指针** |
| `%rbx` | `%ebx` | `%bx` | `%bl` | 被调用者保存 |
| `%rbp` | `%ebp` | `%bp` | `%bpl` | 被调用者保存 / 可选帧指针 |

> 对低 32 位进行操作时，高 32 位会自动清零（x86-64 的特性）。

寄存器的子划分（以 `%rax` 为例）：

```
%rax — 64 位（8 字节）
  %eax — 32 位（%rax 的低 32 位）
    %ax — 16 位（%eax 的低 16 位）
      %al — 8 位（%ax 的低 8 位）
      %ah — 8 位（%ax 的高 8 位）
```

命名规则：`l` = **l**ow byte（低 8 位），`h` = **h**igh byte（高 8 位）。

| 64 位 | 32 位 | 16 位 | 低 8 位（l） | 高 8 位（h） |
|-------|-------|-------|-------------|-------------|
| `%rax` | `%eax` | `%ax` | `%al` | `%ah` |
| `%rdx` | `%edx` | `%dx` | `%dl` | `%dh` |
| `%rcx` | `%ecx` | `%cx` | `%cl` | `%ch` |
| `%rbx` | `%ebx` | `%bx` | `%bl` | `%bh` |

> 写 32 位子寄存器（如 `%eax`）时，x86-64 会自动将 `%rax` 的高 32 位清零。写 8 位或 16 位子寄存器（如 `%al`、`%ax`）则不会，高位保持原值。


> **核心结论**：16 个 64 位通用寄存器可拆为 32/16/8 位子寄存器；写 32 位自动清零高 32 位，写 8/16 位不清。

## 4. 数据访问与传送

程序操作的数据有三种来源：直接写在指令里的常数（立即数）、存在寄存器中的值、存在内存中的值。本节从操作数类型讲起，然后看数据如何传送、如何在内存中定位，最后引出地址计算的硬件复用。

### 操作数类型（Operand Types）

x86-64 指令中，操作数可以是以下三类之一：

| 类别 | 语法 | 示例 | 含义 |
|------|------|------|------|
| **立即数（Immediate）** | `$` + 整数 | `$0x1234` | 常数本身 |
| **寄存器（Register）** | `%` + 寄存器名 | `%rax` | 寄存器中的值 |
| **内存（Memory）** | 寻址模式（见后） | `(%rsp)` | 内存地址处的值 |

### 数据传送指令：movq

```assembly
movq source, dest
```

将源操作数的值**复制**到目的操作数。源可以是立即数、寄存器或内存；目的不能是立即数。

**数据传送方向**：

```
立即数  ──→  寄存器／内存
寄存器  ──→  寄存器／内存
内存    ──→  寄存器
```

> ⚠️ **x86-64 的限制**：不能直接从内存搬到内存（需要用两条指令）。
> ⚠️ **movq** 的 q 表示 quad word（8 字节），类似的还有 `movb`（1 字节）、`movw`（2 字节）、`movl`（4 字节）。

**mov 家族总结**：

| 指令 | 源大小 | 目标大小 | 高位怎么处理 | 用途 |
|------|--------|---------|------------|------|
| `movb` | 1 字节 | 1 字节 | 不涉及高位 | 直接复制 1 字节 |
| `movw` | 2 字节 | 2 字节 | 不涉及高位 | 直接复制 2 字节 |
| `movl` | 4 字节 | 4 字节 | **清零**高 32 位 | 32 位传送 |
| `movq` | 8 字节 | 8 字节 | 不涉及高位 | 64 位传送 |
| `movzbl` | 1 字节 | 4 字节 | **补 0** | 无符号扩展 |
| `movsbl` | 1 字节 | 4 字节 | **补符号位** | 有符号扩展 |
| `movzwl` | 2 字节 | 4 字节 | **补 0** | 16→32 无符号扩展 |

其中 `movzbl`（Move Zero-Extend Byte to Long）常用于 `setx` 之后，把单字节结果扩展为 32 位返回值。

### 寻址模式（Addressing Modes）

当操作数在内存中时，需要告诉 CPU 如何计算地址。x86-64 提供了三种寻址方式：

| 模式 | 语法 | 地址计算 | 示例 |
|------|------|---------|------|
| **寄存器间接** | `(R)` | `Mem[Reg[R]]` | `movq (%rcx), %rax` |
| **基址+偏移** | `D(R)` | `Mem[Reg[R] + D]` | `movq 8(%rsp), %rax` |
| **基址+索引+偏移** | `D(Rb, Ri, S)` | `Mem[Reg[Rb] + S * Reg[Ri] + D]` | `movq (%rdi, %rcx, 4), %rax` |

其中各参数的含义：
- `D`：常量偏移（displacement），可以是负数
- `Rb`：基址寄存器（base register）
- `Ri`：索引寄存器（index register），不能是 `%rsp`
- `S`：比例因子（scale），取值 1、2、4 或 8

> **常见用法**：
> - `8(%rsp)`：访问栈上第 2 个元素（跳过第一个 8 字节）
> - `(%rdi, %rcx, 4)`：访问 `rdi + rcx * 4` 处的内存（适合 int 数组索引）

> **核心结论**：操作数分立即数/寄存器/内存三类；mov 家族不能直接 mem→mem；三种寻址模式 (R)、D(R)、D(Rb,Ri,S)。

## 5. 地址计算与算术优化

寻址模式 `D(Rb, Ri, S)` 的硬件能高效计算 `Rb + S * Ri + D`。如果有一条指令能借用这份计算能力但**不去访存**，那它就能做快速的算术运算。这正是 `leaq` 的设计目的。

### leaq 的基本语义

```assembly
leaq source, dest
```

`leaq`（Load Effective Address）用寻址模式计算出地址，但**不访问内存**，直接把计算出的地址值写入目的寄存器。

"Effective Address" 中的 "Effective" 指的是经过基址+索引+偏移计算后的**最终地址**——指令加载的是这个地址本身，而不是地址处的内容。

### leaq 与寻址模式的关系

leaq 的源操作数使用与 movq 完全相同的寻址模式语法，但行为不同：

```asm
movq (%rdi), %rax    # 以 %rdi 为地址去访存，%rax = *(rdi)
leaq (%rdi), %rax    # 只计算地址 = %rdi，%rax = rdi       （不访存）
```

对于更复杂的寻址模式也是同理：

```asm
movq (%rdi, %rcx, 4), %rax   # %rax = *(rdi + rcx*4)，访存取值
leaq (%rdi, %rcx, 4), %rax   # %rax = rdi + rcx*4，只算地址
```

### leaq 的算术优化用途

由于寻址模式的硬件能在一条指令内完成"基址 + 索引 * 比例 + 偏移"，编译器经常用 leaq 做**常数乘法优化**。

**示例：return x * 12**

```assembly
leaq (%rdi, %rdi, 2), %rax    # %rax = x + x*2 = 3x
salq $2, %rax                  # %rax = 3x * 4 = 12x
```

将 `x * 12` 分解为 `3x * 4`：`leaq`（1 个周期）计算 3 倍，`salq`（1 个周期）左移完成乘以 4。总共 2 个周期，比 `imulq`（约 3 个周期）更快。

**leaq 的限制**：
1. 比例因子 `S` 只能取 1、2、4、8，无法直接计算 `*7`、`*11` 等质数倍数。
2. 只能做加法，不能做减法（`leaq (%rdi, -%rdi, 2)` 非法）。
3. 因此编译器只在常数可以分解为 $2^k(2^m + 1)$ 的形式时才会使用 leaq 优化。

> **不修改条件码**：leaq 不改变条件码寄存器的值，因此不会影响后续的条件判断。这让编译器可以灵活地在算术运算中插入 leaq 而不破坏已有状态。

### 括号 `()` 的含义——统一视图

括号在 x86-64 中始终表示"以寄存器中的值为地址"，但**去不去访问那个地址的数据，由指令决定**：

| 指令 | `( )` 的含义 | 结果（假设 `%rcx = 0x1000`，`0x1000` 处存 `42`） |
|------|-------------|---------------------------------------------------|
| `movq %rcx, %rax` | 直接传寄存器值（无括号） | `%rax = 0x1000` |
| `movq (%rcx), %rax` | **访存**：去 `0x1000` 拿值 | `%rax = 42` |
| `leaq (%rcx), %rax` | **不访存**：地址 = `0x1000`，直接放入 | `%rax = 0x1000` |

### 逻辑运算指令：xor / and / or

| 指令 | 含义 | C 运算符 |
|------|------|----------|
| `xorq` | 按位异或 | `^` |
| `andq` | 按位与 | `&` |
| `orq` | 按位或 | `|` |

最常见的用法——**寄存器清 0**：

```asm
xorq %rax, %rax        # %rax = 0（2 字节，比 movq $0, %rax 更短更快）
```

因为 `X ^ X = 0`，编译器清寄存器几乎都用 `xorq`。另一个常见用途——判断两个值是否相等：

```asm
xorq %rdi, %rsi        # 结果为 0 则相等
jz   equal_label
```

**判断规则**——看指令的第一个字母：

- **`mov`** / **`add`** / **`sub`** / **`cmp`** 等 → 括号里是地址，去那里取值。
- **`lea`** → 括号里是计算公式，算出值写入目的寄存器，**不访问内存**。

### 移位指令：shl / shr / sar

移位指令和 C 语言的 `<<`、`>>` 对应，区别在于汇编区分逻辑右移和算术右移：

| 指令 | 全称 | 行为 | 对应 C |
|------|------|------|--------|
| **`shl`**（或 `sal`） | Shift Left | 左移，低位补 0 | `x << k` |
| **`shr`** | Shift Right（逻辑） | 右移，**高位补 0** | 无符号的 `x >> k` |
| **`sar`** | Shift Arithmetic Right | 右移，**高位补符号位** | 有符号的 `x >> k` |

```asm
shl $2, %rax          # %rax = %rax << 2
shr $3, %rax          # %rax = %rax >> 3（逻辑，高位补 0）
sar $1, %rax          # %rax = %rax >> 1（算术，高位补符号位）
```

> **shl 和 sal 是同一个指令的两个名字**，因为左移低位总是补 0，不存在"逻辑"和"算术"的区别。右移则需要区分：`shr`（逻辑）用于无符号数，`sar`（算术）用于有符号负数。和你笔记里 Ch2 记的"逻辑右移补 0、算术右移补符号位"一一对应。

> **核心结论**：leaq 计算地址但不访存，编译器用它做常数乘法优化（分解为 2^k(2^m+1) 形式）；不修改条件码。

## 6. 条件码与条件传送

算术逻辑运算的结果会影响 CPU 的条件码寄存器，而条件码可以用于分支跳转或条件传送。本节介绍最基础的四个条件码、比较/测试指令和 setx 条件传送。

### 条件码寄存器

CPU 维护一组**条件码（Condition Codes）**，记录最近一次算术或逻辑运算的属性：

| 标志位 | 含义 | 说明 |
|--------|------|------|
| **CF（Carry Flag）** | 进位/借位标志 | 无符号运算发生溢出时置 1 |
| **SF（Sign Flag）** | 符号标志 | 结果为负数（最高位为 1）时置 1 |
| **ZF（Zero Flag）** | 零标志 | 结果为零时置 1 |
| **OF（Overflow Flag）** | 溢出标志 | 补码运算发生溢出时置 1 |

程序计数器 `%rip` 存放下一条待执行指令的地址。这一点在 `gdb` 调试时需要注意：`x/i $rip` 显示的是当前正在执行的指令，因为 CPU 在取指阶段已自动将 `%rip` 更新为下一条。

> 与 `%rsp`（栈指针）不同，`%rip` 不能作为通用寄存器使用，程序员通常不能直接修改它——它由分支指令、`call`/`ret` 等隐式控制。

### 比较指令：cmpq

```assembly
cmpq b, a
```

计算 `a - b`，根据结果设置条件码，**不修改寄存器**（差值丢弃）。

| 情形 | 设置的条件码 |
|------|-------------|
| `a == b` | `ZF = 1` |
| `a < b`（有符号） | `SF != OF` |
| `a < b`（无符号） | `CF = 1` |

> `cmpq` 非常像 `subq`（`a - b`），区别仅在于 subq 会写回目的寄存器，而 cmpq 只设置条件码。

### 测试指令：testq

```assembly
testq b, a
```

计算 `a & b`，根据结果设置条件码（CF = OF = 0，ZF 和 SF 按位与结果设定），**不修改寄存器**。

常见用途——检测某一位是否为 1：

```asm
testq %rax, %rax     # rax & rax，若 rax = 0 则 ZF = 1
# 常借来检查 rax 是否为零（等价于 cmpq $0, %rax，但更高效）

> **test 的本质**：`testq b, a` 计算 `a & b`（按位与），结果丢弃，只设条件码。
>
> - `testq X, X`（两个操作数相同）→ 相当于"和 0 比大小"，因为 `X & X = X`，所以 `ZF = (X == 0)`、`SF = (X < 0)`。
> - `testq X, Y`（两个操作数不同）→ 检查 `X & Y` 的结果，常用于掩码检测某一位是否为零。
>
> `test` 比 `cmp` 的优点：机器码更短，且不影响 CF/OF（强制置 0）。

```

### 条件传送指令：setx

`setx` 指令根据条件码的组合，将目的寄存器的**最低字节**设为 0 或 1：

```assembly
setx dest    # dest 必须是单字节寄存器（如 %al, %bl, %dil 等）
```

| 指令 | 条件 | 含义（有符号） |
|------|------|---------------|
| `sete` / `setz` | `ZF = 1` | 等于 / 零 |
| `setne` / `setnz` | `ZF = 0` | 不等于 / 非零 |
| `sets` | `SF = 1` | 负数 |
| `setns` | `SF = 0` | 非负 |
| `setg` | `~(SF ^ OF) & ~ZF` | 大于（`>`） |
| `setl` | `SF ^ OF` | 小于（`<`） |
| `setge` | `~(SF ^ OF)` | 大于等于（`>=`） |
| `setle` | `SF ^ OF \| ZF` | 小于等于（`<=`） |

| 指令 | 条件 | 含义（无符号） |
|------|------|---------------|
| `seta` | `~CF & ~ZF` | 大于 |
| `setb` | `CF = 1` | 小于 |

> **示例**：C 代码 `return a > b;` 编译为（假设 `a` 在 `%rdi`，`b` 在 `%rsi`）：
>
> ```assembly
> cmpq    %rsi, %rdi      # 计算 %rdi - %rsi
> setg    %al             # 若 %rdi > %rsi，则 %al = 1；否则 %al = 0
> movzbl  %al, %eax       # 将 %al 零扩展到 %eax（setg 只改了最低字节）
> ret
> ```
>
> 其中 `movzbl`（move zero-extend byte to long）将 `%al` 的 8 位值零扩展到 32 位，清空 `%eax` 的高位，确保返回值符合 `int` 类型的约定。

**movzbl vs movsbl**：

| 指令 | 全称 | 高位补什么 |
|------|------|-----------|
| `movzbl` | Move **Zero**-Extend Byte to Long | 补 **0**（无符号扩展） |
| `movsbl` | Move **Sign**-Extend Byte to Long | 补**符号位**（有符号扩展） |

```asm
# %al = 0x9A 时：
movzbl %al, %eax       # → %eax = 0x0000009A（154）
movsbl %al, %eax       # → %eax = 0xFFFFFF9A（-102）
```



> **核心结论**：CF/SF/ZF/OF 记录最近运算属性；cmpq 算差、testq 算与（都只设条件码）；setx 按条件码置目的寄存器最低字节。

## 7. switch 语句与跳转表



当 `switch` 的 case 值分布较密集时，编译器会生成**跳转表（Jump Table）**——一个存储目标代码段地址的指针数组。跳转表将多路分支的时间复杂度从 $O(n)$（逐次比较）降至 $O(1)$（一次间接跳转）。

![[Pasted image 20260705202830.png|switch 图解]]

### 对应 C 源代码

原始 C 代码如下：

```c
long switch_eg(long x, long y, long z) {
    long w = 1;           /* 对应汇编中的 %eax / %rax */
    switch (x) {
        case 1:           /* 跳转表 → .L3 */
            w = y * z;    /* .L3: movq %rsi,%rax; imulq %rcx,%rax */
            break;
        case 2:           /* 跳转表 → .L5 */
            w = y / z;    /* .L5: idivq → 商在 %rax */
            /* fall through ← 注意这里没有 break！ */
        case 3:           /* 跳转表 → .L9 */
            w += z;       /* .L6: addq %rcx,%rax（case 2、3 共享） */
            break;
        case 5:           /* 跳转表索引 5、6 均指向 .L7 */
        case 6:
            w -= z;       /* .L7: subq */
            break;
        case 0:           /* 跳转表指向 .L8（default） */
        case 4:
        default:
            w = 2;        /* .L8: movl $2 */
            break;
    }
    return w;
}
```



### 跳转表结构

跳转表存放在 `.rodata`（只读数据段）中，每条记录为 8 字节地址：

```asm
.section    .rodata
.align 8
.L4:
    .quad   .L8     # x = 0  → default
    .quad   .L3     # x = 1
    .quad   .L5     # x = 2
    .quad   .L9     # x = 3
    .quad   .L8     # x = 4  → default
    .quad   .L7     # x = 5  → 与 case 6 共享
    .quad   .L7     # x = 6  → 与 case 5 共享
```

### 边界检查与间接跳转

进入 switch 后，首先检查索引是否越界，然后通过跳转表一次定位目标：

```asm
switch_eg:
    movq    %rdx, %rcx          # z → %rcx（避免后续除法污染 %rdx）
    cmpq    $6, %rdi            # 比较 x 与 6
    ja      .L8                 # x > 6 或 x < 0（无符号比较）→ default
    jmp     *.L4(,%rdi,8)       # 间接跳转：goto JTab[x]
```

> **关于 `ja`**：`cmpq $6, %rdi` 计算 `%rdi - 6`，`ja`（Jump Above）在**无符号大于**时跳转。这里虽是有符号数 `x`，但用 `ja` 能一举捕获 `x > 6` 和 `x < 0`（负数的无符号表示 > 6）两种情况。

#### 条件跳转指令对照表

| 指令 | 含义 | 条件码 | C 比较 | 有/无符号 |
|------|------|--------|--------|----------|
| `je` / `jz` | 等于 / 为零 | `ZF = 1` | `a == b` | 通用 |
| `jne` / `jnz` | 不等于 / 非零 | `ZF = 0` | `a != b` | 通用 |
| `jg` / `jnle` | 大于 | `~(SF ^ OF) & ~ZF` | `a > b` | 有符号 |
| `jge` / `jnl` | 大于等于 | `~(SF ^ OF)` | `a >= b` | 有符号 |
| `jl` / `jnge` | 小于 | `SF ^ OF` | `a < b` | 有符号 |
| `jle` / `jng` | 小于等于 | `(SF ^ OF) \| ZF` | `a <= b` | 有符号 |
| **`ja`** / `jnbe` | **高于（无符号大于）** | `~CF & ~ZF` | `a > b` | **无符号** |
| `jae` / `jnb` / `jnc` | 高于等于（无符号大于等于） | `~CF` | `a >= b` | **无符号** |
| **`jb`** / `jnae` / `jc` | **低于（无符号小于）** | `CF = 1` | `a < b` | **无符号** |
| `jbe` / `jna` | 低于等于（无符号小于等于） | `CF \| ZF` | `a <= b` | **无符号** |

> **记法提示**：有符号用 `g`（greater）/ `l`（less），无符号用 `a`（above）/ `b`（below）。测试代码是否为 0 常用 `je`（零跳转）配合 `testq %rax, %rax`。

最后一条指令 `*.L4(,%rdi,8)` 的含义：
- `.L4` 是跳转表的基地址
- `%rdi` 作为索引
- 每条表项占 8 字节，故地址计算为 `.L4 + x * 8`
- `*` 表示从该地址**取出目标地址**再跳转（而非跳到 .L4 本身）

### 穿透（Fall Through）处理

当 `case 2` 没有 `break` 而落入 `case 3` 时，编译器不复制代码，而是通过标签排列和跳转实现流转：

```asm
# 跳转表索引 2 指向 .L5（case 2）
.L5:
    movq    %rsi, %rax          # w = y
    cqto                         # 符号扩展至 %rdx:%rax
    idivq   %rcx                # w /= z
    jmp     .L6                 # 直接跳入合并区，绕过 case 3 的初始化

# 跳转表索引 3 指向 .L9（case 3）
.L9:
    movl    $1, %eax            # w = 1（case 3 不经过除法）
                                 # ← 顺序向下流入 .L6

# 合并收尾区（merge）
.L6:
    addq    %rcx, %rax          # w += z
    ret
```

执行路径：
- **`x == 2`**：`.L5`（除法）→ `jmp .L6`（加法）→ `ret`
- **`x == 3`**：`.L9`（赋 1）→ 顺序流入 `.L6`（加法）→ `ret`

### 多 case 合并与 default

多个 case 执行相同代码时，跳转表直接指向同一标签，避免代码重复：

```asm
# 跳转表索引 5、6 均指向 .L7
.L7:
    movl    $1, %eax            # w = 1
    subq    %rdx, %rax          # w -= z
    ret

# default
.L8:
    movl    $2, %eax            # w = 2
    ret
```

触发 default 有两种情况：
1. 边界检查时 `x > 6` 或 `x < 0`，通过 `ja .L8` 跳转。
2. 索引在 $[0, 6]$ 范围内，但跳转表中对应项指向 `.L8`（如 `x = 0` 或 `x = 4` 没有对应的 case）。



> **核心结论**：case 密集时用跳转表实现 O(1) 多路分支；`ja`（无符号大于）一次捕获越界与负数；fall-through 用标签排列 + 跳转实现。

## 8. 过程调用与栈

过程调用（函数调用）涉及栈操作、参数传递、返回地址管理和寄存器保存约定。本节介绍 x86-64 下这些机制的基本原理。

### ABI（Application Binary Interface）

ABI 是"二进制层面的调用约定"，规定了函数如何传参、如何返回值、哪些寄存器由谁保存等规则。只要所有代码遵循同一 ABI，不同语言编译出的目标文件就可以互相调用。

### 栈的基本操作

栈在 x86-64 中**向下增长**（从高地址向低地址延伸），`%rsp` 始终指向**栈顶**（当前最低的有效地址）。

```asm
pushq Src        # %rsp -= 8; Mem[%rsp] = Src
```

将 `Src` 的值压入栈顶：先减小 `%rsp`（分配 8 字节空间），再将值写入。

```asm
popq Dest        # Dest = Mem[%rsp]; %rsp += 8
```

从栈顶弹出值：先读取 `%rsp` 指向的数据，再增大 `%rsp`（释放 8 字节空间）。

![[Pasted image 20260707161228.png]]

### call 与 ret 指令

```asm
callq label      # pushq return_addr; jmp label
```

`callq` 做了两件事：
1. 将**下一条指令的地址（返回地址）**压入栈顶（模拟 `pushq`）。
2. 将目标函数的地址写入 `%rip`，跳转到函数执行。

```asm
retq             # popq %rip
```

`retq` 从栈顶弹出返回地址，写入 `%rip`，使执行流回到调用者。

![[Pasted image 20260709103624.png|call 指令的效果]]
![[Pasted image 20260709103554.png|ret 指令的效果]]

> **对比**：`%rsp`（栈指针）管理的是内存中的栈，`%rip`（程序计数器）管理的是指令序列。`callq` 将返回地址存在栈上，`retq` 取回——两者通过栈这个媒介协作。

### 栈的 16 字节对齐

System V ABI 要求**在 `call` 指令之前，`%rsp` 必须是 16 的倍数**。

**为什么**：现代库函数（如 `printf`）内部用 SSE 指令（`movaps`）搬运数据，这类指令**硬性要求** 16 字节对齐的内存操作数，不对齐直接崩溃（SIGSEGV）。

**对齐的原理**：CPU 一次内存访问的最小单位是缓存行（通常 64 字节）。数据若跨缓存行，需要两次访问并拼接。让数据对齐到缓存行内，一次访问就能取完，更快也更省事。硬件因此把"必须对齐"写进了指令集规范。

**编译器如何保证**：

```
调用前：%rsp 是 16 的倍数 ✅
call    → 压入 8 字节返回地址 → %rsp ≡ 8 (mod 16)
被调函数开头：编译器自动 subq $8（或更多）补回 16 对齐
库函数执行 movaps 时：%rsp 已对齐 ✅
```

> **Attack Lab 的坑**：注入代码自己控制执行流。如果 `ret` 后 `%rsp` 停在错误的位置，`touch2`/`touch3` 一调 `printf`，内部 `movaps` 立即崩溃。所以 payload 里常需要多压一个 dummy 值，让调用前 `%rsp` 回到 16 对齐。

### 参数传递约定

x86-64 的前 6 个整型参数按顺序通过寄存器传递：

| 参数 | 寄存器 |
|------|--------|
| 第 1 个 | `%rdi` |
| 第 2 个 | `%rsi` |
| 第 3 个 | `%rdx` |
| 第 4 个 | `%rcx` |
| 第 5 个 | `%r8` |
| 第 6 个 | `%r9` |
| 第 7 个及以后 | 存放在调用者的栈帧中 |

返回值通过 `%rax` 传递。

> **注**：传参由**调用者**在 `callq` 之前通过 `movq` 指令完成，`callq` 本身只负责压入返回地址和跳转，不负责参数传递。

### 栈帧结构

每个函数在栈上拥有自己的**栈帧（Stack Frame）**：

- `%rsp` 指向当前栈帧的底部（栈顶）。
- `%rbp` 是可选的帧指针，指向当前栈帧的顶部（即调用者的栈底），用于在栈空间动态变化时稳定地访问局部变量和参数。

```
       高地址
      ┌──────────────────┐
      │  caller 的栈帧     │
      ├──────────────────┤
      │  第 7+ 个参数      │ ← caller 在 callq 之前压入
      │  ...              │
      ├──────────────────┤
      │  返回地址          │ ← callq 时压入
      ├──────────────────┤ ← 进入 callee 时的初始 %rsp
      │  旧 %rbp          │ ← pushq %rbp（帧指针，可选）
      ├──────────────────┤ ← %rbp（若启用帧指针）
      │  被保存的寄存器     │ ← callee-saved 寄存器
      │  局部变量          │ ← 不能全放寄存器或需取地址的变量
      ├──────────────────┤
      │  参数构造区        │ ←（可选）为再下一层调用的第 7+ 参数预留
      ├──────────────────┤ ← %rsp
       低地址
```

![[Pasted image 20260709104959.png|栈的图片]]
> **参数与返回地址的顺序**：调用者先压入第 7+ 个参数（栈指针下移），再执行 `callq` 压入返回地址（栈指针继续下移）。因此参数在返回地址的**上方**（更高地址），callee 通过 `16(%rsp)`、`24(%rsp)` 等正偏移访问它们。


### 寄存器保存约定

寄存器根据谁负责保存分为两类：

| 类别 | 寄存器 | 含义 |
|------|--------|------|
| **调用者保存（Caller-Saved）** | `%rax`, `%rcx`, `%rdx`, `%rsi`, `%rdi`, `%r8`~`%r11` | 如果调用者在这些寄存器中有值需要在调用后保留，它必须在 `callq` **之前**自行保存到栈上 |
| **被调用者保存（Callee-Saved）** | `%rbx`, `%rbp`, `%rsp`, `%r12`~`%r15` | 被调用者（callee）若要使用这些寄存器，必须在函数**开头**保存原值到栈上，并在返回**之前**恢复原值 |

**示例**：`%rbx` 是被调用者保存寄存器


**例 1**：无跨调用值——无需保存寄存器

当函数在调用后不需要保留任何参数时，直接用 `%rax` 接收返回值即可，无需使用 callee-saved 寄存器：

```c
long call_incr() {
    long v1 = 15213;
    long v2 = incr(&v1, 3000);
    return v1 + v2;
}
```

对应汇编：

```asm
call_incr:
    subq    $16, %rsp          # 分配 16 字节栈空间（存 v1 + 对齐）
    movq    $15213, 8(%rsp)    # v1 = 15213，存在栈上
    movl    $3000, %esi        # %esi = 3000（第二个参数）
    leaq    8(%rsp), %rdi      # %rdi = &v1（第一个参数）
    call    incr               # incr(&v1, 3000)
    addq    8(%rsp), %rax      # %rax = v1 + v2
                               #   v1 即栈上的 8(%rsp)（incr 修改了它）
                               #   v2 即 incr 的返回值 %rax
    addq    $16, %rsp          # 回收栈空间
    ret
```

**逐行解读**：

| 汇编 | 说明 |
|------|------|
| `subq $16, %rsp` | 栈上腾出 16 字节：8 字节存 `v1`，8 字节保证对齐 |
| `movq $15213, 8(%rsp)` | `v1 = 15213`，存在 `%rsp+8` 处 |
| `movl $3000, %esi` | 第 2 个参数 = 3000，用 `movl`（4 字节）比 `movq` 省指令空间 |
| `leaq 8(%rsp), %rdi` | 第 1 个参数 = `&v1`（`v1` 的地址） |
| `call incr` | `incr(&v1, 3000)`——`incr` 内部会修改 `v1` 的值 |
| `addq 8(%rsp), %rax` | `return v1 + v2`：`%rax` 存 incr 的返回值（即 `v2`），`8(%rsp)` 是 incr 修改后的 `v1` |
| `addq $16, %rsp` | 回收栈空间 |
| `ret` | 返回 `%rax` |

> 这个例子**没有**使用任何 callee-saved 寄存器，因为 `v1` 存栈上、`v2` 在 `%rax` 中，无需跨调用保留任何寄存器值。

**例 2**：调用另一个函数时同时用 `%rbx`

下面的 C 代码在调用 `incr` 之前先把 `x` 存到 `%rbx`（callee-saved），这样 `incr` 内部即使使用 `%rbx` 也不会破坏 `x` 的值：

```c
long call_incr2(long x) {
    long v1 = 15213;          /* 局部变量，存到栈上 */
    long v2 = incr(&v1, 3000); /* 调用 incr 修改 v1 */
    return x + v2;             /* x 值必须跨调用保持 */
}
```

对应汇编：

```asm
call_incr2:
    pushq   %rbx              # 保存 %rbx（callee-saved）
    subq    $16, %rsp          # 分配 16 字节栈空间（存 v1 + 对齐）
    movq    %rdi, %rbx         # %rbx = x（跨 incr 调用保留 x）
    movq    $15213, 8(%rsp)    # v1 = 15213，存在栈上
    movl    $3000, %esi        # %esi = 3000（第二个参数）
    leaq    8(%rsp), %rdi      # %rdi = &v1（第一个参数）
    call    incr               # incr(&v1, 3000)
    addq    %rbx, %rax         # %rax = x + v2（此时 v2 在 %rax 中）
    addq    $16, %rsp          # 回收栈空间
    popq    %rbx               # 恢复 %rbx 原值
    ret
```

**逐行解读**：

| 汇编 | 说明 |
|------|------|
| `pushq %rbx` | callee-saved：一开始就保存 `%rbx`，后面随便用 |
| `subq $16, %rsp` | 在栈上腾出 16 字节，8 字节存 `v1`，8 字节对齐 |
| `movq %rdi, %rbx` | `%rbx` 现在持有 `x` 的值，**incr 内部不会破坏它** |
| `movq $15213, 8(%rsp)` | 把 `v1 = 15213` 写入分配的栈空间 |
| `movl $3000, %esi` | 设置第 **2** 个参数（`%esi`），编译器用 `movl` 省字节 |
| `leaq 8(%rsp), %rdi` | 设置第 **1** 个参数（`%rdi`）为 `v1` 的地址 |
| `call incr` | 压入返回地址、跳转。`%rbx` 的值在 incr 执行前后不变 |
| `addq %rbx, %rax` | `%rax = x + v2`，`%rbx` 里的 `x` 完好无损 |
| `addq $16, %rsp` | 回收栈空间（对称于 `subq`） |
| `popq %rbx` | 恢复 `%rbx` 原值（对称于 `pushq`） |

> **关键观察**：`x` 存在 `%rbx` 中而不是栈上，是因为 `%rbx` 是 callee-saved，`incr` 内部若要使用 `%rbx` 会自己保存和恢复，对外层透明。这比把 `x` 存到栈上再读回来更高效（寄存器访问远快于内存）。

> **核心结论**：callq 压返回地址再跳转、retq 弹出返回；call 前 %rsp 须 16 字节对齐（库函数用 SSE movaps）；前 6 参数走寄存器、其余压栈；caller/callee-saved 寄存器分工明确。

## 9. 数组与指针

### 一维数组

数组名和指针的关系：

```c
int val[5] = {1, 5, 2, 1, 3};
```

| 表达式 | 类型 | 值 | 地址 |
|--------|------|----|------|
| `val` | `int *` | `x` | 数组首地址 |
| `val + 1` | `int *` | `x + 4` | 下一个元素（`int` 占 4 字节） |
| `&val[2]` | `int *` | `x + 8` | 取下标 2 的地址 |
| `*(val + 1)` | `int` | `5` | 下标 1 的元素值 |
| `val[i]` | `int` | `x + 4i` | 数组下标语法 |

> 数组名不能像指针一样自增（`val++` 非法），因为它不是左值，没有独立的存储空间。

### 二维数组

在内存中按**行优先（Row-Major）**顺序存储。对于一个 $R 	imes C$ 的数组 `A[R][C]`：

```
A[0][0]  A[0][1]  ...  A[0][C-1]  A[1][0]  ...  A[R-1][C-1]
```

元素 `A[i][j]` 的地址：

```
&A[i][j] = A + i * (C * K) + j * K
```

其中 $K$ 是每个元素的大小（`int` 为 4，`long` 为 8）。

**示例**：定长二维数组 `fix_matrix a[16][16]` 的元素访问 `a[i][j]`：

```asm
# a in %rdi, i in %rsi, j in %rdx
salq    $6, %rsi                # 64 * i （$16 \times 4 = 64$）
addq    %rsi, %rdi              # a + 64 * i
movl    (%rdi,%rdx,4), %eax     # M[a + 64*i + 4*j]
ret
```

> 编译器将常数 $C \times K$ 优化为移位操作（如 $16 \times 4 = 64$ 用 `salq $6`）。

### 指针数组

```c
int *univ[UCOUNT] = {mit, cmu, ucb};   // 指针数组，每个元素是 int*
```

访问 `univ[index][digit]` 的汇编：

```asm
salq $2, %rsi                  # 4 * digit
addq univ(, %rdi, 8), %rsi     # Mem[univ + 8*index] + 4*digit
movl (%rsi), %eax
ret
```

> 先取 `univ[index]`（指针数组中第 `index` 个指针），再在该指针基础上偏移 `digit` 个 `int`。

### 变长数组（VLA, Variable-Length Array）

当数组的列数由变量决定时，编译器无法在编译期确定偏移量，必须使用乘法指令：

```c
int var_ele(size_t n, int a[n][n], size_t i, size_t j) {
    return a[i][j];
}
```

```asm
# n in %rdi, a in %rsi, i in %rdx, j in %rcx
imulq   %rdx, %rdi              # %rdi = n * i
leaq    (%rsi,%rdi,4), %rax     # %rax = a + 4 * n * i
movl    (%rax,%rcx,4), %eax     # %eax = M[a + 4*n*i + 4*j]
ret
```

> 定长数组用移位（更快），变长数组用乘法（`imulq`）。这是编译器在"已知常数"和"未知变量"之间的优化取舍。

> **核心结论**：数组按行优先存储，A[i][j] 地址 = A + i·C·K + j·K；定长数组偏移用移位优化，变长数组只能用乘法。

## 10. 结构体、联合体与对齐

### 结构体内存布局

结构体成员在内存中按声明顺序排列，但编译器会在成员之间插入**填充（Padding）**以满足对齐要求。

```c
struct rec {
    int a[3];       // 偏移 0，占 12 字节
    int i;          // 偏移 16（前有 4 字节填充），占 4 字节
    struct rec *next; // 偏移 24（前有 4 字节填充），占 8 字节
};
```

总大小：32 字节（对齐要求由最大成员 `next` 的 8 字节决定）。

### 对齐原则

1. **基本数据类型的地址必须是其大小的倍数**：`char` 可在任意地址，`int` 的地址需为 4 的倍数，`double` 需为 8 的倍数。
2. **结构体的总大小必须是其最大成员的对齐要求的倍数**——确保结构体数组的每个元素都能正确对齐。

**示例**：`struct S1 { char c; int i[2]; double v; }` 的对齐：

| 偏移 | 大小 | 内容 | 说明 |
|------|------|------|------|
| `p+0` | 1 | `c` | `char`，无需对齐 |
| `p+1`~`p+3` | 3 | **填充** | 让 `i` 对齐到 4 的倍数 |
| `p+4`~`p+11` | 8 | `i[0]`, `i[1]` | 两个 `int` |
| `p+12`~`p+15` | 4 | **填充** | 让 `v` 对齐到 8 的倍数 |
| `p+16`~`p+23` | 8 | `v` | `double` |

总大小：24 字节（17 字节原始数据 + 7 字节填充）。

### 访问结构体成员

通过**基地址 + 偏移量**访问。以下是对链表赋值操作的汇编：

```c
void set_val(struct rec *r, int val) {
    while (r) {
        int i = r->i;           // i = M[r + 16]
        r->a[i] = val;          // M[r + 4*i] = val
        r = r->next;            // r = M[r + 24]
    }
}
```

```asm
.L11:
    movslq  16(%rdi), %rax      # i = M[r+16]（符号扩展）
    movl    %esi, (%rdi,%rax,4) # M[r+4*i] = val
    movq    24(%rdi), %rdi      # r = M[r+24]（next 指针）
    testq   %rdi, %rdi          # r 是否为 NULL？
    jne     .L11                # 不为 NULL 则继续循环
```

> `movslq` 将 `int i` 符号扩展为 64 位——因为 `%rax` 作为索引寄存器参与地址计算需要 64 位。

### 结构体数组的对齐

```c
struct S2 {
    double v;       // 8 字节 → 对齐要求 8
    int i[2];       // 8 字节
    char c;         // 1 字节
} a[10];
```

最大成员 $K = 8$（`double`），因此总大小必须是 8 的倍数。实际布局为 24 字节（`v` 占 8，`i[2]` 占 8，`c` 占 1，末尾 7 字节填充），确保 `a[1].v` 仍然在 8 字节对齐的地址。

> **编写结构体的技巧**：将大对齐要求的成员（`double`、指针）放在前面，小对齐要求的成员（`char`）放在后面，可以减少填充字节。

### 联合体（Union）

#### 内存分配

Union 的所有成员**共享同一块内存**，大小按最大的成员分配：

```c
union U1 {
    char c;        // 1 字节
    int i[2];      // 8 字节
    double v;      // 8 字节
} *up;

struct S1 {
    char c;        // 1 字节
    int i[2];      // 8 字节
    double v;      // 8 字节
} *sp;
```

| 类型 | 布局 | 总大小 |
|------|------|--------|
| `struct S1` | `c` + 3B padding + `i[2]` + 4B padding + `v` | **24 字节** |
| `union U1` | `c`、`i[2]`、`v` 重叠在同一起始地址 | **8 字节** |

**任何时候只能使用 union 中的一个字段**，写入一个字段再读另一个字段会得到未定义结果。

#### 实用场景：访问浮点数的位模式

```c
typedef union {
    float f;
    unsigned u;
} bit_float_t;

float bit2float(unsigned u) {
    bit_float_t arg;
    arg.u = u;         // 写入无符号整数
    return arg.f;      // 读出相同的位模式作为浮点数
}

unsigned float2bit(float f) {
    bit_float_t arg;
    arg.f = f;         // 写入浮点数
    return arg.u;      // 读出相同的位模式作为无符号整数
}
```

> 用 union 做类型双关（type punning）比用指针强制转换更符合 C 标准（但 GCC 对两种方式都支持）。

#### 字节序可视化

Union 可以直观地展示多字节数据在内存中的排列：让 `unsigned char c[8]`、`unsigned short s[4]`、`unsigned int i[2]`、`unsigned long l[1]` 字段重叠，按不同粒度"看"同一块内存，就能观察小端/大端下各字段呈现的值。大端/小端的完整讲解见**第 2 章「字长与字节序」**。

> 小端序：**最低有效字节（LSB）存在最低地址**。x86 全系列和 ARM（默认模式）都是小端序。

> **核心结论**：结构体成员按声明顺序 + 填充满足对齐，总大小为最大成员对齐要求的倍数；union 所有成员共享一块内存、大小为最大成员，常用于类型双关；大对齐成员放前面可减少填充。

## 11. x86-64 Linux 内存布局

一个进程的虚拟地址空间从低到高分为几个区域：

```
十六进制地址范围          区域        用途
─────────────────────────────────────────────────
00007FFFFFFFFFFF        Stack       运行时栈（8MB 限制，局部变量）
                        ↑           栈向低地址增长
                        Shared Libs 共享库（libc 等）
                        ↓           堆向高地址增长
                        Heap        动态分配（malloc/calloc 返回）
                        Data        静态分配数据（全局变量、静态变量、字符串常量）
400000                  Text/代码    可执行机器指令（只读）
0000 ~ 400000           保留区      不可访问（NULL 指针检测）
```

> 从虚拟内存的视角（页表、mmap 区域等）看这套布局，见**第 9 章「虚拟内存」**。

### 地址分布示例

```c
char big_array[1L<<24];  /* 16 MB 全局 */
char huge_array[1L<<31]; /*  2 GB 全局 */
int global = 0;
int useless() { return 0; }

int main() {
    void *p1, *p2, *p3, *p4;
    int local = 0;
    p1 = malloc(1L << 28); /* 256 MB */
    p2 = malloc(1L << 8);  /* 256  B */
    p3 = malloc(1L << 32); /*   4 GB */
    p4 = malloc(1L << 8);  /* 256  B */
}
```

实际地址分布：

| 符号 | 地址 | 区域 |
|------|------|------|
| `local` | `0x00007ffe4d3be87c` | **Stack**（高地址） |
| `p1` | `0x00007f7262a1e010` | Heap（大块分配靠近 libs） |
| `p3` | `0x00007f7162a1d010` | Heap |
| `p4` | `0x000000008359d120` | **Heap**（小块分配在低地址） |
| `p2` | `0x000000008359d010` | Heap |
| `big_array` | `0x0000000080601060` | Data（大全局数组） |
| `huge_array` | `0x0000000000601060` | Data |
| `main()` | `0x000000000040060c` | **Text**（低地址） |
| `useless()` | `0x0000000000400590` | Text |

> **模式**：Text 在最低地址（0x400000 附近），Data 紧接着，Heap 在上面，Stack 在最高地址（0x7FFF 开头）。大 malloc（>128KB）用 `mmap` 分配，位于 Heap 和 Stack 之间的共享库区域。

> **核心结论**：进程虚拟地址空间从低到高为 Text→Data→Heap(↑)→共享库→Stack(↓)；大 malloc（>128KB）用 mmap 分配。

## 12. 缓冲区溢出（Buffer Overflow）

### 漏洞根源

C 标准库中的部分函数不检查输入长度：

| 危险函数 | 问题 |
|---------|------|
| `gets()` | 无限制读取 stdin 到缓冲区，直到换行 |
| `strcpy()` / `strcat()` | 复制/拼接任意长度的字符串 |
| `scanf("%s")` | 读取不定长字符串 |

```c
/* 最经典的漏洞函数——gets() */
char *gets(char *dest) {
    int c = getchar();
    char *p = dest;
    while (c != EOF && c != '\n') {
        *p++ = c;
        c = getchar();
    }
    *p = '\0';
    return dest;   /* 没有长度限制！*/
}
```

### 溢出过程

```c
void echo() {
    char buf[4];      /* 只有 4 字节！*/
    gets(buf);         /* 读入任意长字符串 */
    puts(buf);
}
```

栈布局（`subq $24, %rsp` 分配了 24 字节）：

```
      高地址
      ┌──────────────┐
      │  call_echo 栈帧 │
      ├──────────────┤
      │  返回地址     │ ← call_echo 的返回地址（8 字节）
      ├──────────────┤
      │  (20 bytes)  │ ← 未使用的栈空间
      │  buf[0~3]    │ ← %rsp（gets 写入起点）
      └──────────────┘
      低地址
```

不同长度的输入导致不同后果：

| 输入长度 | 后果 |
|---------|------|
| ≤ 4 字节 | 正常，不溢出 |
| 5~24 字节 | 覆盖了未使用的栈空间，但返回地址完好，**看似正常** |
| 25~32 字节 | **覆盖了返回地址** → `ret` 跳转到非法地址 → **Segmentation Fault** |
| 25~32 字节（精心构造） | 把返回地址改为攻击代码的地址 → **Code Injection** |

### 现实危害

- **1988 年 Morris 蠕虫**：利用 `fingerd` 的 `gets()` 漏洞，入侵约 6000 台计算机（当时互联网的 10%），直接促成 CERT 的成立
- **1999 年 IM 战争**：AOL 利用 AIM 客户端的缓冲区溢出漏洞检测和拦截 MSN Messenger 客户端，微软伪造举报邮件曝光此事
- **至今**：缓冲区溢出仍是 CVE 漏洞的头号技术成因

> **核心结论**：gets/strcpy/scanf 等不检查长度，可覆盖返回地址导致段错误或代码注入；缓冲区溢出是 CVE 头号成因（Morris 蠕虫等）。

## 13. 缓冲区溢出防御

### 13.1 避免在代码中写漏洞

```c
/* ❌ 危险 */
gets(buf);
strcpy(buf, input);
scanf("%s", buf);

/* ✅ 安全 */
fgets(buf, sizeof(buf), stdin);   /* 限制读取长度 */
strncpy(buf, input, sizeof(buf)); /* 限制复制长度 */
```

### 13.2 系统级防护

**地址空间布局随机化（ASLR）**：
- 程序启动时在栈上随机分配一段空间，使每次运行的栈地址不同
- 攻击者即使有漏洞，也难以预测注入代码的地址

![[Pasted image 20260727141709.png]]

**栈不可执行（NX bit）**：
- x86-64 为内存页引入了"执行"权限位
- 栈被标记为不可执行，注入的 shellcode 即使被执行也会崩溃

![[Pasted image 20260727141726.png]]

### 13.3 栈金丝雀（Stack Canary）

GCC 的 `-fstack-protector` 现在默认开启：

```bash
gcc -fstack-protector -o prog prog.c  # 开启金丝雀
```

原理：

```asm
echo:
    subq    $24, %rsp
    movq    %fs:40, %rax        # 从线程局部存储中取出金丝雀值
    movq    %rax, 8(%rsp)       # 放在 buf 和返回地址之间
    xorl    %eax, %eax
    # ... 调用 gets(buf) ...
    movq    8(%rsp), %rax       # 取出栈上的金丝雀
    xorq    %fs:40, %rax        # 和金丝雀原值比较
    je      .L6                 # 相同 → 正常返回
    call    __stack_chk_fail    # 不同 → 检测到溢出，报错退出
.L6:
    addq    $24, %rsp
    ret
```

> 攻击者必须先覆盖金丝雀才能碰到返回地址，但金丝雀的值是随机的且不可预测。输入 `01234567` 时金丝雀被破坏 → `*** stack smashing detected ***`。

### 13.4 面向返回编程（ROP）

即使有了 NX（栈不可执行）和 ASLR，攻击者还有更高级的手段：

**ROP（Return-Oriented Programming）**：不注入新代码，而是利用**程序中已有的代码片段（gadget）**，每个 gadget 以 `ret`（0xc3）结尾，通过栈上布置的地址链将它们串联起来。攻击者用溢出覆盖返回地址，使其指向第一个 gadget，gadget 执行完毕后 `ret` 自动弹出下一个地址，依次执行。

**Gadget 的来源**：可以来自正常函数的**中间或尾部片段**，也可以是某条指令中间字节的**意外解码**。

**Gadget 1**——利用函数的尾部：

```c
long ab_plus_c(long a, long b, long c) {
    return a*b + c;
}
```

编译后（攻击者不调用 `ab_plus_c`，而是把返回地址覆写为 `0x4004d4`，从中间开始执行）：

```asm
<ab_plus_c>:
  4004d0:  48 89 d0           movq   %rdx, %rax     # rax = c
  4004d3:  48 0f af fe        imulq  %rsi, %rdi     # rdi = a * b
  4004d4:  48 01 f8           addq   %rdi, %rax     # rax = a*b + c ← Gadget
  4004d7:  c3                 retq
```

**Gadget 2**——从指令中间意外解码：

```asm
<setval>:
  4004d9:  c7 07 d4 48 89 c7  movl   $0xc78948d4,(%rdi)
  4004df:  c3                 retq
```

攻击者跳过前 3 个字节，从 `0x4004dc` 开始解码：

```
地址         机器码         汇编
4004dc:     48 89 c7        movq   %rax, %rdi    ← Gadget
4004df:     c3              retq
```

**金丝雀如何阻止 ROP**：攻击者在 `gets()` 时一次性写入超长输入，从缓冲区一路覆盖到返回地址及其后的 gadget 链。而金丝雀**恰好夹在缓冲区和返回地址之间**——要改返回地址必须先经过金丝雀，而金丝雀的值是随机的，覆盖它就等于触发 `__stack_chk_fail`，`ret` 根本不会执行，gadget 链无法启动。

| 有无金丝雀 | `ret` 是否执行 | gadget 链能否启动 |
|-----------|--------------|-----------------|
| **有** | ❌ 不会——`__stack_chk_fail` 直接终止程序 | ❌ |
| **无** | ✅ 弹出 gadget 地址，跳转执行 | ✅ |

> **核心结论**：防御三件套：ASLR 随机化栈地址、NX 使栈不可执行、栈金丝雀在返回地址前放随机值；ROP 用程序中已有 gadget 绕 NX，但金丝雀夹在缓冲区间，覆盖即触发检测、阻止链启动。

## 14. 习题与思考

1. 为什么 `x * 12` 编译器选择用 `leaq` 算 `3x` 再左移，而不是直接用 `imulq` 指令？

   > `imulq` 是乘法指令，延迟较高（约 3 个周期），而 `leaq`（1 个周期）+ `salq`（1 个周期）的组合更快。编译器倾向于将常数乘法分解为移位和加法。

2. 以下指令等价于什么 C 代码？
   ```assembly
   leaq (%rdi, %rsi, 4), %rax
   ```
   > `%rax = %rdi + %rsi * 4`，即 C 中的 `x + y * 4`（假设 `%rdi` 对应 `x`，`%rsi` 对应 `y`）。

> **核心结论**：常数乘法用 leaq + 移位组合比 imulq 快；leaq (%rdi, %rsi, 4), %rax 等价于 C 的 x + y*4。

## 总结

| 概念 | 要点 |
|------|------|
| **ISA** | 指令集体系结构，x86-64 是主流 |
| **从 C 到汇编** | `gcc -Og -S` 生成汇编，`objdump -d` 反汇编 |
| **寄存器** | 16 个 64 位通用寄存器，`%rsp` 为栈指针 |
| **movq** | 数据传送，不能 mem→mem |
| **寻址模式** | `(R)` / `D(R)` / `D(Rb, Ri, S)` |
| **leaq** | 计算地址但不访存，常用于算术优化 |
| **条件码** | CF/SF/ZF/OF 记录运算属性；cmpq/testq 设置；setx 读取 |
| **switch** | 跳转表实现 $O(1)$ 多路分支 |
| **过程调用** | `callq` 压返回地址跳转，`retq` 弹出返回 |
| **参数传递** | 前 6 个在寄存器，其余在栈上 |
| **寄存器保存** | caller-saved（按需存）vs callee-saved（用前存） |
| **数组** | 行优先存储，`A[i][j]` 地址 = `A + i*C*K + j*K` |
| **结构体对齐** | 成员地址须为其大小的倍数；结构体总大小为最大成员的倍数 |
| **Union** | 所有成员共享一块内存，大小为最大成员；常用于类型双关 |
| **内存布局** | Text（低地址）→ Data → Heap（↑）→ Libs → Stack（↓，高地址） |
| **缓冲区溢出** | `gets()`/`strcpy()` 无长度检查，可覆盖返回地址 |
| **防御** | ASLR（随机化栈地址）、NX（栈不可执行）、栈金丝雀（%fs:40）、ROP 防御 |
