## 1. 异常与系统调用机制

### ECF 存在于系统各层

| 机制 | 实现 |
|---|---|
| 异常 (Exceptions) | 硬件 + 内核软件 |
| 进程上下文切换 | 硬件定时器 + 内核软件 |
| 信号 (Signals) | 内核软件 + 应用软件 |
| 非局部跳转 (Nonlocal jumps) | C 运行时库 |

### 异常的定义

- **异常 (exception)**：响应某事件（处理器状态变化）而**把控制转移到 OS 内核**。
- 事件示例：除 0、算术溢出、页故障、I/O 请求完成、键入 Ctrl-C。
- 异常处理程序完成后有三种选择：**返回到 I_current**（重新执行当前指令）、**返回到 I_next**（执行下一条）、**中止 (abort)**。

### 异常表（Exception Table）

- 每类事件有唯一的**异常号 k**；k 是**异常表**（又称**中断向量 interrupt vector**）的索引；每次异常 k 发生时调用处理程序 k。

### 硬件 ECF 分类

```
ECF
├─ 异步 (Asynchronous) ──── 中断 (Interrupts)
└─ 同步 (Synchronous) ──── 陷阱 (Traps) / 故障 (Faults) / 中止 (Aborts)
```

- **异步异常（中断 Interrupts）**：由处理器**外部**事件引起（处理器中断引脚置位）；处理程序返回"**下一条**"指令。例子：**定时器中断**（每隔几 ms，内核夺回控制权）、**I/O 中断**（键盘 Ctrl-C、网络包到达、磁盘数据到达）。
- **同步异常**：由**执行指令**导致：
  - **陷阱 (Trap)**：**故意**的，程序主动"绊陷阱"（**系统调用**、gdb 断点）；返回"下一条"指令。
  - **故障 (Fault)**：**非故意**但**可能可恢复**（页故障可恢复、保护故障不可恢复、浮点异常）；**重新执行出错指令**或中止。
  - **中止 (Abort)**：**非故意且不可恢复**（非法指令、奇偶错误、机器检查）；中止当前程序。

### 系统调用机制（System Call）

- **系统调用 (system call)** 是实现为**陷阱**的特殊函数调用：程序用特殊指令 `syscall`（x86）主动把控制交给内核，由内核以**不同特权级**执行。
- 每个 x86-64 系统调用有唯一 ID 号：

| 号 | 名称 | 描述 |
|---|---|---|
| 0 | read | 读文件 |
| 1 | write | 写文件 |
| 2 | open | 打开文件 |
| 3 | close | 关闭文件 |
| 4 | stat | 获取文件信息 |
| 57 | fork | 创建进程 |
| 59 | execve | 执行程序 |
| 60 | _exit | 终止进程 |
| 62 | kill | 向进程发信号 |

**打开文件示例**（`open` 是 syscall #2）：

```asm
mov $0x2,%eax      # open 是 2 号系统调用
syscall            # 返回值在 %rax
```

- **`%rax` 放系统调用号**；其余参数在 `%rdi, %rsi, %rdx, %r10, %r8, %r9`；**返回值在 `%rax`**，负值表示错误（对应负的 errno）。
- 几乎像普通函数调用，但有一个重要例外：**由内核执行、特权级不同**；另外"函数地址"在 `%rax`、用 `errno` 等。

**故障示例**：
- **页故障（可恢复）**：访问的页在磁盘上 → 内核把页从磁盘拷入内存，**重新执行 `movl`**。
- **无效内存引用（不可恢复）**：`a[5000]` 越界 → 内核检测到无效地址，**向进程发 `SIGSEGV`**，进程以 "segmentation fault" 退出。

> **核心结论**：异常是响应事件的硬件/内核控制转移，分异步中断（返回下一条）与同步陷阱/故障/中止；系统调用是陷阱，用 `%rax` 传号、返回值在 `%rax`；页故障可恢复（重执行），无效引用发 SIGSEGV。

## 2. 进程与多任务

### 什么是进程（Process）

- **定义**：**进程是一个正在运行程序的实例 (instance of a running program)**——计算机科学中最深刻的思想之一；不同于"程序"或"处理器"。
- 进程给每个程序两个关键抽象：
  - **私有地址空间 (Private address space)**：每个程序仿佛独占主存——由**虚拟内存**机制提供；
  - **逻辑控制流 (Logical control flow)**：每个程序仿佛独占 CPU——由**上下文切换**机制提供。

### 控制流（Control Flow）

- 处理器只做一件事：从启动到关闭，每个 CPU 核心**逐条读取并执行机器指令序列**——这就是 CPU 的**物理控制流**。
- （现代 CPU 可能乱序并行执行多条指令，但对程序员不可见。）

### 多处理（Multiprocessing）

- 计算机**同时运行许多进程**：一个或多个用户的应用（浏览器、邮件客户端、编辑器…）+ 后台任务（监控网络与 I/O 设备）。
- 这就是**分时 (time sharing)**：物理内存中各程序占不同区域，但每个进程的代码只看到**自己方便选择的虚拟地址**。

### 上下文切换（Context Switching）

- 进程由**内核 (kernel)** 管理——内核是一块常驻内存的 OS 代码；**重要：内核不是独立进程，而是作为某个现有进程的一部分运行**。
- 控制流经**上下文切换 (context switch)** 从一个进程传到另一个。

**单处理器上**：
1. 非执行进程的**寄存器值保存在内存**中；
2. 切换时**保存当前进程寄存器**到内存；
3. **调度器 (scheduler)** 选出下一个执行的进程；
4. **加载新进程的寄存器**并**切换地址空间**（内核用新页表，PTBR 值随上下文保存）。

**多核处理器**：单芯片多个 CPU，**共享主存（和部分缓存）**，每个核可执行一个独立进程；核到进程的调度由内核完成。

### 并发 vs 顺序

- 两个进程**并发 (concurrent)**：它们的执行在时间上**有重叠**；否则**顺序 (sequential)**。
- 用户看来并发进程"并行"运行——但它们**可能互相干扰**。
- 单处理器现实：同一时刻只有一个进程运行，执行是**交错 (interleaved)** 而非真正并行——仍可能互相干扰。

### 内核如何夺回控制

- CPU 依序执行指令，我们的程序不会写"运行内核代码"——但可以用**特殊指令 `syscall`**（x86）调用内核。
- 其他夺回控制的方式：**页故障**等异常（详见 §1 异常与系统调用机制）。

> **核心结论**：进程是"运行中程序的容器"，提供私有地址空间（虚拟内存）与逻辑控制流（上下文切换）；单核靠寄存器保存/恢复 + 换页表实现交错多任务，多核才能真并行；`syscall` 指令是程序主动把控制交给内核的门。

## 3. 系统调用应用与错误处理

### 为什么需要系统调用

- 程序只要想在**自身进程之外**产生效果，就必须请内核帮忙。例子：读/写文件、获取当前时间、分配 RAM（`sbrk`）、创建新进程。
- 从 `fopen` 到 `open` 再到 `syscall`：C 库的 `open` 是汇编写的，只做两件事——把常量放入 `%eax`、执行 `syscall`，再比较返回值。
- 内核有**特殊权限**（改页表、直接与 I/O 设备通信），所以不能随便跳进它的代码，必须用特殊指令。

### 系统调用数量

- 当前 Unix 上有**近 400 个系统调用**（Linux 内核 6.0 列表）；许多只在特定场景有用。
- 对比：C 库有约 **2 万个**文档化函数。

### 系统调用错误处理

- **几乎所有系统级操作都可能失败**（唯一例外是返回 void 的那几个）。
- 出错时大多返回 **−1** 并设置全局变量 **`errno`** 表示原因。
- 必须**显式检查失败**：

```c
pid_t pid = fork();
if (pid == -1) {
    fprintf(stderr, "fork error: %s\n", strerror(errno));
    exit(1);
}
```

- 可用**错误报告函数**封装：`unix_error`（`fprintf(stderr,"%s: %s\n", msg, strerror(errno)); exit(1)`）。
  - 注意：csapp.c 的错误函数若用 `exit(0)` 需改成 `exit(1)`。
- **Stevens 风格错误处理包装 (wrapper)**：首字母大写的系统调用（如 `Fork()`）封装了错误处理，"只有成功才返回"。**便于阅读讲义，但真实程序几乎不该这样用**——退出并不总是对的。

> **核心结论**：程序要影响自身之外必须经 `syscall` 进内核；几乎所有系统调用都可能失败（返回 −1 + `errno`），必须显式检查；`unix_error` 与 Stevens 包装只是讲义的简化写法。

## 4. 进程控制（fork/exit/wait/execve）

### 获取进程 ID

- `pid_t getpid(void)`：当前进程 PID。
- `pid_t getppid(void)`：父进程 PID。
- PID 在进程生命周期内不变，但可能被**复用**；每个进程有父进程（进程终止时通知它）。父进程先亡则子进程改由 **进程 1（init）** 收养。

### 进程状态

| 状态 | 含义 |
|---|---|
| **Running（运行）** | 正在执行指令，或只要有核就能执行 |
| **Blocked / Sleeping（阻塞/睡眠）** | 在某个外部事件（通常是 I/O）发生前无法继续执行 |
| **Stopped（停止）** | 被用户动作阻止执行（如 control-Z） |
| **Terminated / Zombie（终止/僵尸）** | 进程结束，但父进程**尚未收到通知** |

### 终止进程

三种原因：收到默认动作为终止的信号（见 §6 信号）；从 `main` 返回；调用 `exit`。

```c
void exit(int status)
```

- 以状态 `status` 终止；**约定正常返回 0，出错非 0**。
- `exit` 被调用一次但**永不返回**。

### 创建进程：fork

```c
int fork(void)
```

- **父进程**调用 `fork` 创建新运行的**子进程**：
  - 向**子进程**返回 **0**，向**父进程**返回**子进程的 PID**；
  - 子进程是父进程的**几乎相同拷贝**：获得父进程虚拟地址空间的**相同但独立**的拷贝、父进程**打开文件描述符**的相同拷贝；但 **PID 不同**。
- `fork` 有趣（且常令人困惑）之处：**调用一次，返回两次**。
- 概念视图：**完整复制执行状态**，指定一个为父、一个为子，分别恢复执行（优化：**写时复制 copy-on-write** 避免复制 RAM）。

**fork 示例**（`int x = 1`）：子进程 `printf("child : x=%d", ++x)` → 2；父进程 `--x` → 0。**父/子执行顺序不可预测**（多次运行两种顺序都可能）。

### 用进程图建模 fork

- **进程图 (process graph)**：捕获并发程序中语句偏序的工具。
  - 每个**顶点**是一条语句的执行；`a → b` 表示 a 先于 b 发生；边可标变量当前值；printf 顶点标输出。
- **任何拓扑排序**都对应一个**可行全序**（所有边从左到右）。
- 例：`fork2` 连续两次 fork，可行输出 `L0 L1 Bye Bye L1 Bye Bye`（7 行）；`L0 Bye L1 Bye L1 Bye Bye` **不可行**（不是拓扑排序）。
- 嵌套 fork：`fork4`（子进程才继续 fork）与 `fork5`（父进程才继续 fork）各自有可行/不可行的输出判断。

### 收割子进程（Reaping）

- **想法**：进程终止后仍占用系统资源（内存、OS 表、退出状态本身）——称为**僵尸 (zombie)**，"活死人"。
- **收割 (reaping)**：父进程对已终止子进程执行（用 `wait`/`waitpid`）；父进程获得退出状态信息；内核随后删除僵尸子进程。
- **父进程不收割会怎样？** 父进程若先终止，孤儿子进程由 **init（pid 1）** 收割（除非终止的正是 init——那就得重启）。所以**只需在长运行进程（如 shell、服务器）里显式收割**。
- 僵尸示例：`ps` 显示 `<defunct>`；杀掉父进程后 init 收割。
- 非终止子进程示例：父进程终止后**子进程仍活动**，必须显式 kill，否则永远运行。

### wait：与子进程同步

```c
pid_t wait(int *status)
pid_t waitpid(pid_t pid, int *status, int options)
```

- **`wait`**：挂起当前进程直到**某个**子进程终止；返回该子进程 PID，退出状态存入 `status`。
- **`waitpid`**：更灵活——可等待**特定子进程或一组**；可要求"没有可收割的子进程就立即返回"。
- `fork9` 示例：可行输出 `HC HP CT Bye` 或 `HP HC CT Bye`；`HP CT Bye HC` **不可行**（CT 必须在子终止之后）。
- **状态码**：`wait` 返回值是终止子进程的 PID；`status` 需用 `sys/wait.h` 宏解码——`WIFEXITED`、`WEXITSTATUS`、`WIFSIGNALED`、`WTERMSIG`、`WIFSTOPPED`、`WSTOPSIG`、`WIFCONTINUED`。
- 多个子进程完成时，`wait` **按任意顺序**收取；`waitpid(pid[i], ...)` 可按指定顺序。

### execve：加载并运行程序

```c
int execve(char *filename, char *argv[], char *envp[])
```

- **在当前进程中**加载并运行可执行文件 `filename`（目标文件或 `#!interpreter` 开头的脚本），带参数列表 `argv`（约定 `argv[0]==filename`）与环境变量列表 `envp`（`"name=value"` 字符串，如 `USER=droh`；`getenv`/`putenv`/`printenv`）。
- **覆盖代码、数据与栈**；**保留 PID、打开的文件与信号上下文**。
- **调用一次，永不返回**——除非出错。
- 与内存布局：释放旧页表、为新区建新的，程序与已初始化数据由目标文件支撑、`.bss` 与栈由匿名文件支撑（细节详见第 9 章-虚拟内存）。

> **核心结论**：进程控制四件套——`fork`（一次调用两次返回，复制地址空间+打开文件）、`exit`（一次调用不返回）、`wait`/`waitpid`（收割+同步，僵尸需回收）、`execve`（当前进程换程序，保留 PID/打开文件）。用**进程图/拓扑排序**判断 fork 程序的可行输出。

## 5. Shell 程序

### 什么是 Shell

- **Shell 是一个应用程序**，代用户运行程序。`sh`（Bourne，1977）、`csh`/`tcsh`、`bash`（默认 Linux shell）。
- 桌面界面（Windows/Mac）本质也是 shell——其主要职责是替你启动程序。

### 简单 Shell 示例

```
linux> ./shellex
> /bin/ls -l csapp.c
-rw-r--r-- 1 bryant users 23053 Jun 15 2015 csapp.c
> /bin/sleep 10 &
32031 /bin/sleep 10 &
> /bin/ps
...
> quit
```

- 必须给出**完整路径名**；`&` 结尾在**后台**运行。

### 基本循环

- 读命令行 → 执行请求的操作（**内建命令**，本示例只实现 `quit`；或**从文件加载并执行程序**）。

### eval 函数（核心逻辑）

```c
void eval(char *cmdline) {
    ...
    bg = parseline(buf, argv);              /* 解析命令行，返回是否以 & 结尾 */
    if (argv[0] == NULL) return;            /* 忽略空行 */
    if (!builtin_command(argv)) {           /* 不是内建命令 */
        if ((pid = Fork()) == 0) {          /* 子进程运行用户任务 */
            if (execve(argv[0], argv, environ) < 0) {
                printf("%s: Command not found.\n", argv[0]);
                exit(0);                    /* 正确写法 exit(127)：execve 失败 */
            }
        }
        if (!bg) {                          /* 前台：等待子进程结束 */
            int status;
            if (waitpid(pid, &status, 0) < 0)
                unix_error("waitfg: waitpid error");
        }
        else                                /* 后台：打印 pid 继续 */
            printf("%d %s", pid, cmdline);
    }
    return;
}
```

- `parseline` 把 `buf` 解析进 `argv` 并返回是否以 `&` 结尾；`execve` 只在出错时返回（`exit(127)` 表示 "execve failed"）。

### 简单 Shell 的问题

- Shell **设计为无限运行**，不应累积无用资源（内存、子进程、文件描述符）。
- 示例 shell 正确等待并收割**前台**任务；但**后台任务**终止后变成僵尸，**永远不会被收割**（因为 shell 通常不终止）——最终可能耗尽整台计算机的内存，更可能**耗尽 PID**。
- 解决之道是**信号**：Shell 用 `SIGCHLD` 处理程序在后台任务终止时收割（见 §6 信号与 §7 正确的信号处理）。

> **核心结论**：Shell = read/evaluate 循环；前台任务 fork+execve 后 `waitpid` 等待、后台任务打印 PID 继续；它必须用信号（`SIGCHLD`）收割后台子进程，否则后台任务积累成僵尸耗尽资源。

## 6. 信号

### 信号的概念

- **信号 (signal)**：通知进程系统发生某类事件的小消息，类似异常与中断；由内核（有时应另一进程请求）发给进程；用**小整数 ID（1–30）** 标识；信号携带的唯一信息就是 ID 与"它到了"。

| ID | 名称 | 默认动作 | 对应事件 |
|---|---|---|---|
| 2 | SIGINT | 终止 | 用户键入 ctrl-c |
| 9 | SIGKILL | 终止 | 杀死程序（**不能覆盖或忽略**） |
| 11 | SIGSEGV | 终止 | 段违规 |
| 14 | SIGALRM | 终止 | 定时器信号 |
| 17 | SIGCHLD | **忽略** | 子进程停止或终止 |

### 发送信号（Sending）

- 内核通过**更新目标进程上下文中的状态**发送信号。原因两种：
  - 内核检测到系统事件（如除 0 → SIGFPE、子进程终止 → SIGCHLD）；
  - 另一进程调用 **`kill` 系统调用**显式请求。

### 接收信号（Receiving）

- 目标进程收到信号 = 被内核**强制**以某种方式反应：**忽略**、**终止**（可选 core dump）、**捕获**（执行用户级**信号处理程序**，类似响应异步中断的硬件异常处理程序）。

### 待决与阻塞（Pending and Blocked）

- **待决 (pending)**：已发送但未收到。**每种信号最多一个待决**——**信号不排队**：已有类型 k 的待决信号时，后续同型信号被**丢弃**。
- **阻塞 (blocked)**：进程可阻塞某些信号——可发送但**解除阻塞前不会收到**。`SIGKILL`、`SIGSTOP` 不能被阻塞。
- 一个待决信号**至多被接收一次**。
- 内核在每个进程上下文中维护 **pending 与 blocked 位向量**：
  - 发送类型 k 信号 → 置 pending 第 k 位；接收 → 清除；
  - blocked（又称**信号掩码 signal mask**）可用 `sigprocmask` 设置/清除。

### 进程组（Process Groups）

- 每个进程属于**恰好一个进程组**；`getpgrp()` 返回当前进程组、`setpgid()` 改变进程组。
- 键盘 **ctrl-c（ctrl-z）** 使内核向**前台进程组**每个任务发 **SIGINT**（终止）或 **SIGTSTP**（停止）。

### 发送信号的途径

- **`/bin/kill` 程序**：`/bin/kill -9 24818` 发 SIGKILL 给进程；`/bin/kill -9 -24817` 发 SIGKILL 给**整个进程组**（负号表示组）。
- **键盘**：ctrl-c / ctrl-z。
- **`kill` 函数**：`kill(pid[i], SIGINT)` 向指定进程发信号。

### 接收算法的内核侧

- 设 `pnb = pending & ~blocked`（进程 p 的**待决且非阻塞**信号集）：
  - 若 `pnb == 0`：控制传给 p 逻辑流的下一条指令；
  - 否则：选 pnb 中**最低非零位 k**，强制 p 接收信号 k；对 pnb 中所有非零 k 重复；再把控制传给下一条指令。

### 默认动作与安装处理程序

- 每类信号有预定义**默认动作**：进程终止；进程停止直到 `SIGCONT`；进程忽略。
- 安装处理程序：

```c
handler_t *signal(int signum, handler_t *handler);
```

- `SIG_IGN`：忽略该类信号；`SIG_DFL`：恢复默认动作；否则 `handler` 是用户级处理程序地址（"安装"；执行它叫"捕获/处理"）。返回时控制回到被中断的指令。
- 警告：本讲义用 `signal` 简化，实际应使用 `sigaction`。

### 处理程序是并发流

- 信号处理程序是与主程序**并发的独立逻辑流**（不是进程），仅存在到返回主程序为止；处理程序可被其他处理程序**中断（嵌套）**。

### 阻塞与解除阻塞

- **隐式**：内核阻塞**当前正在处理的类型**的待决信号（SIGINT 处理程序不会被另一个 SIGINT 中断）。
- **显式**：`sigprocmask`；配套 `sigemptyset`（建空集）、`sigfillset`（全加入）、`sigaddset`（加入）、`sigdelset`（删除）。

```c
sigset_t mask, prev_mask;
sigemptyset(&mask);
sigaddset(&mask, SIGINT);
sigprocmask(SIG_BLOCK, &mask, &prev_mask);   /* 阻塞 SIGINT 并保存旧掩码 */
/* ... 不会被 SIGINT 中断的代码区 ... */
sigprocmask(SIG_SETMASK, &prev_mask, NULL);   /* 恢复旧掩码 */
```

### 编写安全处理程序的指南（G0–G5）

- **G0**：处理程序**尽量简单**（如置全局标志后返回）。
- **G1**：只调用**异步信号安全 (async-signal-safe)** 的函数——`printf`、`sprintf`、`malloc`、`exit` **不安全**！
- **G2**：进入/退出时**保存并恢复 errno**（防止其他处理程序覆盖）。
- **G3**：访问共享数据结构时**临时阻塞所有信号**防损坏。
- **G4**：全局变量声明为 **`volatile`**（防止编译器放进寄存器）。
- **G5**：全局标志声明为 **`volatile sig_atomic_t`**（只读或只写，如 `flag = 1` 而非 `flag++`），此类标志无需像其他全局那样保护。

### 异步信号安全性（Async-Signal-Safety）

- 函数**可重入 (reentrant)**（所有变量在栈帧上）或**不被信号中断**则安全。
- POSIX 保证 **117 个**函数安全。常见的：`_exit`、`write`、`wait`、`waitpid`、`sleep`、`kill`。
- 常见但**不在列表**：`printf`、`sprintf`、`malloc`、`exit`。
- **不幸的事实：`write` 是唯一异步信号安全的输出函数。**
- 安全格式化输出：用 csapp.c 的 **SIO（安全 I/O 库）**——`sio_puts`、`sio_putl`、`sio_error`、`sio_printf`（识别 `%c %s %d %u %x %%`）。

> **核心结论**：信号是内核发给进程的小消息（ID 1–30）；pending 位向量不排队（同类最多一个）、blocked 可屏蔽（SIGKILL/SIGSTOP 除外）；处理程序是与主程序并发的独立流，需遵循 G0–G5 与 async-signal-safe 原则（只有 `write` 安全输出）。

## 7. 正确的信号处理

### 不能用信号计数事件

**反例 `fork14`（错误！）**：子进程 `sleep(1); exit(0)`，父进程 `signal(SIGCHLD, child_handler)` 后 `while (ccount > 0);` 自旋，handler 里 `wait(NULL); ccount--`。

- **待决信号不排队**：每种信号一位 pending 位——**同类待决信号至多一个**。
- 多个子进程同时终止，`SIGCHLD` 被**合并**；handler 每次调用只 reap 一个 → `ccount` 永远不到 0，**挂起**。
- **不能靠信号计数事件**（如子进程终止次数）。

**正确写法 `child_handler2`**：**把 `wait` 放进循环**，reap 所有已终止子进程：

```c
void child_handler2(int sig) {
    int olderrno = errno;
    pid_t pid;
    while ((pid = wait(NULL)) > 0) {   /* 收割所有已终止子进程 */
        ccount--;
        ...
    }
    if (errno != ECHILD) sio_error("wait error");
    errno = olderrno;
}
```

### 同步流以避免竞态（Race）

**反例**：简单 shell 的 SIGCHLD 处理程序，假设"父进程先于子进程运行"：

- 父进程 `fork()` 后调用 `addjob(pid)`；子进程 `execve` 可能**立即终止**，SIGCHLD 处理程序的 `deletejob` **先于 `addjob`** 执行 → 竞态。

**修正**（`procmask2.c`）：在 fork **之前**阻塞 SIGCHLD，父进程 `addjob` 之后解除阻塞；子进程 `execve` 前解除阻塞：

```c
sigprocmask(SIG_BLOCK, &mask_one, &prev_one);   /* 父：阻塞 SIGCHLD */
if ((pid = fork()) == 0) {
    sigprocmask(SIG_SETMASK, &prev_one, NULL);  /* 子：execve 前解除 */
    execve("/bin/date", argv, NULL);
}
sigprocmask(SIG_BLOCK, &mask_all, NULL);        /* 父：addjob 期间阻塞所有 */
addjob(pid);
sigprocmask(SIG_SETMASK, &prev_one, NULL);      /* 父：解除阻塞 */
```

### 显式等待信号

- 主程序显式等待 SIGCHLD：handler 里 `pid = waitpid(-1, NULL, 0)`，主程序 `while (!pid);` 自旋。
  - **自旋**：正确但**浪费**；
  - `while (!pid) pause();`：**存在竞态**——检查 pid 与进入 pause 之间可能已收到信号；
  - `while (!pid) sleep(1);`：安全但**慢**（最多 1 秒才响应）。
- **解决：`sigsuspend`**——"设置掩码 + pause + 恢复掩码"的**原子（不可中断）**版本：

```c
int sigsuspend(const sigset_t *mask);
/* 等价于原子的：
   sigprocmask(SIG_SETMASK, &mask, &prev);
   pause();
   sigprocmask(SIG_SETMASK, &prev, NULL);  */
```

```c
pid = 0;
while (!pid)
    sigsuspend(&prev);     /* 原子地解除 SIGCHLD 阻塞并等待 */
```

> **核心结论**：待决信号不排队 → 不能用信号计数，handler 必须循环 `wait` 收割全部；共享数据结构操作要阻塞信号防止竞态（fork 前阻塞 SIGCHLD、addjob 后解除）；等待信号用 `sigsuspend` 原子完成"设掩码+暂停"，避免自旋、竞态与慢轮询。

## 8. 非局部跳转

### 机制

- **非局部跳转 (nonlocal jump)**：强大（但危险）的用户级机制，把控制转移到任意位置——**受控地打破过程调用/返回纪律**，用于错误恢复与信号处理。

```c
int setjmp(jmp_buf j)
void longjmp(jmp_buf j, int i)
```

- **`setjmp`**：必须在 longjmp 之前调用；标识后续 longjmp 的**返回点**；把当前寄存器上下文、栈指针、PC 存入 `jmp_buf`，**返回 0**。**调用一次，返回一次或多次**。
- **`longjmp`**：在 setjmp 之后调用；从跳转缓冲 `j` 记住的 setjmp **再次返回**——这次返回 **i** 而非 0；恢复寄存器上下文（栈指针、基指针、PC），把 `%eax`（返回值）设为 i，跳到缓冲存的 PC。**调用一次，永不返回**。

### 示例：从深层嵌套直接返回

```c
jmp_buf buf;
void foo(void) { if (error1) longjmp(buf, 1); bar(); }
void bar(void) { if (error2) longjmp(buf, 2); }

int main() {
    switch(setjmp(buf)) {
    case 0: foo(); break;
    case 1: printf("Detected an error1 condition in foo\n"); break;
    case 2: printf("Detected an error2 condition in foo\n"); break;
    default: printf("Unknown error condition in foo\n");
    }
    exit(0);
}
```

### 局限：只在栈纪律内工作

- **只能 long jump 到"已被调用但尚未完成"的函数的运行环境**——被跳过的栈帧不再有效。
- 例如：`P1` 调用 `P2`、`P2` 里 `setjmp(env)` 后返回，`P1` 再调 `P3`、`P3` 里 `longjmp(env, 1)` ——**不行**，因为 `P2` 已返回，其环境已失效。

### 应用：ctrl-c 后自动重启

- `sigsetjmp`/`siglongjmp` 组合：安装 SIGINT handler 调用 `siglongjmp(buf, 1)`；主程序 `sigsetjmp(buf, 1)` 非零分支打印 "restarting" 并继续 `processing...`——实现**程序被 ctrl-c 后重启自身**。

> **核心结论**：setjmp 记录返回点并返回 0，longjmp 从该点"再返回一次"并带回自定义值；适合错误恢复与信号处理，但只对"已调用未完成"的函数环境有效，不能跨已返回的栈帧。

## 总结

| 概念 | 要点 |
|---|---|
| **异常** | 硬件+内核的控制转移：异步中断 / 同步陷阱、故障、中止；异常表索引 |
| **系统调用** | 陷阱；`%rax` 传号、参数走调用约定、返回 `%rax`；近 400 个，几乎都可能失败（−1 + errno） |
| **进程** | 运行中程序的实例；私有地址空间（虚拟内存）+ 逻辑控制流（上下文切换） |
| **上下文切换** | 保存/恢复寄存器 + 换页表；单核交错、多核并行；由内核调度 |
| **进程控制** | fork（两次返回）、exit（不返回）、wait/waitpid（收割）、execve（换程序） |
| **僵尸** | 终止但未收割；父进程用 wait 收割，孤儿由 init 收 |
| **Shell** | read/evaluate 循环；前台 waitpid、后台打印 pid；后台僵尸需信号收割 |
| **信号** | 内核小消息（ID 1–30）；pending 不排队、blocked 可屏蔽；进程组 + 键盘/`kill` 发送 |
| **安全处理** | G0–G5 指南；只调 async-signal-safe 函数（`write` 唯一安全输出） |
| **正确信号** | handler 循环收割；阻塞信号防竞态；`sigsuspend` 原子等待 |
| **非局部跳转** | setjmp/longjmp 打破调用返回纪律；仅限"已调用未完成"环境 |
