## 1. 内存抽象与总线事务

### Load 与 Store

- **Load（载入）**：从内存读到 CPU，例如 `movq 8(%rsp), %rax`
- **Store（存储）**：从 CPU 写到内存，例如 `movq %rax, (%rbx, %rcx, 2)`

### 总线（Bus）

- **总线 (Bus)**：一组并行的导线，负责传输地址（address）、数据（data）与控制信号（control signals）。
- 总线通常被多个设备**共享**。

![[Pasted image 20260819211158.png]]

### 内存读事务（Memory Read Transaction）

读操作分三步完成：

1. CPU 把地址 $A$ 放到内存总线上。
2. 主存从总线上读出地址 $A$，取出字 $x$，放回总线。
3. CPU 从总线读出字 $x$，复制到寄存器 `%rax`。

### 内存写事务（Memory Write Transaction）

写操作分三步完成：

1. CPU 把地址 $A$ 放到总线上；主存读取该地址并等待对应的数据字到达。
2. CPU 把数据字 $y$ 放到总线上。
3. 主存从总线读出数据字 $y$，存入地址 $A$。

> **核心结论**：CPU 与主存之间通过**总线**以"地址 + 数据"的事务形式交换信息，读/写各需三拍完成。

## 2. 存储技术：SRAM 与 DRAM

### RAM 的基本特征

- RAM 传统上封装为**芯片**（也可嵌入处理器芯片）。
- 基本存储单元是**单元 (cell)**，每单元存 1 位。
- 多个 RAM 芯片组成一个**内存 (memory)**。
- 两大类：**SRAM（静态 RAM）** 与 **DRAM（动态 RAM）**。

### SRAM vs DRAM

| | SRAM | DRAM |
|---|---|---|
| 每比特晶体管数 | 6 或 8 | 1（1 晶体管 + 1 电容） |
| 访问时间 | 1×（快） | 10×（慢） |
| 需要刷新？ | 否，状态无限保持 | 是，必须周期性刷新 |
| 需要 EDC？ | 可选 | 是（检错纠错） |
| 成本 | 约 100× | 1× |
| 用途 | **缓存内存 (Cache memories)** | **主存 (Main memory)**、帧缓冲 |

**EDC**：错误检测与纠正（Error detection and correction）。

![[Pasted image 20260819211711.png]]

### 发展趋势

- SRAM 随半导体工艺缩放，已接近极限。
- DRAM 缩放受**最小电容**限制——电容的深宽比（aspect ratio）限制了可挖深度，同样接近极限。

### 增强型 DRAM（Enhanced DRAM）

- DRAM 单元的**工作原理自 1970 年 Intel 商业化以来未变**；改变的是接口逻辑与更快的 I/O。
- **同步 DRAM (SDRAM)**：用常规时钟信号代替异步控制。
- **双倍数据率同步 DRAM (DDR SDRAM)**：双沿时钟，每个引脚每周期发 2 位；按预取缓冲大小区分类型——DDR（2 位）、DDR2（4 位）、DDR3（8 位）、DDR4（16 位）。2010 年前后成为服务器与台式机标准；Intel Core i7 支持 DDR3/DDR4。

### DRAM 的组织与读取

- **$d \times w$ DRAM**：共 $d\cdot w$ 位，组织成 $d$ 个**超单元 (supercell)**，每个超单元 $w$ 位（如 16×8 芯片 = 16 个 8 位超单元）。
- 读取超单元 $(2,1)$ 的步骤：
  1. **行访问选通 (RAS)** 选中第 2 行，把整行复制到**内部行缓冲 (row buffer)**。
  2. **列访问选通 (CAS)** 选中第 1 列，把超单元 $(2,1)$ 从缓冲复制到数据线上，最终回到 CPU。
  3. 数据写回行以完成刷新。

![[Pasted image 20260819212306.png]]

![[Pasted image 20260819212315.png]]

### 数据在模块中的分条（Striping）

- 64 位字被**分条**到多个 RAM 芯片上：地址 $A$ 的位 0–7 给 DRAM 0，位 8–15 给 DRAM 1，……位 56–63 给 DRAM 7。
- 典型配置：**64 MB 内存模块**由 8 个 `8M×8` DRAM 组成，每个芯片贡献一个字节，整体形成一个 64 位数据通路。

![[Pasted image 20260819212336.png]]

> **核心结论**：DRAM 用 1 晶体管 1 电容存储、需刷新与 EDC、成本低、用作主存；SRAM 用 6 晶体管、无需刷新、速度快、成本高、用作缓存。64 位字按字节分条在多个 DRAM 芯片上并行存取。

## 3. 局部性原理（Locality）

### CPU-内存差距持续扩大

- CPU、DRAM、磁盘之间的速度差距（**CPU-Memory Gap**）不断加大，是存储层级的根本动机。

![[Pasted image 20260819212806.png]]

### 局部性原理

**局部性原理 (Principle of Locality)**：程序倾向于使用地址接近或等于最近所用地址的数据和指令。

- **时间局部性 (Temporal locality)**：最近被引用的条目很可能在近期再次被引用。
- **空间局部性 (Spatial locality)**：地址相邻的条目倾向于在时间上接近地被引用。

### 局部性示例

```c
sum = 0;
for (i = 0; i < n; i++)
    sum += a[i];
return sum;
```

| 引用 | 模式 | 局部性类型 |
|---|---|---|
| 数据：数组 `a[i]` 依序访问 | stride-1 引用模式 | **空间局部性** |
| 数据：变量 `sum` 每次迭代都引用 | 同一地址 | **时间局部性** |
| 指令：依序执行 | 顺序地址 | **空间局部性** |
| 指令：循环反复执行 | 周期循环 | **时间局部性** |

### 工作集（Working Set）

**定义**：程序在任意时刻并不会访问它的全部数据，而只会反复触碰其中很小的一部分——这一小部分"当下正在被使用"的数据就是它的**工作集 (Working Set)**。"当下"要看上下文（某个循环里正在处理的数组片段，或整个运行期的活跃数据），且既包括数据也包括指令。

**为什么局部性决定它的大小**：时间局部性好的程序反复访问同一批地址，空间局部性好的程序把访问集中在相邻地址——两者都让工作集变小；而工作集越小，缓存就越容易把它整个装下。

**它为什么是存储层级有效的关键**：快而小的缓存不必装下程序的所有数据，只要把"当下要用的那一小块"（工作集）装进去，绝大多数访问就能命中。所以"工作集装得下缓存"就是缓存最有效的情形；一旦工作集超出缓存容量，就频繁发生**容量缺失 (capacity miss)**（第 4 节）。把这里的"缓存/容量缺失"换成"主存/抖动"，就是第 9 章虚拟内存里的同一套逻辑。

### 局部性是良性循环

- 局部性常常**自然发生**，硬件利用它变快；
- 硬件在局部性下更快，软件就被写成具有更多局部性。

### 定性判断局部性（Qualitative Estimates）

能"看代码就说出局部性好坏"是专业程序员的关键技能。判断方法就一句话：**C 数组按行主序存放，遍历要沿最后一个（最内层）下标走才能 stride-1**。看三个例子：

```c
/* ✅ 好：按行遍历，每行连续访问（stride-1） */
int sum_array_rows(int a[M][N]) {
    int i, j, sum = 0;
    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            sum += a[i][j];
    return sum;
}

/* ❌ 差：按列遍历，跨行跳跃，一个缓存块只用到一个元素 */
int sum_array_cols(int a[M][N]) {
    int i, j, sum = 0;
    for (j = 0; j < N; j++)
        for (i = 0; i < M; i++)
            sum += a[i][j];
    return sum;
}

/* 三维：把 j（最后一个下标）调成最内层，即得 stride-1 */
int sum_array_3d(int a[M][N][N]) {
    int i, j, k, sum = 0;
    for (i = 0; i < N; i++)
        for (k = 0; k < M; k++)
            for (j = 0; j < N; j++)
                sum += a[k][i][j];
    return sum;
}
```

| 函数 | 访问模式 | 局部性 |
|---|---|---|
| `sum_array_rows` | 每行连续访问 | ✅ 好 |
| `sum_array_cols` | 跨行跳跃访问 | ❌ 差（除非 M 很小） |
| `sum_array_3d` | 最后下标在最内层 → stride-1 | ✅ 好 |

> **核心结论**：局部性分为**时间局部性**（同一地址重复引用）与**空间局部性**（相邻地址连续引用）；C 数组按**行主序 (row-major)** 存放，遍历应沿行方向（stride-1）以获取好的空间局部性——局部性让程序的工作集（见上）变得很小，从而能被缓存整个装下。

## 4. 存储层级与缓存基本概念

### 存储层级的基本性质

- 快的存储技术**每字节更贵、容量更小**，且有时更耗电（发热）。
- CPU 与主存速度差距在扩大。
- 写得好（well-written）的程序往往具有良好局部性。
- 这三条互补，催生了 **存储层级 (memory hierarchy)** 的组织方式。

### 示例存储层级（L0–L6）

| 层级 | 设备 | 每层缓存的内容来源 |
|---|---|---|
| L0 | **Regs**（CPU 寄存器） | 从 L1 取的字 |
| L1 | **L1 cache（SRAM）** | 从 L2 取的缓存行 |
| L2 | **L2 cache（SRAM）** | 从 L3 取的缓存行 |
| L3 | **L3 cache（SRAM）** | 从主存取来的缓存行 |
| L4 | **主存（DRAM）** | 从本地磁盘取的磁盘块 |
| L5 | **本地二级存储（磁盘）** | 从远程服务器取的文件 |
| L6 | **远程二级存储（Web 服务器）** | —— |

从 L0 到 L6：设备**越来越大、越来越慢、每字节越来越便宜**。

### 缓存（Cache）与层级的根本思想

- **缓存 (Cache)**：一个更小、更快的存储设备，作为更大更慢设备数据的**暂存区 (staging area)**。
- **核心机制**：对每一层 $k$，更快更小的 $k$ 层充当更大更慢的 $k+1$ 层的缓存。
- **为什么有效**：因为局部性——程序访问 $k$ 层数据的频率远高于 $k+1$ 层；因此 $k+1$ 层可以更慢、更大、每比特更便宜。
- **Big Idea（理想）**：存储层级创造出**一大片存储池**——价格接近底部廉价存储，却以顶部快速存储的速度向程序供数。

### 缓存的基本概念：命中与缺失

- 数据以**块（block）**为传输单位复制（块大小由缓存与内存两侧共同定义）。
- **命中 (Hit)**：所需块已在缓存中。
- **缺失 (Miss)**：所需块不在缓存中：
  - 把块从内存取出存入缓存；
  - **放置策略 (Placement policy)** 决定块放哪里；
  - **替换策略 (Replacement policy)** 决定哪个块被逐出（victim）。

### 三类缓存缺失（3 Types of Cache Misses）

1. **冷缺失（强制缺失）(Cold / Compulsory miss)**：缓存初始为空、对该块**第一次引用**。
2. **容量缺失 (Capacity miss)**：活跃缓存块集合（**工作集 working set**）大于缓存容量。
3. **冲突缺失 (Conflict miss)**：放置策略把多个数据对象映射到同一小集合块（如块 $i$ 必须放在块 $i \bmod 4$）。缓存容量够大，但多个对象竞争同一位置——例如反复引用块 $0, 8, 0, 8, \dots$ 每次都缺失。

### 存储层级中的缓存实例

| 缓存类型 | 缓存什么 | 缓存在哪里 | 延迟（周期） | 管理者 |
|---|---|---|---|---|
| 寄存器 | 4–8 字节字 | CPU 核心 | 0 | 编译器 |
| TLB | 地址翻译 | 片上 TLB | 0 | 硬件 MMU |
| L1 cache | 64 字节块 | 片上 L1 | 4 | 硬件 |
| L2 cache | 64 字节块 | 片上 L2 | 10 | 硬件 |
| 虚拟内存 | 4-KB 页 | 主存 | 100 | 硬件 + OS |
| 缓冲区缓存 | 文件部分 | 主存 | 100 | OS |
| 磁盘缓存 | 磁盘扇区 | 磁盘控制器 | 100,000 | 磁盘固件 |
| 网络缓冲区缓存 | 文件部分 | 本地磁盘 | 10,000,000 | NFS 客户端 |
| 浏览器缓存 | 网页 | 本地磁盘 | 10,000,000 | Web 浏览器 |
| Web 缓存 | 网页 | 远程服务器磁盘 | 1,000,000,000 | Web 代理服务器 |

> **核心结论**：存储层级 = 以"快而小"的设备缓存"慢而大"的设备；靠**局部性**保证上层命中率高。缺失分为冷/容量/冲突三类，其中冲突缺失由放置策略的受限映射造成。

## 5. 缓存组织：S/E/B、直映射/组相联/中间位索引

> **交叉引用**：第 10 讲"缓存基础回顾"中的局部性、工作集与三类缓存缺失概念与第 3、4 节重复，已分别并入[[#3. 局部性原理（Locality）|第 3 节]]与[[#4. 存储层级与缓存基本概念|第 4 节]]，此处不再赘述。

### CPU 缓存

- CPU 缓存是**小而快、基于 SRAM** 的内存，由**硬件自动管理**，保存主存常用块。
- CPU 先到缓存找数据。典型结构：CPU 芯片内寄存器堆 + ALU + **缓存内存**，经内存总线连主存。

![[Pasted image 20260819215601.png]]

### 通用缓存组织（S, E, B）

缓存由 **S = $2^s$ 个组 (sets)** 组成，每组有 **E = $2^e$ 条行 (lines)**，每条行存 **B = $2^b$ 字节**的数据块：

- **缓存容量 $=S \times E \times B$ 数据字节**
- 每行含：**有效位 v** + **标记 tag** + $B$ 字节数据
- 内存地址划分为三段：**标记 (tag) $t$ 位 | 组索引 (set index) $s$ 位 | 块偏移 (block offset) $b$ 位**

![[Pasted image 20260819214412.png]]

### 直映射缓存（Direct-Mapped，$E = 1$）

- 每组仅 1 行，地址的**组索引**直接决定唯一可能的位置。
- 访问流程：由组索引**找组** → 检查该行的有效位 + 标记是否匹配 → **命中**则按**块偏移**取数据；不匹配（**缺失**）则**驱逐旧行并替换**。

![[Pasted image 20260819214657.png]]

**直映射仿真**（4 位地址，$t=1, s=2, b=1$，$M=16$ 字节，$S=4$ 组、$E=1$、$B=2$）：

| 访问地址 | 二进制 | 结果 | 类型 |
|---|---|---|---|
| 0 | `0000` | 缺失 | 冷缺失 |
| 1 | `0001` | 命中 | 与块 0 同组同块 |
| 7 | `0111` | 缺失 | 冷缺失 |
| 8 | `1000` | 缺失 | **冲突缺失**（与块 0 争同一组，驱逐块 0） |
| 0 | `0000` | 缺失 | **冲突缺失**（块 0 被驱逐后重回） |

> `M[0]` 与 `M[8]` 毫无关联，却因映射到同一组而互相干扰对方在缓存中的存在。

### 地址、块编号与 tag 的作用

**地址三段与"块编号"**：仿真里的 4 位二进制是**字节地址**，不是块编号。它拆成 tag(1 位) | 组索引(2 位) | 块偏移(1 位)：

| 地址 | tag | 组索引→组 | 块偏移 | 块编号 |
|---|---|---|---|---|
| `0000`（0） | 0 | `00`→组 0 | 0 | 0（M[0-1]） |
| `0001`（1） | 0 | `00`→组 0 | 1 | 0（M[0-1]） |
| `0111`（7） | 0 | `11`→组 3 | 1 | 3（M[6-7]） |
| `1000`（8） | 1 | `00`→组 0 | 0 | 4（M[8-9]） |
| `0000`（0） | 0 | `00`→组 0 | 0 | 0（M[0-1]） |

**块编号 = 地址去掉低 $b$ 位**（本例 $b=1$，即 地址 >> 1）。组索引选"去哪个组"，块偏移选"块内第几个字节"，两者都不参与块的编号。

**为什么 1 命中**：块大小 $B=2$ 字节，地址 0 和 1 属于同一个块 `M[0-1]`。取 0 时（冷缺失）把整块装入组 0，紧接着访问 1 就在块里 → 命中——这是**空间局部性**的直接体现：相邻地址共享一块，取一次带进一片。

**为什么需要 tag**：缓存太小，组数 $S$ 远小于内存块数。本例 $S=4$ 组对应 8 个内存块，平均每组要服务 $8/4 = 2$ 个块，而组里只有 $E=1$ 行、装不下全部候选。于是行里必须记录"现在装的是哪个"——**tag 就是这一行里块的身份标记**。访问按"组索引找组 + 有效位 + tag 匹配"判定命中：tag 不匹配说明组里是别的块，算缺失。块 0（tag=0）与块 4（tag=1）组索引都是 `00`，竞争组 0、靠 tag 区分，谁后到谁驱逐对方——这正是轨迹里 0、8 互相驱逐、回到 0 仍缺失的原因。

**tag 什么时候可以消失**：如果缓存大到每组恰好只对应一个块（$S = M/B$，即缓存≈内存），每组就只有那一个候选，无需区分。正因缓存"快而小"、罩不住大内存，每组才要服务多个块——**tag 是小缓存罩大内存的必然代价**，其位数 $= \log_2(\text{每组对应的块数})$。

### 组相联缓存（Set-Associative，E > 1）

- 每组 **E 条行**（如 $E=2$ 为 2 路组相联），把组索引相同的多个块放入同一组，缓解冲突。
- 访问流程：找组 → **并行比较组内所有行的标记** → 命中则取数据；未命中则从组内**选一行驱逐**。
- **替换策略 (Replacement policy)**：随机、**最近最少使用 (LRU)** 等。

**2 路组相联仿真**（$t=2, s=1, b=1$，$S=2$ 组、$E=2$、$B=2$）：

| 访问地址 | 二进制 | 结果 | 类型 |
|---|---|---|---|
| 0 | `0000` | 缺失 | 冷缺失 |
| 1 | `0001` | 命中 | 块 0 仍在 |
| 7 | `0111` | 缺失 | 冷缺失 |
| 8 | `1000` | 缺失 | 冷缺失（块 0 与 8 可共处一组） |
| 0 | `0000` | **命中** | 块 0 未被驱逐 ✅ |

> 对比直映射：E 从 1 增到 2 后，块 0 与块 8 可并存于同一组，冲突缺失转为命中。

### 为什么用中间位做组索引（Middle-Bit Indexing）

- **中间位索引 (Middle-bit indexing)**：地址形式 `TTSSBB`（T 标记、S 组索引、B 偏移），**充分利用空间局部性**。
- **高位索引 (High-bit indexing)**：地址形式 `SSTTBB`，空间局部性强的程序会产生大量**冲突**——相邻地址块落入不同组，访问顺序推进时不断驱逐彼此。
- 因此标准做法是用**中间位**做组索引。

### 实例：Core i7 L1 数据缓存

- 规格：**32 KB、8 路组相联、每块 64 字节、47 位地址**。
- 推导：$B = 64\ (b=6)$，$S = 64\ (s=6)$，$E = 8\ (e=3)$，$C = 64 \times 64 \times 8 = 32768 = 2^{15}$。
- 栈地址 `0x00007f7262a1e010` 按 tag(35) | 组索引(6) | 块偏移(6) 拆开（看低 16 位 `0xe010 = 1110 0000 0001 0000`，其中 bit 4 = 1、bits 12–15 = `1110`）：

| 段 | 取的位 | 结果 | 含义 |
|---|---|---|---|
| **块偏移** | bits 0–5 | `010000` = **0x10** | 块内第 17 字节 |
| **组索引** | bits 6–11 | `000000` = **0x0** | 去第 0 组 |
| **tag** | bits 12–46 | **0x7f7262a1e**（35 位） | 块的身份 |

解读：

- **块偏移 0x10**：块基址 = 地址去掉低 6 位 = `0x00007f7262a1e000`，整块范围 `0x...e000 ~ 0x...e03f`（64 字节），要的是块内第 17 个字节。
- **组索引 0x0**：落入第 0 组；凡 bits 6–11 为 `000000` 的地址（栈、堆里的都可能）都竞争这一组。
- **tag 0x7f7262a1e**：第 0 组有 8 行（8 路），同时最多装 8 个 tag 不同的块。

访问判定：按组索引去 set 0 → 并行比对 8 行的 tag 是否为 `0x7f7262a1e` → 是且 valid=1 则**命中**（按偏移取字节）；否则**缺失**，从下级缓存/内存取整块 `0x...e000` 并替换一行。

> 该栈地址组索引恰为 0，会和所有"低 12 位 ≈ 0x000"的地址争 set 0 的 8 个位置——若栈上密集出现这类地址，它们会在 set 0 内互相驱逐（冲突缺失），即使整个栈装得下 32KB。

> **核心结论**：缓存用 $(S, E, B)$ 刻画——$2^s$ 组、每组 $2^e$ 行、每块 $2^b$ 字节；地址拆成标记/组索引/块偏移。直映射冲突多，组相联用多路缓解冲突；组索引取**中间位**以利用空间局部性。

## 6. 写策略与性能指标

### 写命中的处理（Write-Hit）

数据在 L1、L2、L3、主存里有多份副本——写操作必须决定"改哪一份、什么时候传播下去"，于是有两种命中策略：

- **写直达 (write-through)**：**立即**把新值写回内存——实现简单，但每次写都要走内存。
- **写回 (write-back)**：先只改缓存里的副本、置**脏位 (dirty bit)**，等该行**被驱逐时才写回**内存——省内存流量，但要维护脏位。

### 写缺失的处理（Write-Miss）

写操作的目标块不在缓存里，还要再决定"**要不要先把块装进来**"：

- **写分配 (write-allocate)**：先像读缺失一样把块取进缓存，再在缓存里更新——适合**同一块还会被反复写/读**的情形。
- **非写分配 (no-write-allocate)**：**不装块**，直接写向下一级内存——适合**一次性写、写完不再碰**的情形。

两维组合成四种策略，常用的两种：

| 命中时 | 缺失时 | 用途 |
|---|---|---|
| 写直达 (write-through) | 非写分配 (no-write-allocate) | 传统简单实现 |
| **写回 (write-back)** | **写分配 (write-allocate)** | **现代系统**（如 Core i7） |

### 实际做法：写回 + 写分配

现代 CPU 的写流程：

1. **写命中**：更新块内容，置**脏位 = 1**（粘性，驱逐时才清除）。
2. **写缺失**：先按"读缺失"把块取进缓存，再按"写命中"执行写（取块 → 更新 → 置脏）。
3. **驱逐**：被替换的行若脏位 = 1，把整块 $2^b$ 字节**写回内存**、清除脏位，再装入新内容。

> **直觉**：写回 + 写分配的本质是"把多次写攒在缓存里、一次写回"。例如清零数组 `for (i=0; i<N; i++) arr[i] = 0;`——每块第一次写是缺失（取块），块内其余元素写都命中，一次取块换来整块本地写；驱逐时才把脏块整体写回内存。

### 性能指标（Cache Performance Metrics）

- **缺失率 (Miss rate)** = 缺失数 / 访问数 = 1 − 命中率。典型值：L1 约 3–10%，L2 可低至 <1%。
- **命中时间 (Hit time)**：把行交给处理器的时间（含判定是否命中）。典型：L1 约 4 周期，L2 约 10 周期。
- **缺失代价 (Miss penalty)**：缺失造成的额外时间，主存通常 50–200 周期（**趋势：越来越大**）。

**命中与缺失的天壤之别**——为什么用"缺失率"而非"命中率"：

假设命中时间 1 周期、缺失代价 100 周期：

- 97% 命中：$1 + 0.03 \times 100 = 4$ 周期
- 99% 命中：$1 + 0.01 \times 100 = 2$ 周期

> **99% 命中是 97% 命中的两倍快**——缺失代价极高，缺失率每降一点都价值巨大。

### 写缓存友好代码（Writing Cache Friendly Code）

- **让常见情况跑得快**：聚焦核心函数的内层循环。
- **最小化内层循环的缺失**：
  - **重复引用**变量（时间局部性）——好；
  - **stride-1 引用模式**（空间局部性）——好。

> **核心结论**：现代缓存用**写回 + 写分配**（脏位延迟写回、写缺失先取块）。性能三指标为缺失率/命中时间/缺失代价；因为缺失代价极大，"缺失率"比"命中率"更能反映性能。

## 7. 缓存友好编程：矩阵乘法缺失率与分块

### C 数组的内存布局（行主序）

- C 数组按**行主序 (row-major)** 分配。
- **沿行内移动**（`sum += a[0][i]`）：若块大小 $B > \text{sizeof}(a_{ij})$，可挖掘空间局部性，**缺失率 = $\dfrac{\text{sizeof}(a_{ij})}{B}$**。
- **沿列移动**（`sum += a[i][0]`）：访问相距很远的元素，**无空间局部性**，**缺失率 = 1（100%）**。

### 矩阵乘法背景

- $N \times N$ 矩阵，元素为 `double`（8 字节），$O(N^3)$ 次操作。
- 变量 `sum` 可保持在寄存器中。

### 循环顺序对缺失率的影响

假设块大小 = 32B（可容纳 4 个 double），$N$ 非常大（$1/N \approx 0$），缓存装不下多行。

**`ijk`（与 `jik` 等价）**：

```c
for (i=0; i<n; i++)
  for (j=0; j<n; j++) {
    sum = 0.0;
    for (k=0; k<n; k++)
      sum += a[i][k] * b[k][j];
    c[i][j] = sum;
  }
```

- 内层循环访问模式：A 沿行（**行式 row-wise**），B 沿列（**列式 column-wise**），C 固定。
- 每次迭代缺失率：A `0.25`，B `1.0`，C `0.0` → **平均 1.25 次缺失/迭代**（2 次加载，0 次存储）。

**`kij`（与 `ikj` 等价）**：

```c
for (k=0; k<n; k++)
  for (i=0; i<n; i++) {
    r = a[i][k];
    for (j=0; j<n; j++)
      c[i][j] += r * b[k][j];
  }
```

- 内层访问：A 固定（`r` 保持寄存器）、B 沿行、C 沿行。
- 每次迭代缺失率：A `0.0`，B `0.25`，C `0.25` → **平均 0.5 次缺失/迭代**（2 次加载，1 次存储）。

**`jki`（与 `kji` 等价）**：

```c
for (j=0; j<n; j++)
  for (k=0; k<n; k++) {
    r = b[k][j];
    for (i=0; i<n; i++)
      c[i][j] += a[i][k] * r;
  }
```

- 内层访问：A 沿列、B 固定、C 沿列。
- 每次迭代缺失率：A `1.0`，B `0.0`，C `1.0` → **平均 2.0 次缺失/迭代**（2 次加载，1 次存储）。

### 总结与实测

| 循环顺序 | 内层访问模式 | 平均缺失/迭代 | 说明 |
|---|---|---|---|
| `ijk` / `jik` | A 行式、B 列式 | 1.25 | 2 加载、0 存储 |
| `kij` / `ikj` | B、C 都行式 | **0.5** | 2 加载、1 存储 |
| `jki` / `kji` | A、C 都列式 | 2.0 | 2 加载、1 存储 |

Core i7 实测（每内层迭代周期数）：`kij/ikj (0.5)` ≪ `ijk/jik (1.25)` ≪ `jki/kji (2.0)`。

### 动机：矩阵乘法的时间局部性

- 输入数据共 $3n^2$，计算量 $2n^3$——**每个数组元素被用 $O(n)$ 次**，蕴含天然的时间局部性，但必须写对程序才能利用。

### 无分块的缺失分析

朴素版 `mmm`（`ijk` 顺序，内层读改写 `c`）：

```c
void mmm(double *a, double *b, double *c, int n) {
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            for (k = 0; k < n; k++)
                c[i*n+j] += a[i*n+k] * b[k*n+j];
}
```

假设：元素是 `double`（8 字节）、**缓存块 = 8 个 double**、**缓存 $C \ll n$**——缓存装不下几行，意味着两次扫描之间没有复用，每次内层扫描都得从头把 A 的行、B 的列搬一遍。

固定一个 `(i,j)`，看**一次完整的内层 k 扫描**各数组缺几次：

| 数组 | 访问方式 | 一次扫描缺失 | 原因 |
|---|---|---|---|
| **A** `a[i*n+k]` | 沿**行**走（连续地址） | $n/8$ | 块装 8 个 double，stride-1 每 8 个缺 1 次 |
| **B** `b[k*n+j]` | 沿**列**走（跨 $n\times8$ 字节） | $n$ | 每取 1 个 double 都在新块，块的 1/8 利用率 |
| **C** `c[i*n+j]` | 固定地址 | 0（已驻留） | 内层反复读改写同一处 |

一次扫描合计 $n/8 + n = 9n/8$ 次缺失。外层 `(i,j)` 有 $n^2$ 对、每对都完整扫一遍 k，所以总缺失：

$$(9n/8) \times n^2 = \frac{9}{8}\, n^3$$

直觉：A 行式访问本不差（每块全用上），但 $C \ll n$ 使每对 (i,j) 都重读整行 A、整列 B；B 列式访问是重灾区，每次只取块里的 1 个 double。

### 分块矩阵乘法（Blocked Matrix Multiplication）

```c
for (i = 0; i < n; i += B)
  for (j = 0; j < n; j += B)
    for (k = 0; k < n; k += B)
      /* B x B 小矩阵乘法 */
      for (i1 = i; i1 < i+B; i1++)
        for (j1 = j; j1 < j+B; j1++)
          for (k1 = k; k1 < k+B; k1++)
            c[i1*n+j1] += a[i1*n + k1] * b[k1*n + j1];
```

### 分块的缺失分析


> **前提**：缓存块 = 8 个 double；**三个 $B\times B$ 块能同时驻留缓存**（$3B^2 < C$：两个输入 + 一个输出），且缓存**恰好只够这 3 块**——算完一个输出块，下一个输出块的输入块都得重新取（块间无复用）。

![[Pasted image 20260820195430.png]]

如图，假设分块大小为 $B$，则算 $c$ 的一个 $B\times B$ 的**输出块**，需要把 $a$ 和 $b$ 的 $\frac{n}{B}$ 对输入块逐一取出相乘——即 $k$ 方向有 $\frac{n}{B}$ 步，每步取 1 个 A 块 + 1 个 B 块。

假设正在计算图中 $a$ 和 $b$ 的红色块相乘，那么这三个块（两个输入 + 一个输出）会被装进缓存里面并**驻留复用**。由于按行移动是 1-stride 的，每行的缺失数为 $\frac{B}{8}$（每块 8 个 double、每 8 个缺 1 次），一共有 $B$ 行，故**一个输入块**的缺失数为 $\frac{B^{2}}{8}$。

于是计算一个 $a$ 和 $b$ 的红色块相乘缺失数为 $\frac{2B^{2}}{8}$（两个输入块各取一次，取进来后在缓存里被 $B^2$ 次乘法复用），计算 $C$ 的一个**输出块**缺失数为 $\frac{n}{B}\times \frac{2B^{2}}{8}=\frac{nB}{4}$，一共有 $\left( \frac{n}{B} \right)^{2}$ 个输出块且**块间无缓存复用**，所以总缺失数为 $\frac{n^{3}}{4B}$。

> **注**：C 块本身的取入（每个输出块一次，$\frac{B^2}{8}$）是低阶项，已省略。对比无分块 $\frac{9}{8}n^3$，分块为 $n^3/(4B)$（$B=8$ 时约 36 倍差距）——根源在于分块让**每个输入块取进来后驻留、被复用 $O(B)$ 次**，而无分块每次要用数据都得重搬。

### 分块总结

- **无分块**：$(9/8)n^3$ 次缺失。
- **分块**：$\dfrac{1}{4B} n^3$ 次缺失。
- **取最大 $B$ 使 $3B^2 < C$**——三个块装进缓存：**两个输入 + 一个输出**。
- 巨大差异的原因：矩阵乘法有天然的时间局部性（元素被用 $O(n)$ 次），程序只要写得对就能兑现。

> **核心结论**：让内层循环**沿行主序（stride-1）**访问两个输入矩阵（`kij`），缺失率从 1.25/迭代 降到 0.5/迭代——仅靠**重排循环顺序**就提升空间局部性。分块把一次缓存不下的整行计算切成 $B \times B$ 的小块，使三个块同时驻留缓存（$3B^2 < C$），缺失从 $(9/8)n^3$ 降到 $n^3/(4B)$，用 $B$ 放大削减效果。

## 8. 存储技术：磁盘与 SSD

### 非易失内存（Nonvolatile Memories）

- DRAM 与 SRAM 是**易失 (volatile)** 的——断电即失信息。
- **非易失内存**断电仍保留值：
  - **只读内存 (ROM)**：生产时编程。
  - **电可擦除可编程 ROM (EEPROM)**：电子擦除能力。
  - **闪存 (Flash memory)**：具备部分（块级）擦除能力，约 10 万次擦除后磨损。
  - **3D XPoint**（Intel Optane）等新型非易失内存：新材料。
- **用途**：固件（BIOS、磁盘/网卡/图形加速器/安全子系统控制器）、**固态硬盘**（取代旋转磁盘）、磁盘缓存。

### 机械磁盘（Magnetic Disks）

- 磁盘由**盘片 (platters)** 组成，每盘两**面 (surface)**；每面由同心**磁道 (tracks)** 组成；每磁道由**扇区 (sectors)** 组成，扇区间有**间隙 (gaps)**。
- 读写头装在**臂 (arm)** 末端，在薄空气垫上飞过盘面；径向移动臂可定位到任意磁道。盘面以固定转速旋转。

### 磁盘容量（Disk Capacity）

- **容量**：可存储的最大位数。厂商用 GB/TB 表示，其中 $1\ \text{GB} = 10^9$ 字节，$1\ \text{TB} = 10^{12}$ 字节。
- 由三个技术因素决定：
  - **记录密度 (Recording density)**：单位磁道长度内可挤入的比特数（bits/in）。
  - **磁道密度 (Track density)**：单位半径内可挤入的磁道数（tracks/in）。
  - **面密度 (Areal density)**：记录密度 × 磁道密度（bits/in²）。

### 磁盘访问时间（Disk Access Time）

$$T_{access} = T_{avg\ seek} + T_{avg\ rotation} + T_{avg\ transfer}$$

- **寻道时间 (Seek time)**：把磁头定位到目标扇区所在磁道的时间，典型 $3$–$9$ ms。
- **旋转延迟 (Rotational latency)**：等待目标扇区首位转到读写头下的时间：
  $$T_{avg\ rotation} = \frac{1}{2} \times \frac{1}{\text{RPMs}} \times \frac{60\ \text{sec}}{1\ \text{min}}$$
- **传输时间 (Transfer time)**：读取目标扇区中比特的时间：
- 
  $$T_{avg\ transfer} = \frac{1}{\text{RPM}} \times \frac{1}{\text{avg  sectors/track}} \times \frac{60\ \text{sec}}{1\ \text{min}}$$

**示例**（转速 7200 RPM、平均寻道 9 ms、每磁道 400 扇区）：

- $T_{avg\ rotation} = \frac{1}{2} \times \frac{60}{7200} \times 1000 = 4$ ms
- $T_{avg\ transfer} = \frac{60}{7200} \times \frac{1}{400} \times 1000 = 0.02$ ms
- $T_{access} = 9 + 4 + 0.02 \approx 13$ ms

要点：
- 访问时间**由寻道与旋转延迟主导**。
- **扇区第一位最贵，其余免费**。
- SRAM 访问约 4 ns/双字，DRAM 约 60 ns；磁盘比 SRAM 慢约 40000×，比 DRAM 慢约 2500×。

### I/O 总线与读取磁盘扇区

- CPU 通过**内存总线**连主存，再经**总线接口 (bus interface)** 连 **I/O 总线**，后者挂 USB 控制器、图形适配器、磁盘控制器及扩展槽。

读取磁盘扇区的三步（**DMA** 流程）：

1. CPU 向磁盘控制器端口写入命令、**逻辑块号 (logical block number)** 与目标内存地址。
2. 磁盘控制器读取扇区，执行**直接内存访问 (DMA)** 传输到主存。
3. DMA 完成后，磁盘控制器通过**中断 (interrupt)** 通知 CPU。

### 固态硬盘（SSD）

- SSD 结构：I/O 总线 ↔ **DRAM 缓冲** + **闪存翻译层 (flash translation layer)** ↔ **闪存**。
- 闪存组织：**页 (pages)** 512B–4KB，**块 (blocks)** 32–128 页。
  - 数据以**页**为单位读写；
  - 页只能在**其所在块被擦除后**写入；
  - 块约 **1 万次**重复写入后磨损。

**性能特征**（Samsung 970 EVO Plus 基准）：

- 顺序访问快于随机访问（存储层级中的一贯主题）。
- 随机写棘手：擦除一块需约 1 ms，但 SSD 有**预擦除块池**；修改某页需把块内其余页复制到新块；SSD 用**写缓存**累积写入。
- 实测：顺序读 2,221 MB/s，顺序写 1,912 MB/s；随机读 61.7 MB/s，随机写 165 MB/s；深队列（DQ）随机读写 947 / 1028 MB/s。

**SSD vs 旋转磁盘**：

- 优点：无活动部件 → 更快、更省电、更抗震动。
- 缺点：可能磨损——由翻译层的**磨损均衡 (wear leveling)** 缓解（如 Samsung 保证每字节约 600 次写入）；2022 年每字节贵 4–5 倍。
- 旋转磁盘仍用于：**大容量存储**（视频、大数据集/数据库）、廉价桌面存储。

### 发展趋势

- **存储趋势**：SRAM、DRAM、磁盘的每 MB/GB 价格 30 年间暴跌（磁盘每 GB 价格从 1985 的 10 万降到 2015 的 0.03，约 330 万倍），访问时间改善远小于价格改善。
- **CPU 时钟速率**：2003–2005 年撞上 **"功耗墙 (Power Wall)"** 出现转折点，此后靠**多核**提升有效性能（Core 2 → Core i7，核数 2 → 4，有效周期时间大幅下降）。

> **核心结论**：磁盘访问 = 寻道 + 旋转 + 传输，主导成本在机械运动；SSD 用闪存（页读写、块擦除、有限寿命）以电代机械；非易失内存（ROM/EEPROM/Flash）用于固件与存储。CPU 时钟在功耗墙后靠多核前进。

## 总结

| 概念 | 要点 |
|---|---|
| **内存抽象** | CPU 经总线以读/写事务访问主存，地址+数据三拍完成 |
| **SRAM vs DRAM** | SRAM 快/贵/无需刷新，做缓存；DRAM 慢/便宜/需刷新+EDC，做主存 |
| **局部性** | 时间局部性（重复引用）+ 空间局部性（相邻地址）；行主序沿行遍历 |
| **工作集** | 程序当前处理的数据集合；局部性缩小工作集，装得下缓存则有效 |
| **存储层级** | L0 寄存器→L6 远程存储；每层是下一层的缓存，靠局部性工作 |
| **缓存缺失** | 冷（首次引用）、容量（工作集超容）、冲突（映射受限） |
| **缓存组织** | $(S, E, B)$：$2^s$ 组、$2^e$ 路、$2^b$ 字节块；容量 = $S \times E \times B$ |
| **直映射 vs 组相联** | 直映射冲突多；组相联多路并存缓解冲突 |
| **中间位索引** | 地址 `TTSSBB`，利用空间局部性；高位索引会产生大量冲突 |
| **写策略** | 写回+写分配为现代标准；脏位在驱逐时触发整块写回 |
| **性能三指标** | 缺失率（L1 3–10%）、命中时间（L1 4 周期）、缺失代价（主存 50–200 周期） |
| **循环重排** | `kij` 使 B、C 沿行访问，缺失 0.5/迭代（优于 `ijk` 的 1.25） |
| **分块** | 块尺寸 $B$ 满足 $3B^2 < C$，缺失从 $(9/8)n^3$ 降至 $n^3/(4B)$ |
| **磁盘** | 寻道+旋转+传输；首位最贵；DMA + 中断完成读取 |
| **SSD** | 页读写、块擦除、磨损均衡；顺序≫随机 |
| **趋势** | 价格暴跌、CPU 时钟到功耗墙后转向多核 |
