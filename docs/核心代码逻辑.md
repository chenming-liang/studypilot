## 一、全局架构

```
                    ┌─────────────────────────────────────────────┐
                    │                crates/tui (bin)              │
                    │  ratatui App │ 单线程所有权 + 统一 mpsc 事件总线  │
                    │  /import /review /outline 等斜杠命令 → 后台任务  │
                    └───────┬──────────────┬──────────────┬────────┘
                            │              │              │
                 ┌──────────▼───┐   ┌──────▼──────┐  ┌────▼─────────┐
                 │ crates/core  │   │crates/tools │  │crates/importer│
                 │ Agent Loop   │   │search_notes │  │ 解析→清洗→抽取  │
                 │ Provider trait│  │list_courses │  │ →入库流水线    │
                 │ Tool trait   │   │ (D6:只读工具) │  │              │
                 └──────┬───────┘   └──────┬──────┘  └────┬─────────┘
                        │                  │              │
              ┌─────────▼──────────┐      │              │
              │  crates/providers  │      │              │
              │  OpenAI-compatible │      │              │
              │  reqwest 非流式客户端│      │              │
              └────────────────────┘      │              │
                                          ▼              ▼
                                   ┌────────────────────────┐
                                   │     crates/storage     │
                                   │ rusqlite + FTS5(jieba) │
                                   │   data/mynotes.db      │
                                   └────────────────────────┘
```

**三条铁律（贯穿全库）：**

1. **D2 异步纪律**：rusqlite 与子进程调用一律 `tokio::task::spawn_blocking`，绝不在 async 上下文直接执行。
2. **单写回路**：TUI 中所有后台任务（聊天/导入/出题/批改/DB）都是 fire-and-forget 的 `tokio::spawn`，完成后把结果作为 `AppEvent` 投回**同一条** unbounded mpsc；`App` 状态只在主循环线程被修改，无锁无共享可变状态。
3. **命令 vs 工具（D6）**：`/import` `/delete` `/move` 等写操作/费用敏感操作直连内部函数，**不进 agent loop**；只有只读检索型工具（search_notes / list_courses）暴露给 LLM。
4. **命令参数全旗标化 + 向导直连（收口会话⑨）**：含自由文本字段的命令一律 `--字段 <值>`（`/review --course/--concept/--n`、`/import --dir/--course`、`/move --id/--course`、`/delete --id|--course`），旗标值可含空格、顺序无关——位置参数的"课程|概念"切分歧义从语法层面消除。向导完成时直连结构化入口，`handle_command` 文本解析仅服务手输路径（报错引导走向导）；`collect_flags` 通用旗标扫描为各命令共用。

## 二、三条主线数据流

### 导入（Import）

```
/import <dir> [--course 名]
  → walkdir 收集(排序确定) → 逐文件串行(费用/速率约束)
      ① parse_file:  md/txt 直读 │ pdf→python3 pdf_extract.py 子进程 │ pptx→zip+quick-xml
         产出 RawDoc { text, fts_text, content_hash }   ← content 与 FTS 两级分离
      ② clean:       content 层只剥 wikilink；fts 层再剔"目录"段+头部引用块
      ③ extract:     LLM 结构化抽取 {title, course, concepts}（D4 降级链）
                     **概念抽取质量改造（2026-08-30）**：① 输入从 `take(2000)` 改为全文
                     （cap 20000 字符——此前只喂开头导致概念全是章节级粗粒度，细知识点全漏）；
                     ② prompt 加 `CONCEPT_RULES` 硬定义（正例/反例：概念=可学习可考察的名词性
                     知识点；禁形容词「高效/可靠」、禁空泛主题「Rust 语言/内存安全」、禁目录式
                     命名、章节标题拆知识点、同义合并、5~12 个/篇指导）；③ `extract_concepts`
                     概念刷新专用入口（只返回概念名）
      ④ 入库:        content_hash 幂等去重 → notes+notes_fts(jieba 预分词)
                     → 概念 get_or_create + 关联 → 按 ## 标题切 chunk 入 note_chunks(+_fts)
   全程 ImportEvent 过 mpsc 上报进度，CancellationToken 随时可停
   （LLM 抽取等待经 providers::with_cancel 包装：Ctrl+C 立即中断，不等返回）
```

### 学习（Study / RAG）

```
用户输入 → submit() → 预算熔断检查(R6) → history 入栈
  → spawn_chat(): Agent + ToolBox{search_notes, list_courses} + AI-Tutor system prompt
  → Agent::run_loop: LLM ←→ 工具 多轮循环 → 最终答案
  → Done 事件: 累计 usage/成本、persist 新消息、渲染 trace + markdown 回复
```

### 复习（Review）

```
/review <课程> [--concept <自由文本>] [--n 数量]
  → 范围两种来源（同一 prompt 结构，只换范围指令）：
      无 --concept = 随机范围：concepts_with_material 里按掌握度加权随机抽概念子集
                   （薄弱优先但范围随机，治复读）
      有 --concept = 用户自由文本：文本当检索 query + 注入 prompt，AI 自主解析覆盖哪些知识点
  → 逐题生成（2026-08-30 改造，替代一次性批量出题）：
      素材一次收集存 ReviewState.ctx（Arc<QuizContext>，整轮范围一致）
      → LLM 出第 1 题即显示（ReviewReady 只带 1 题）
      → 用户作答当前题时后台预取下一题（generate_review_question → ReviewQuestionReady 回流）
      → 题型配额 choice=⌈n/2⌉ 剩余多者优先；prompt 带「已出题目」列表防重复考点
      → 推进时下一题未到位 = 等待态（workspace 渲染"出题中…"，Esc 可退）
      → 生成失败重试 1 次，耗尽优雅收束（已答的出部分摘要）
     prompt 单题化（P1考知识不考材料 / P2认知层级 / P3选项质量 / P4简答质量 / P5针对性 保留）
     → 每题生成即入库（quizzes/questions，quiz 行提前建）
     → 防重复（⑲重设计：**去重单位=题目，概念=主题非去重单位**——同 concept 可多角度
       反复考察，换皮改写才拒绝；多样性由 LLM 驱动，代码只做最后防线）：
       evidence history 进 prompt（同轮全量：题干+概念+学生判分+考察角度；
       跨轮 8 题截断题面仅 prompt）+ LLM 自报 aspect（definition/code_prediction/
       comparison/application/why/counterexample/debugging/transfer）作 coverage summary，
       已覆盖角度优先避开；**同轮 guard 只拦接近字面重复**（too_similar bigram Jaccard
       ≥0.75，实测校准：真同义改写 0.89 拒 / 模板跨概念 0.20 放），重试 prompt 带
       retry_hint（"生成有意义的新变体，换考察角度"）；概念级/contains 判重删除
  → 答题: 选择题本地判分(零成本) / 简答题 LLM 批改(score/missing/comment)
  → 每题: record_attempt + update_concept_mastery(UPSERT 累计)
  → 结束(答满 planned): 静态摘要卡 + 异步 LLM「已掌握/需巩固/下一步」小结建议
  → 下次出题 prompt 注入新掌握度 → 闭环
```
出题系统消息：只输出 JSON 本体（禁用代码块包裹整个输出），**题干/解析内的代码允许 ```c 等围栏**——否则 LLM 把 C 代码写成纯文本，Review workspace 渲染无高亮无缩进（CommonMark 剥缩进 + Indented CodeBlock 无语言标签）。解析时对文本字段做 `normalize_text`：LLM 常把换行**双重转义**成 `\\n`（JSON 解析后是字面反斜杠+n），还原为真实换行，否则整段代码压成一行。

**prompt 重构要点**（review.rs，单题版沿用）：P1 考知识不考材料（好题判据 = 去掉「根据笔记/第X章/某示例」前缀后依然成立，素材只支撑答案不进题干）；P2 认知层级（Recall/Explain/Predict/Apply 之一，禁止纯复述）；P3 选择题单选唯一正确、干扰项同质；P4 简答题 key_points 2~4 个可独立判分；P5 优先考察掌握度低的概念、每题 concept 取自概念列表。素材按概念分组标注（随机范围），禁止事项给反例（考材料/照抄示例/环境琐事/逐字复述）。解析 `parse_one_question`：裸对象 → `{"questions":[...]}` 旧格式 → 裸数组 → first_json_block 四级容错 + normalize_text。

## 三、Agent Loop（crates/core/src/agent.rs）

核心函数：`run_loop`（agent.rs:93）、`execute_tool`（agent.rs:191）。

```
for round in 1..=max_rounds(默认12):
    resp = provider.chat(msgs, tools.schemas())
    if resp.tool_calls 为空 → 推入最终 assistant 消息，返回 AgentResult
    else:
        推入 assistant_tool_calls 消息
        逐个执行 tool call，结果以 tool_result 消息回填，继续循环
超过 max_rounds → Err（模型未收敛）
```

关键机制：

- **search_notes 防重门控**：单次会话最多 3 次真实检索，且 query 不可重复。重复/超限不执行工具，而是返回提示文本让模型换关键词或基于已有结果作答。坏参数（q 提取失败）则透传 `execute_tool` 让工具自身的参数校验回错给模型修正——不谎报"重复查询"。
- **错误不炸循环**：未知工具 / 参数 JSON 解析失败 / 工具执行失败统一转成 `TOOL_ERROR: ...` 文本喂回模型自行调整（`tool_error_text`）。
- **AgentResult** 附带 `total_usage`、`new_messages`（循环期间新增消息，供 TUI 持久化）、`tool_trace`（工具调用轨迹，含 query 与命中数，供 UI 展示）。
- **错误回喂格式**：`TOOL_ERROR [{category}]: {message}`——category（parse/storage/api/api_server/transport/config）机器可读，模型可据此决定"换参数重试/换工具/放弃"（ToolResult 协议的轻量版，不改 trait 签名）。

### Context Manager（core/src/context.rs）

长会话全量重发 history 会导致 token 成本线性上涨。`trim_history(history, budget)`：

- **轮次原子**：一轮 = user 消息 + 其后全部非 user 消息；裁剪以轮为单位，`assistant(tool_calls)` 与 `tool_result` **永不拆散**（拆散会被 API 拒收）
- **策略**：从最新轮往回累计字符预算，装不下的最老轮整体丢弃；单轮即超预算也至少保留最后一轮
- **省略注记**：裁剪发生时在保留段最前插一条 user 角色注记（`[对话裁剪提示: 早期 N 轮已省略…]`）——多数 endpoint 不接受中部的 system 消息，user 角色最稳
- **接线**：`Agent` 默认启用（`DEFAULT_CONTEXT_BUDGET_CHARS` = 24_000 字符 ≈ 8k token），`with_context_budget` 覆盖、`without_context_trim` 关闭；TUI 层零改动

### 检索评测框架（eval/ + crates/tui/examples/eval.rs）

- 题集 `eval/questions.jsonl`：31 个真实学习问题，每题带 expect 笔记关键词
- 评测器 `cargo run --release -p tui --example eval -- --out eval/report-*.md`：离线跑 chunk 级 FTS（不调 LLM、零成本），输出 rank1/top3/top5 命中率 + miss 明细
- **判定锚点用 `source_path` 文件名而非笔记标题**——标题是导入时 LLM 重写的，不稳定
- **`--llm` 模式（真调 API）**：完整 RAG 链路回答 + judge 评分（0-10 + 幻觉判定），每题 2 次调用，报告含成本记账；31 题全量约 ¥0.43
- **BM25 基线（2026-08-27）：rank1 18/31，top3 26/31，top5 28/31**。miss 归因：噪声笔记（plan/README）污染排序 > 词法盲区（rsp/死锁）。结论：下一步收益最大的不是 hybrid embedding，而是噪声降权 + 补语料

### 噪声降权（storage/search.rs）

大纲/计划/索引类笔记（`file_stem` 含 readme/plan/index/syllabus/agenda，或路径含"索引/目录"）污染检索排序——基线评测的直接结论。机制：

- **SQL 候选池放宽 3 倍**（`FETCH_MULTIPLIER`），惩罚重排在 Rust 层做
- `is_noise_source` 判定 → 命中 chunk 的 bm25 加罚 `NOISE_PENALTY=5.0` → 重排截断 top_k
- chunk 级 `run_chunks` 与 note 级 `run`（复习出题路径）都覆盖；note 级 OR 降级排序键为「命中词数 desc → 非噪声优先 → bm25 asc」
- **效果（评测实测）：rank1 58% → 71%，top3 84% → 87%**，原被 plan/README 压住的内容 chunk（如 #6 分块总结）恢复排名

### LLM 端评测结论

**严格模式（旧，report-llm.md）**：prompt 约束"仅依据资料回答"——rank1 题 7.2 分 vs 非 rank1 题 3.6 分（强相关），0 幻觉，但语料缺口题全部拒答 0 分。

**开放模式（现行，report-llm-open.md）**：产品决策调整为**「笔记优先 + 外部补充明示」**——
- 笔记有相关内容 → 优先依据并 [n] 引用（[n] 只指向笔记片段）
- 笔记未覆盖 → 允许用模型自身知识补充，但必须明示「（笔记外补充）」
- 幻觉重新定义：不再罚"用外部知识"，只罚**错误事实**与**把外部知识伪装成笔记引用**——来源可区分性是底线
- 落点三处：`app.rs build_rag_system_prompt` 约束段、`tools/search_notes.rs` 工具描述、评测器 prompt/judge 同步
- **实测：平均分 6.1 → 9.3，低分题清零，0 幻觉**；检索与分数的强相关消失（外部知识兜底），judge 逐题确认外部补充标注清晰

## 四、LLM 客户端（crates/providers/src/client.rs）

- `OpenAiClient::new`（client.rs:27）：reqwest Client，**connect 超时 10s / 整体超时 300s**（防慢端点挂死 async 任务）。
- `chat_request`（client.rs:47）：POST `{endpoint}/chat/completions`；`chat_json` 加 `response_format: {"type":"json_object"}`（D4 第一跳）；tools 非空才携带 tools 字段。
- `parse_response`（client.rs:115）：纯函数，从 completion JSON 提取 Response。要点：
  - **D7 思考字段双变体**：`reasoning_content` / `reasoning` 取先命中者，空串视同无思考，单独存放不计入 content。
  - tool_calls 逐条提取，脏条目（缺 id/name）跳过不丢整响应。
  - usage 缺失/null 回退 0——"少记一次成本好过拒答合法响应"。
- 客户端本身**无重试**：弹性（降级/重试）全部上移给调用方，职责单一。

## 六、存储与检索（crates/storage）

### Schema 与迁移

- DDL 单点存放：`crates/storage/src/schema.sql` 即唯一事实源；改表先改 DDL 再写迁移。
- `migrate()`：`PRAGMA user_version` 逐版升级（当前 **v3** = quizzes/sessions.course_id 补 `ON DELETE SET NULL`——原为 NO ACTION，出过题或开过会话的删除课程会撞 FOREIGN KEY 约束；SQLite 不能 ALTER 外键，迁移以建新表拷数据重建）；WAL 模式 + foreign_keys ON。
- 课程定位：**UI 选择器一律走 id**（`/course --id N`、`/course -delete --id N`，store 有 `delete_course_by_id`）——对课程名的任何字符免疫；文本命令的名字定位支持多词（整段匹配 known 消歧）+ `<...>` 占位符无条件剥除（照抄文档容错）。
- `Store` = `Mutex<Connection>` 同步门面，靠 D2 由调用方进 blocking 池。

### 幂等去重

`content_hash`（store.rs）：SHA-256 前 16 hex 字符。`insert_note`（store.rs:206）事务内先按 hash 查重（**全局唯一，`notes.content_hash` UNIQUE 约束**），命中返回 `InsertOutcome::Duplicate { existing_id, existing_title, existing_course_id }`（导入层映射为 FileSkipped 事件并**带存活位置**：`⊘ 文件名（已存在：课程#id 标题）`——用户需要知道去哪删才能重导）。语义注意：删除某课程的笔记后重新导入同一文件，若同内容笔记在其他课程仍存活，依然会被去重跳过。

**收编例外**：命中的旧笔记躺在 all 区（course_id 为 NULL）且本次导入有明确归类（--course 指定或 LLM 抽取）时，pipeline 自动 `move_note` 收编——`⊘ 已原在 all 区，已归入课程 rust：#56 01-basic`。语义是"重新导入 + 指定课程 = 纠正分类"；已归属具体课程的笔记不会被搬去另一课。

### 中文检索（决策 D1）

- **同一条 jieba 管线**：`segment.rs` 全局 `OnceLock<Jieba>`，入库与查询共用 `cut_tokens`（segment.rs:22，过滤纯标点、去重保序）。
- MATCH 构造：每个词加**双引号**（内部引号翻倍转义）。`match_query`（segment.rs:41）= 空格连接（隐式 AND）；`match_query_or` = 显式 OR。
- **AND → OR 降级**（search.rs）：
  - note 级 `run`（search.rs:29）：AND 命中不足 top_k → OR 全量取回，对每个词单独 COUNT 补 `hit_terms`，按「命中词数 desc + bm25 asc」排序（复习出题侧使用）。
  - chunk 级 `run_chunks`（search.rs:147）：AND → OR，纯 bm25 排序（agent 检索主路径）。
- **范围语义**：`course_id = ? OR course_id IS NULL` = 当前课程 ∪ all 区；`course_id = None` 即全局不过滤。
- **两级文本**：notes.content 存清洗原文（展示/引用），notes_fts/note_chunks_fts 存预分词文本；chunk 的 `fts_extra` 字段把概念名拼进索引做 boosting，但不污染正文显示。

### Markdown 渲染管线（markdown.rs）

`render_markdown`（markdown.rs:15）三段式：

1. **跨事件文本聚合**：pulldown 会把 `[7]` 拆成 `"["`、`"7"`、`"]"` 独立 Text 事件，逐事件推送永远拼不出括号对；先聚合到 `text_acc`，遇结构事件在状态翻转**前**经 `drain_text!` 统一处理。
2. `LineBuffer`（markdown.rs:227 `push_text_with_refs`）：正文走 `[n]` 引用检测涂蓝；bold/italic/行内 code 记录进 StyleState。
3. `flush_as_lines`（markdown.rs:259）：展开为**逐字符样式流**（base 块级色 + 修饰叠加 + extra 覆盖），按显示宽度折行、同样式相邻字符合并 Span——样式跨折行边界不丢失。

### 复习模式闭环

- `start_review`（review.rs）：范围两种来源——无 `--concept` 走随机范围（`concepts_with_material` 里按掌握度加权随机抽概念子集，`Prng`/`weighted_sample` 无外部依赖，薄弱优先但范围随机治复读）；有 `--concept` 走自由文本（文本当检索 query + 注入 prompt，AI 自主解析覆盖哪些知识点）。素材按概念分组标注 → prompt 重构（P1-P5 + 禁止反例 + 认知层级）→ D4 出题（answer 字母→下标，`answer_to_index`）→ 入库 → ReviewState。
- **Review workspace**（ui.rs `draw_review_workspace`）：复习中主区从聊天流隔离为独立答题场——顶部 `✓/✗/●/○` 进度点（每颗独立配色：绿/红/黄/暗灰），`Question n/N` 黄 + 题型紫标签；**题干与解析走 markdown 管线**（`markdown::render_markdown`，与聊天流一致：行内代码橙 / 代码块 syntect 高亮 / 加粗），前缀 `  ` 缩进对齐 workspace；选择题 A-D 字母蓝、`❯` 光标黄、当前项亮白其余灰；**答后选项正误染色**（`ReviewResult::user_choice` 记用户选择：✓ 正确答案绿 / ✗ 误选红 / 其余灰）+ 反馈卡 `✓/✗ Correct/Incorrect` 彩条 + 得分 + 解析（复用 `explanation`）+ 缺失要点（Concept 绿）。**滚动/拖选复用聊天流机制**（收口会话⑪）：workspace 渲染行存进 `chat_lines`/`chat_rect`（拖选复制的坐标映射同源）、滚轮与 PageUp/PageDown 经 `scroll_up` 滚动视口（scroll_up=0 跟随最新，新内容到达吸附底部）——此前未存导致滚不动、拖选复制到过期聊天内容。聊天流仅出题完成时打一行 `· Review started · N questions`，逐题过程不再刷聊天流。**底部状态栏专属化**（ui.rs `draw_input`）：Review 时按答题态显示专属 hint——批改中… / `正在生成回答 · Esc 中断追问`（追问等待）/ `空 Enter 下一题 · 输入可追问 · Esc 退出复习`（反馈停留态）/ `↑↓ 选择 · A-D 作答 · Enter 提交 · Esc 退出`（选择题）/ `输入答案 · Enter 提交批改 · Esc 退出`（简答题，此时输入行即答案框，workspace 不再重复画答案行）；输入行前缀反馈态为 `追问：`；输入区高度随折行数动态增长。
- `handle_review_key`（app/keys.rs）：Answering 态 ↑↓ 移选项光标、A-D 直接作答、Enter 提交当前光标、简答字符进 `input`；Feedback 停留态（`ReviewState::awaiting_feedback()` = `results.len() > current`）Enter 推进下一题。`selected_option` 记录选择题光标；`ReviewResult::user_choice` 记录所选选项下标（答后染色用）。简答题 Enter 提交 `review_grading` 防并发错位，过期批改结果按 idx 丢弃。
- `grade_short_answer`（review.rs:333）：LLM 批改 `{score, missing, comment}`，score≥70 记正确。
- `finish_review_question`（app/review_flow.rs）：`record_attempt` + `update_concept_mastery`（UPSERT），失败经 `DatabaseFailed` 事件上报；随后**只记录结果进入反馈停留态**，不再逐题推进/刷聊天流。
- `advance_review`（app/review_flow.rs）：反馈停留态 Enter → `current += 1`（切题清 `followups`），到尾题则 `finish_review`。`finish_review`/`finish_review_state` 渲染静态摘要卡（正确数/每题 ✓✗/缺失要点/正确率）回聊天流，并**异步触发 LLM 小结建议**（`spawn_review_advice`：每题结果+概念名交给 LLM，生成 `{mastered, consolidate, next}` → `ReviewAdvice` 事件渲染「✓已掌握/△需巩固/→下一步」；失败静默不阻塞）。中途 Esc 退出若已有进度同样出部分摘要卡。
- **追问（收口会话⑪，⑬升级）**：反馈停留态输入行即追问框（前缀 `追问：`）——空 Enter 下一题、输入后 Enter 提交追问（答对答错都可）、Esc 退出；追问等待中 Esc = 中断（`followup_pending` token，agent loop 经 `tokio::select!` 竞速取消，占位行填充"（已中断）"）。`submit_followup` 打包题目上下文（题干/选项/正确答案/学生选择/解析/缺失 + 此前追问）→ **agent loop（挂 `SearchNotesTool`，course_id 取 `ReviewState.ctx`）**：system prompt 要求"涉及『笔记里有没有讲』必须先查笔记不许凭空判断"，工具循环回答（usage 记 review）→ `ReviewFollowup` 事件回流。**问题即时显示**（⑬）：提交时先 push `FollowupTurn{question, answer: None}`（workspace 显示"▍思考中…"占位），回流按问句匹配**填充**尾部 pending turn（不再等回答一起出现）。**追问不改判分不落库**，纯学习辅助。**引用脚注（⑰）**：search_notes 工具结果经 `extract_citations` 提取 [n]→笔记来源映射，`ReviewFollowup` 事件携带，workspace 回答下方渲染「── 引用来源 ──」脚注（此前只有编号没有来源）。workspace 渲染加尾部窗口（内容超区域只渲染最后 N 行，追问多轮不挤爆视口）。

### 成本控制（R6，双口径对账）

- **内存口径（即时）**：chat 的 Done 事件里 `total_cost += delta`，驱动 header 显示与发送前熔断（`submit`，app.rs:482）。
- **DB 口径（对账）**：所有 LLM 调用（chat/import/review/grade/outline）都写 usage_log；review/outline/import/grade 完成事件触发 `request_cost_sync`（app.rs:2139）读 `total_recorded_cost` 回投 `CostSynced`，取 `max(内存值, DB值)` 合并——成本单调递增，对账时该笔尚未落库也不会回退。
- `/budget [金额|reset]` 管理上限；reset 清 usage_log 并归零内存计数。
- **概念刷新（2026-08-30，`/refresh-concepts`）**：对当前分区课程逐篇重抽概念——**唯一输入 = DB 存储全文**（canonical content，不依赖源文件，语料目录删除后仍可跑）；逐篇 unlink 旧关联 → LLM 重抽（`extract_concepts`，与导入共用 `CONCEPT_RULES`）→ link 新概念；收尾 `prune_unlinked_concepts` 只清「零关联且零学习历史」的概念（**有 mastery 记录的绝不删**——学习历史不可丢，孤儿保留）。后端 `refresh_course_concepts` 在 importer（TUI 命令与 examples/refresh_concepts.rs 验收工具共用）；完成事件 `ConceptsRefreshed` 汇总 before/after 对比。动机：Review Map 前置——rust 课实测旧概念 22 个含形容词/空泛词/同义重复，刷新后 65 个知识点级概念零垃圾残留。

- **Theme 语义色**（theme.rs）：颜色是语义 token 而非装饰——`FG/MUTED/PRIMARY/SECONDARY/USER/SUCCESS/REFERENCE/ERROR/CODE_FG`（70/20/10 原则：正文低亮度灰白、亮色面积少）。所有 UI 文件经 `use crate::theme` 取色，换主题只改一个文件。
- **Markdown 层级**（markdown.rs）：H1=SECONDARY 紫+粗、H2+=SECONDARY_DIM 淡紫+粗、正文=FG 浅灰、行内代码=CODE_FG、`[n]` 引用=REFERENCE 青（RAG 品牌色；测试断言引用常量自动适配）。
- **Agent Trace 可见化（⑰ 审计后补缺）**：全链路审计 12 类 LLM/Tool 入口（chat/出题/批改/追问/小结/outline/refresh/import/diagnose/web），统一 trace = `Entry::Tool`（◌ running / ✓ / ✗ 生命周期）+ 文案前缀分类（[生成]/[批改]/[整理]/[抽取]/[搜索]）——**不伪造 tool_call**（非工具协议的 LLM 动作用动作前缀而非 Tool 字样）。审计结论与处置：chat（AgentActivity 已达标）/ 出题（workspace 等待行+header Generating+题目即完成，达标）/ 批改（header Grading+反馈卡，达标）/ 追问（workspace 思考行，达标）/ 摘要卡与 /review-map 热读（纯本地/DB，**正确地不显示**）/ web（tool_trace 字段达标）；**补缺三处**：① review 小结（START"[整理] 正在生成…"→✓ 完成 / ⚠ 失败三态，修复静默失败悬挂 running）；② outline 重组（中性开始行"[整理] 正在准备…"——是否真跑 LLM 由缓存签名决定不伪造，完成行区分 ✓ 重新组织 vs 缓存命中无 trace）；③ refresh-concepts（START/完成/失败统一风格）。原则：真实 LLM/工具动作才显示，纯 DB/统计/状态机跳转不显示。

- **状态指示器**：`status_label` 输出 `● Ready` / `◌ Thinking…` / `◌ Review 2/5 · Grading…` / `◌ Importing…`（符号+语义色）。
- **用户/AI 两套视觉语言**（ui.rs `push_prefixed_wrapped`）：前缀着色、正文浅灰——`你 ›`（USER 暖黄）/ `StudyPilot ›`（SECONDARY 蓝紫）/ `·`（MUTED）/ `✗`（ERROR），续行按前缀宽缩进对齐。
- **Review workspace 配色**（ui.rs `draw_review_workspace`）：进度圆点 `✓ 答对(绿) · ✗ 答错(红) · ● 当前(黄) · ○ 未到(暗灰)`；选项字母蓝（ACCENT）、`❯` 光标黄、当前项亮白、未选灰；答后选项 ✓ 绿 / ✗ 红；反馈彩条 + 缺失要点 Concept 绿。底部输入区高度随输入折行数动态增长（`wrap_input_with_cursor`，上限 8 行），hint 随答题态切换（选择题/简答/反馈/批改各一套）。
- **侧栏导航化**：`COURSES`/`RECENT` 分区标题（MUTED 大写）、当前课程 `●` + PRIMARY 粗体、其他课程 MUTED。
- **代码块语法高亮**（收口会话⑩，highlight.rs）：syntect（fancy-regex 纯 Rust 后端，无 C 依赖）+ base16-ocean.dark 主题（One Dark 系，与 theme.rs 同族）。markdown 代码块路径：Start 记录 fence 语言 → Text 独立累积（`code_buf`，不走 [n] 解析）→ End 拦截整块高亮，逐 token 染色 + `── {lang} ──` 标签 + 尾分隔线；未知语言回退 plain text，单行解析失败不影响其余行。SyntaxSet/ThemeSet 以 OnceLock 全局单例加载（jieba 同款模式）。
- **工具活动流**（收口会话⑩，core LoopEvent）：Agent 加 `with_on_event` 回调，loop 在每轮思考/每次工具调用前后 emit `LoopEvent::RoundStart/ToolStart/ToolDone`；TUI 经 `AgentEvent::AgentActivity` 实时渲染活动行——`◌ search_notes "查询"`（蓝紫）→ 完成后**原地替换**为 `✓ → N 条`（绿）/`✗`（红）。旧的事后 "Agent trace" 汇总输出移除（实时行已覆盖）；事后 tool_trace 字段保留。**调用纪律**：`finish_wizard` 在读取向导数据后才清理状态——调用方提前置 None 会让所有向导动作静默失效（已回归测试锁定）。
- **RAG 来源脚注**（收口会话⑩）：Done 事件时从 `new_messages` 解析 search_notes 的 tool 结果 JSON，建立 (编号→"标题 · 小节") 映射，扫描回答中被实际引用的 `[n]`（`extract_ref_numbers`），在回答底部渲染 `── 来源 ──` + `Entry::Citation`（Reference 青色）。多次搜索同编号以最后出现为准；未被引用的编号不显示。已落地：代码块 syntect 语法高亮（见上）。暂缓：概念词染色、课程身份色、引用悬停、Review 折叠摘要、多主题切换。
