## 一、全局架构

```
                    ┌─────────────────────────────────────────────┐
                    │                crates/tui (bin)              │
                    │  ratatui App │ 单线程所有权 + 统一 mpsc 事件总线  │
                    │  /import /review /outline 等斜杠命令 → 后台任务  │
                    └───────┬──────────────┬──────────────┬────────┘
                            │              │              │
                 ┌──────────▼───┐   ┌──────▼──────┐  ┌────▼─────────┐
                 │ crates/core  │   │crates/tools │  │crates/importer│
                 │ Agent Loop   │   │search_notes │  │ 解析→清洗→抽取  │
                 │ Provider trait│  │list_courses │  │ →入库流水线    │
                 │ Tool trait   │   │ (D6:只读工具) │  │              │
                 └──────┬───────┘   └──────┬──────┘  └────┬─────────┘
                        │                  │              │
              ┌─────────▼──────────┐      │              │
              │  crates/providers  │      │              │
              │  OpenAI-compatible │      │              │
              │  reqwest 非流式客户端│      │              │
              └────────────────────┘      │              │
                                          ▼              ▼
                                   ┌────────────────────────┐
                                   │     crates/storage     │
                                   │ rusqlite + FTS5(jieba) │
                                   │   data/mynotes.db      │
                                   └────────────────────────┘
```

**三条铁律（贯穿全库）：**

1. **D2 异步纪律**：rusqlite 与子进程调用一律 `tokio::task::spawn_blocking`，绝不在 async 上下文直接执行。
2. **单写回路**：TUI 中所有后台任务（聊天/导入/出题/批改/DB）都是 fire-and-forget 的 `tokio::spawn`，完成后把结果作为 `AppEvent` 投回**同一条** unbounded mpsc；`App` 状态只在主循环线程被修改，无锁无共享可变状态。
3. **命令 vs 工具（D6）**：`/import` `/delete` `/move` 等写操作/费用敏感操作直连内部函数，**不进 agent loop**；只有只读检索型工具（search_notes / list_courses）暴露给 LLM。
4. **命令参数全旗标化 + 向导直连（收口会话⑨）**：含自由文本字段的命令一律 `--字段 <值>`（`/review --course/--concept/--n`、`/import --dir/--course`、`/move --id/--course`、`/delete --id|--course`），旗标值可含空格、顺序无关——位置参数的"课程|概念"切分歧义从语法层面消除。向导完成时直连结构化入口，`handle_command` 文本解析仅服务手输路径（报错引导走向导）；`collect_flags` 通用旗标扫描为各命令共用。

## 二、三条主线数据流

### 导入（Import）

```
/import <dir> [--course 名]
  → walkdir 收集(排序确定) → 逐文件串行(费用/速率约束)
      ① parse_file:  md/txt 直读 │ pdf→python3 pdf_extract.py 子进程 │ pptx→zip+quick-xml
         产出 RawDoc { text, fts_text, content_hash }   ← content 与 FTS 两级分离
      ② clean:       content 层只剥 wikilink；fts 层再剔"目录"段+头部引用块
      ③ extract:     LLM 结构化抽取 {title, course, concepts}（D4 降级链）
      ④ 入库:        content_hash 幂等去重 → notes+notes_fts(jieba 预分词)
                     → 概念 get_or_create + 关联 → 按 ## 标题切 chunk 入 note_chunks(+_fts)
  全程 ImportEvent 过 mpsc 上报进度，CancellationToken 随时可停
```

### 学习（Study / RAG）

```
用户输入 → submit() → 预算熔断检查(R6) → history 入栈
  → spawn_chat(): Agent + ToolBox{search_notes, list_courses} + AI-Tutor system prompt
  → Agent::run_loop: LLM ←→ 工具 多轮循环 → 最终答案
  → Done 事件: 累计 usage/成本、persist 新消息、渲染 trace + markdown 回复
```

### 复习（Review）

```
/review <课程> [概念] [--n 数量]
  → 收集片段(search_chunks) + 概念掌握度(低掌握度排前)
  → LLM 出题(混合题型, D4 降级链) → quizzes/questions 入库
  → 答题: 选择题本地判分(零成本) / 简答题 LLM 批改(score/missing/comment)
  → 每题: record_attempt + update_concept_mastery(UPSERT 累计)
  → 下次出题 prompt 注入新掌握度 → 闭环
```

## 三、Agent Loop（crates/core/src/agent.rs）

核心函数：`run_loop`（agent.rs:93）、`execute_tool`（agent.rs:191）。

```
for round in 1..=max_rounds(默认12):
    resp = provider.chat(msgs, tools.schemas())
    if resp.tool_calls 为空 → 推入最终 assistant 消息，返回 AgentResult
    else:
        推入 assistant_tool_calls 消息
        逐个执行 tool call，结果以 tool_result 消息回填，继续循环
超过 max_rounds → Err（模型未收敛）
```

关键机制：

- **search_notes 防重门控**：单次会话最多 3 次真实检索，且 query 不可重复。重复/超限不执行工具，而是返回提示文本让模型换关键词或基于已有结果作答。坏参数（q 提取失败）则透传 `execute_tool` 让工具自身的参数校验回错给模型修正——不谎报"重复查询"。
- **错误不炸循环**：未知工具 / 参数 JSON 解析失败 / 工具执行失败统一转成 `TOOL_ERROR: ...` 文本喂回模型自行调整（`tool_error_text`）。
- **AgentResult** 附带 `total_usage`、`new_messages`（循环期间新增消息，供 TUI 持久化）、`tool_trace`（工具调用轨迹，含 query 与命中数，供 UI 展示）。
- **错误回喂格式**：`TOOL_ERROR [{category}]: {message}`——category（parse/storage/api/api_server/transport/config）机器可读，模型可据此决定"换参数重试/换工具/放弃"（ToolResult 协议的轻量版，不改 trait 签名）。

### Context Manager（core/src/context.rs）

长会话全量重发 history 会导致 token 成本线性上涨。`trim_history(history, budget)`：

- **轮次原子**：一轮 = user 消息 + 其后全部非 user 消息；裁剪以轮为单位，`assistant(tool_calls)` 与 `tool_result` **永不拆散**（拆散会被 API 拒收）
- **策略**：从最新轮往回累计字符预算，装不下的最老轮整体丢弃；单轮即超预算也至少保留最后一轮
- **省略注记**：裁剪发生时在保留段最前插一条 user 角色注记（`[对话裁剪提示: 早期 N 轮已省略…]`）——多数 endpoint 不接受中部的 system 消息，user 角色最稳
- **接线**：`Agent` 默认启用（`DEFAULT_CONTEXT_BUDGET_CHARS` = 24_000 字符 ≈ 8k token），`with_context_budget` 覆盖、`without_context_trim` 关闭；TUI 层零改动

### 检索评测框架（eval/ + crates/tui/examples/eval.rs）

- 题集 `eval/questions.jsonl`：31 个真实学习问题，每题带 expect 笔记关键词
- 评测器 `cargo run --release -p tui --example eval -- --out eval/report-*.md`：离线跑 chunk 级 FTS（不调 LLM、零成本），输出 rank1/top3/top5 命中率 + miss 明细
- **判定锚点用 `source_path` 文件名而非笔记标题**——标题是导入时 LLM 重写的，不稳定
- **`--llm` 模式（真调 API）**：完整 RAG 链路回答 + judge 评分（0-10 + 幻觉判定），每题 2 次调用，报告含成本记账；31 题全量约 ¥0.43
- **BM25 基线（2026-08-27）：rank1 18/31，top3 26/31，top5 28/31**。miss 归因：噪声笔记（plan/README）污染排序 > 词法盲区（rsp/死锁）。结论：下一步收益最大的不是 hybrid embedding，而是噪声降权 + 补语料

### 噪声降权（storage/search.rs）

大纲/计划/索引类笔记（`file_stem` 含 readme/plan/index/syllabus/agenda，或路径含"索引/目录"）污染检索排序——基线评测的直接结论。机制：

- **SQL 候选池放宽 3 倍**（`FETCH_MULTIPLIER`），惩罚重排在 Rust 层做
- `is_noise_source` 判定 → 命中 chunk 的 bm25 加罚 `NOISE_PENALTY=5.0` → 重排截断 top_k
- chunk 级 `run_chunks` 与 note 级 `run`（复习出题路径）都覆盖；note 级 OR 降级排序键为「命中词数 desc → 非噪声优先 → bm25 asc」
- **效果（评测实测）：rank1 58% → 71%，top3 84% → 87%**，原被 plan/README 压住的内容 chunk（如 #6 分块总结）恢复排名

### LLM 端评测结论

**严格模式（旧，report-llm.md）**：prompt 约束"仅依据资料回答"——rank1 题 7.2 分 vs 非 rank1 题 3.6 分（强相关），0 幻觉，但语料缺口题全部拒答 0 分。

**开放模式（现行，report-llm-open.md）**：产品决策调整为**「笔记优先 + 外部补充明示」**——
- 笔记有相关内容 → 优先依据并 [n] 引用（[n] 只指向笔记片段）
- 笔记未覆盖 → 允许用模型自身知识补充，但必须明示「（笔记外补充）」
- 幻觉重新定义：不再罚"用外部知识"，只罚**错误事实**与**把外部知识伪装成笔记引用**——来源可区分性是底线
- 落点三处：`app.rs build_rag_system_prompt` 约束段、`tools/search_notes.rs` 工具描述、评测器 prompt/judge 同步
- **实测：平均分 6.1 → 9.3，低分题清零，0 幻觉**；检索与分数的强相关消失（外部知识兜底），judge 逐题确认外部补充标注清晰

## 四、LLM 客户端（crates/providers/src/client.rs）

- `OpenAiClient::new`（client.rs:27）：reqwest Client，**connect 超时 10s / 整体超时 300s**（防慢端点挂死 async 任务）。
- `chat_request`（client.rs:47）：POST `{endpoint}/chat/completions`；`chat_json` 加 `response_format: {"type":"json_object"}`（D4 第一跳）；tools 非空才携带 tools 字段。
- `parse_response`（client.rs:115）：纯函数，从 completion JSON 提取 Response。要点：
  - **D7 思考字段双变体**：`reasoning_content` / `reasoning` 取先命中者，空串视同无思考，单独存放不计入 content。
  - tool_calls 逐条提取，脏条目（缺 id/name）跳过不丢整响应。
  - usage 缺失/null 回退 0——"少记一次成本好过拒答合法响应"。
- 客户端本身**无重试**：弹性（降级/重试）全部上移给调用方，职责单一。

## 六、存储与检索（crates/storage）

### Schema 与迁移

- DDL 单点存放：`crates/storage/src/schema.sql` 即唯一事实源；改表先改 DDL 再写迁移。
- `migrate()`：`PRAGMA user_version` 逐版升级（当前 **v3** = quizzes/sessions.course_id 补 `ON DELETE SET NULL`——原为 NO ACTION，出过题或开过会话的删除课程会撞 FOREIGN KEY 约束；SQLite 不能 ALTER 外键，迁移以建新表拷数据重建）；WAL 模式 + foreign_keys ON。
- 课程定位：**UI 选择器一律走 id**（`/course --id N`、`/course -delete --id N`，store 有 `delete_course_by_id`）——对课程名的任何字符免疫；文本命令的名字定位支持多词（整段匹配 known 消歧）+ `<...>` 占位符无条件剥除（照抄文档容错）。
- `Store` = `Mutex<Connection>` 同步门面，靠 D2 由调用方进 blocking 池。

### 幂等去重

`content_hash`（store.rs）：SHA-256 前 16 hex 字符。`insert_note`（store.rs:206）事务内先按 hash 查重（**全局唯一，`notes.content_hash` UNIQUE 约束**），命中返回 `InsertOutcome::Duplicate { existing_id, existing_title, existing_course_id }`（导入层映射为 FileSkipped 事件并**带存活位置**：`⊘ 文件名（已存在：课程#id 标题）`——用户需要知道去哪删才能重导）。语义注意：删除某课程的笔记后重新导入同一文件，若同内容笔记在其他课程仍存活，依然会被去重跳过。

**收编例外**：命中的旧笔记躺在 all 区（course_id 为 NULL）且本次导入有明确归类（--course 指定或 LLM 抽取）时，pipeline 自动 `move_note` 收编——`⊘ 已原在 all 区，已归入课程 rust：#56 01-basic`。语义是"重新导入 + 指定课程 = 纠正分类"；已归属具体课程的笔记不会被搬去另一课。

### 中文检索（决策 D1）

- **同一条 jieba 管线**：`segment.rs` 全局 `OnceLock<Jieba>`，入库与查询共用 `cut_tokens`（segment.rs:22，过滤纯标点、去重保序）。
- MATCH 构造：每个词加**双引号**（内部引号翻倍转义）。`match_query`（segment.rs:41）= 空格连接（隐式 AND）；`match_query_or` = 显式 OR。
- **AND → OR 降级**（search.rs）：
  - note 级 `run`（search.rs:29）：AND 命中不足 top_k → OR 全量取回，对每个词单独 COUNT 补 `hit_terms`，按「命中词数 desc + bm25 asc」排序（复习出题侧使用）。
  - chunk 级 `run_chunks`（search.rs:147）：AND → OR，纯 bm25 排序（agent 检索主路径）。
- **范围语义**：`course_id = ? OR course_id IS NULL` = 当前课程 ∪ all 区；`course_id = None` 即全局不过滤。
- **两级文本**：notes.content 存清洗原文（展示/引用），notes_fts/note_chunks_fts 存预分词文本；chunk 的 `fts_extra` 字段把概念名拼进索引做 boosting，但不污染正文显示。
- **课程统计与出题概念口径**：`course_stats` 的概念数与 `list_concepts_with_mastery`（出题概念清单）按 **"该课笔记关联的 DISTINCT 概念"** 计（JOIN note_concepts），而非概念的 `course_id` 归属——收编（move_note）只改笔记归属、概念归属留在原课/NULL，按归属统计会把收编课程显示成 0c 且出题概念清单为空。

## 九、TUI 层（crates/tui）

### 事件总线与主循环

`run`（app.rs:2220）：crossterm EventStream 与 100ms Tick 两个常驻生产者 → 统一 `AppEvent` mpsc → `loop { draw; recv; dispatch }`。所有 `on_*` 处理器只改 App 状态，下一帧 draw 反映。

按键路由优先级：复习模式 > **参数向导（Ctrl+K 触发）** > **列表选择器** > 命令面板（Ctrl+K）> /model 弹窗 > `v` 选择模式 > 普通（Enter 提交 / Ctrl+C 中断 / Ctrl+Q 强退）。

### 交互层模块结构（收口会话⑥ 重构）

app.rs（3147 行 god-file）拆分为：`app/mod.rs`（App 状态 + 事件分发 + 主循环）、`app/keys.rs`（全部按键/鼠标路由）、`app/commands.rs`（斜杠命令分发与 handler）、`app/chat.rs`（agent 接线与成本）、`app/sessions.rs`（会话持久化）、`app/review_flow.rs`、`app/outline_flow.rs`、`app/import_flow.rs`，加上顶层独立模块 `events.rs`（事件类型）、`input_edit.rs`（UTF-8 编辑纯函数）、`wizard.rs`、`palette.rs`（面板+选择器+模型弹窗数据）、`clipboard.rs`、`outline_render.rs`。方法跨 impl 块统一 `pub(crate)`。

### 命令面板交互体系

- **PaletteAction 绑条目**（替代字符串前缀分流）：`Run` 直执行 / `WizardReview` / `WizardImport` / `Prompt(title, prompt, prefix)` 单步文本向导（prefix 为**无占位符**的命令前缀，完成时 `prefix + 输入` 合成真实命令；条目 command 文本含占位符仅作列表展示）/ `Pick(kind)` 列表选择器。Tab 一律填入文本模式（power-user 兜底）。
- **分组显示与滚动**（收口会话⑨）：条目按五组排列（学习/知识库/课程/会话/系统，`PaletteGroup`），无过滤时渲染组头分隔行（不可选、键盘导航跳过）、**输入过滤即隐藏组头**；条目+组头超出视口时滚动（选中条目可见性对齐）。`/budget` 家族三条：查看 / 设置上限（Prompt 向导）/ reset 重置。
- **共享输入缓冲**（fzf 风格）：覆盖层打开时 `take_input_for_overlay` 备份聊天框内容并清空，过滤/输入直接落在 `App.input`（编辑键走普通路径，`sync_palette_filter` 同步过滤结果）；Esc 恢复备份、执行丢弃。palette/wizard 不再持有独立的 filter/input/cursor 状态。

### 状态可见性与命令面板（收口会话⑤）

- **状态可见性**：`App::status_label()`（app.rs）从覆盖层状态推导显示——`复习 n/m 题（·批改中）` > `导入中` > `思考中…` > `选择模式` > `就绪`，header 渲染并随状态变色（紫/黄/黄/青/绿）。与按键路由同源，替代原隐含状态机的"用户看不见"问题。
- **课程列表/统计刷新**：`request_courses_refresh()`（D2）——导入流水线可能在 DB 里 `get_or_create_course` 新建课程（归类/收编），内存 `courses` 与侧栏统计若不刷新就会缺失。触发点：导入 Finished/Cancelled、删课/建课操作完成、笔记删除/移动成功。
- **Toast 通知与选择模式移除**（收口会话⑨）：拖选复制的反馈改为**右上角 toast**（`Toast` 2.5s/错误 4s 自动消失，Tick 时过期清理，不插入聊天流）；`v` 选择模式（终端原生选中）整体移除——拖选复制已覆盖其用途，同时移除了鼠标捕获开关与相关状态。
- **会话归属课程标注**：sessions 表建会话时记录 `course_id`，且**跟随当前工作分区**——用户 `/course` 切换/新建/删课回落时，`update_session_course` 同步更新当前会话归属并刷新列表（会话是工作上下文载体，归属取"最后所在分区"，`/open` 恢复即回到该分区）。Recent 侧栏行尾与 `/sessions` 打印均显示归属课程（`course_label`，None=all）并**高亮当前打开的会话**（▸ + 强调色，仅 Ready 态）。
- **命令面板**（Ctrl+K，`CommandPalette`）：可发现性入口，交互范式复用 /model 弹窗。字符实时过滤（匹配命令+描述）、↑↓ 选择；**渲染三要点**：宽度按内容动态计算、对齐用 unicode 显示宽度（`display_pad`/`display_truncate`，中文字符按 2 列）、选中项完整信息显示在面板底行。Enter 行为分流：`/review`、`/import` → **参数向导**；其他无参命令直接执行、带参命令填入输入框；Tab 一律强制填入文本模式（power-user 兜底）。19 条命令与 /help 文案一一对应。
- **参数向导**（`Wizard`）：多步文本输入（每步预填默认值），Enter 推进、Esc 逐级回退并恢复已填值、第一步 Esc 取消。`/review`（概念默认空=全部、题数默认 5）与 `/import`（目录必填、课程预填当前分区、all 区留空=LLM 归类）两条接入；**课程自动取当前分区**，不弹课程选择。完成后**直连结构化入口**（`run_review` / `run_import` / `rename_session_id` / `create_course_flow`，字段以 i64/usize/Option 传递，不再合成命令字符串走文本解析），非数字题数安全回退默认 5。
- **/help 能力化**：按用户思维组织的四组能力说明（学习/知识库/复习/大纲 + 系统），示例先行；系统命令压缩为两行，指向 Ctrl+K 查看全部。

- **会话浏览器（收口会话⑨，session_browser.rs + app/sessions.rs）**：`/sessions` 与无参 `/open` 统一入口，范式同笔记浏览器。双模式（按标题 LIKE 过滤；Select：Enter/o 恢复、r 重命名任意会话、d 删除会话、/ 回搜索）。**安全边界**：当前打开的会话禁止删除（正被写入）；删除确认页明示"聊天记录级联删除且无法恢复"（会话无外部副本，语气比笔记重）。store 新增 `search_sessions`（LIKE title）与 `delete_session`（messages 外键级联）。重命名不再限当前会话。palette 移除 `/open` Pick 条目（/delete /move Fill 上轮已移除，/notes 即浏览器）。
- **header 左右分区**：左侧=学习位置（StudyPilot │ 课程），右侧=系统状态（模型·思考 │ 费用 │ 状态），中间空格填充右对齐。

`interrupt_or_quit`：导入中→取消导入；请求中→取消 LLM；空闲→退出。

### 会话持久化（R5）

三态机（app.rs:1994 `persist`）：

```
None ──首条消息──▶ Pending{buffered} ──SessionReady(id)──▶ Ready{id, saver}
                    │ 建会话失败                          │ 经 unbounded channel
                    ▼                                    ▼
            SessionCreateFailed:                 单写泵 spawn_saver_pump 顺序
            回退 None + 报错告知                   append_message（seq 递增）
```

消息存 Message 原样 JSON（含 tool_calls），`/open` 无损还原；恢复会话时连课程分区一起还原。

### Markdown 渲染管线（markdown.rs）

`render_markdown`（markdown.rs:15）三段式：

1. **跨事件文本聚合**：pulldown 会把 `[7]` 拆成 `"["`、`"7"`、`"]"` 独立 Text 事件，逐事件推送永远拼不出括号对；先聚合到 `text_acc`，遇结构事件在状态翻转**前**经 `drain_text!` 统一处理。
2. `LineBuffer`（markdown.rs:227 `push_text_with_refs`）：正文走 `[n]` 引用检测涂蓝；bold/italic/行内 code 记录进 StyleState。
3. `flush_as_lines`（markdown.rs:259）：展开为**逐字符样式流**（base 块级色 + 修饰叠加 + extra 覆盖），按显示宽度折行、同样式相邻字符合并 Span——样式跨折行边界不丢失。

### 复习模式闭环

- `start_review`（review.rs:98）：收集（薄弱概念排前）→ D4 出题 → 入库 → ReviewState。
- `handle_review_key`（app.rs:738）：选择题数字键本地判分；简答题 Enter 提交（`review_grading` 防并发错位，过期批改结果按 idx 丢弃）。
- `grade_short_answer`（review.rs:333）：LLM 批改 `{score, missing, comment}`，score≥70 记正确。
- `finish_review_question`（app.rs:872）：`record_attempt` + `update_concept_mastery`（UPSERT），失败经 `DatabaseFailed` 事件上报，不再静默吞错。

### 成本控制（R6，双口径对账）

- **内存口径（即时）**：chat 的 Done 事件里 `total_cost += delta`，驱动 header 显示与发送前熔断（`submit`，app.rs:482）。
- **DB 口径（对账）**：所有 LLM 调用（chat/import/review/grade/outline）都写 usage_log；review/outline/import/grade 完成事件触发 `request_cost_sync`（app.rs:2139）读 `total_recorded_cost` 回投 `CostSynced`，取 `max(内存值, DB值)` 合并——成本单调递增，对账时该笔尚未落库也不会回退。
- `/budget [金额|reset]` 管理上限；reset 清 usage_log 并归零内存计数。
