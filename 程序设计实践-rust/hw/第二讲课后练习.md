下面这段代码无法通过编译：

  

Rust

```
pub struct Job {
    pub name: String,
    pub payload: Vec<u8>,
}

fn process(p: Vec<u8>) -> usize {
    p.len()
}

fn audit(j: &Job) {
    println!("audited {}", j.name);
}

pub fn run(job: Job) -> usize {
    let payload = job.payload;
    let n = process(payload);
    audit(&job);
    n
}
```

报错信息如下：

  

Plaintext

```
error[E0382]: borrow of partially moved value: `job`
  --> snippet.rs:17:11
   |
15 |     let payload = job.payload;
   |                   ----------- value partially moved here
16 |     let n = process(payload);
17 |     audit(&job);
   |           ^^^^ value borrowed here after partial move
   |
   = note: partial move occurs because `job.payload` has type `Vec<u8>`, which does not implement the `Copy` trait

error: aborting due to 1 previous error
```

**(1) (20 分) 关于这段代码和这个报错，下面哪些说法是**对**的？**

  

- [ ] `let payload = job.payload;` 这一行把 `job` 整体移走了：`Job` 不是 `Copy`，赋值即移动。从这一行往后 `job` 就是个空壳，它的任何字段都不能再访问，`audit(&job)` 自然无法通过编译。
    
      
    
- [x] 移动是按字段追踪的：被移走的只有 `job.payload` 这一个字段，`job.name` 至今完好、可以照常读。无法通过编译的是 `audit(&job)` ——它要借用的是整个 `job`，而 `job` 现在缺了一块。
    
      
    
- [ ] `Vec<u8>` 没有实现 `Copy`，所以 `job.payload` 只能被移动而不能被复制。给 `Job` 加上 `#[derive(Clone, Copy)]`，这一行就从移动变成复制，`job` 原封不动，问题即解。
    
      
    
- [x] `process` 只是读一下长度，压根不需要所有权。把它的签名改成 `fn process(p: &[u8]) -> usize`、把取字段和调用那两行合成 `let n = process(&job.payload);`，这段代码不用 `clone` 也不用移动任何东西就能编过，`job` 自始至终完好。

### 第 3 题 (Total 20 pts)

下面这个函数能通过编译：

  

Rust

```
pub fn once(v: &mut Vec<i32>) {
    let first = &v[0];
    println!("first = {first}");
    v.push(0);
}
```

把那三行原封不动套进一个 `for` 里——语句的先后顺序一个字都没改——就编不过了：

  

Rust

```
pub fn thrice(v: &mut Vec<i32>) {
    let first = &v[0];
    for _ in 0..3 {
        println!("first = {first}");
        v.push(0);
    }
}
```

报错信息如下：

  

Plaintext

```
error[E0502]: cannot borrow `*v` as mutable because it is also borrowed as immutable
 --> snippet.rs:5:9
  |
2 |     let first = &v[0];
  |                 ----- immutable borrow occurs here
3 |     for _ in 0..3 {
4 |         println!("first = {first}");
  |                   ----- immutable borrow later used here
5 |         v.push(0);
  |         ^^^^^^^^^ mutable borrow occurs here

error: aborting due to 1 previous error
```

**(1) (20 分) 关于这个报错，下面哪个说法是**对**的？**

  

- [ ] 编译器拦的是 `push` 这个具体动作：`Vec::push` 可能扩容，一扩容就会释放旧缓冲区，`first` 手里的指针当场失效。把循环体里那次写换成不会重新分配的形式（比如 `v[1] = 0`），同样的结构就能通过。
    
      
    
- [ ] `first` 的作用域是从它的 `let` 一直到函数末尾，所以它自始至终借着 `*v`。上面那个版本能编过，是因为借用检查器对**不含循环**的函数体做了放宽；只要函数里出现循环，借用就退回按词法作用域算，从 `let` 活到函数末尾，循环里任何一次对 `v` 的写都会撞上它。
    
      
    
- [x] 借用的存活范围是在**控制流图**上算的，不是在源码文本上。循环的回边让 `println!` 那一行成为 `v.push(0)` 的**后继**——下一轮迭代还要读 `first`，所以 `push` 执行的那一刻这个借用确实还活着。
    
      
    
- [ ] 借用活到它在**源码文本**上最后一次出现的位置。这里 `println!` 印在 `v.push(0)` 的上面，`push` 执行时这个借用其实已经结束了，所以其实应该放行，报错是因为借用检查器实现不完善。
