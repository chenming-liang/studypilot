## 第 1 题：`for` 循环把 `Vec` 移走了（20 分）

**题面**：

```rust
pub fn report(v: Vec<String>) {
    let mut total = 0;
    for s in v {          // ← 这里把 v 移动了
        total += s.len();
    }
    println!("{total} bytes in {} strings", v.len());  // 错误：v 已被移动
}
```

**原因**：`for s in v` 等价于 `for s in v.into_iter()`，`into_iter` 会**拿走 `v` 的所有权**（`Vec<String>` 非 `Copy`）。循环结束后 `v` 已失效，最后的 `v.len()` 报 `E0382: borrow of moved value`。报错里的 hint 直接给出正解：`for s in &v`。

**答案：改 `for s in v.clone()`**——四个方案里只有它**引入原本不存在的堆分配**：

| 改法 | 新堆分配 | 原理 |
|---|---|---|
| `for s in &v` | ❌ | 按引用迭代，只是借用，`v` 循环后仍可用 |
| **`for s in v.clone()`** | ✅ | 深拷贝整个 `Vec<String>`：重新分配 `Vec` 缓冲区 + **每个 `String` 的堆缓冲区** |
| 循环前记 `let count = v.len()` | ❌ | 只记录长度（在移动前调用），无分配 |
| 签名改 `pub fn report(v: &[String])`，调用 `report(&v)` | ❌ | 传切片引用，无分配 |

**为什么 `clone` 是深拷贝**：`Vec<String>` 的 `clone` 不只复制外层 `Vec` 的指针，而是递归克隆每个 `String`——每个 `String` 都要在堆上**重新分配**自己的缓冲区。所以它是唯一新增堆分配（而且还不止一处）的方案。其余三个都是"不移动"或"先记下再移动"，零分配。

## 第 2 题：部分移动 (partial move)（20 分）

**题面**：

```rust
pub fn run(job: Job) -> usize {
    let payload = job.payload;   // ← 部分移动：把 payload 字段移走
    let n = process(payload);
    audit(&job);                 // 错误：job 缺了一块，不能再整体借用
    n
}
```

**原因**：`let payload = job.payload;` 只把 `job` 的 `payload` 字段**移动**出去（`Vec<u8>` 非 `Copy`），这叫**部分移动 (partial move)**。`job.name` 仍然完好，但 `job` 整体已经"缺了一块"——`audit(&job)` 要**借用整个 `job`**，所以报 `E0382: borrow of partially moved value`。

**答案：② 和 ④ 对**（多选）：

- **② 对**：移动是**按字段追踪**的——被移走的只有 `job.payload`，`job.name` 照常可读；错的是 `audit(&job)` 要借整个 `job`，而 `job` 缺了一块。
- **① 错**：不是"整体移走、任何字段都不能访问"。部分移动 ≠ 整体移动，`job.name` 依然有效。
- **③ 错**：`Job` 含 `String` 和 `Vec<u8>`，都**非 `Copy`**，`#[derive(Clone, Copy)]` 会**编译失败**（字段不满足 `Copy`）；即便只加 `Clone`，`let payload = job.payload;` 仍是移动（`clone` 不会自动套用）。
- **④ 对**：`process` 只需要长度，改成 `fn process(p: &[u8]) -> usize` 并调用 `process(&job.payload)`——**借用而非移动**，`job` 自始至终完好，无 clone 无移动。

## 第 3 题：NLL 与循环的回边（20 分）

**题面**：

```rust
pub fn once(v: &mut Vec<i32>) {     // 能编过
    let first = &v[0];
    println!("first = {first}");
    v.push(0);
}

pub fn thrice(v: &mut Vec<i32>) {   // 编不过
    let first = &v[0];
    for _ in 0..3 {
        println!("first = {first}");
        v.push(0);                  // 错误：first 的不可变借用还活着
    }
}
```

**原因**：**非词法生命周期 (NLL, non-lexical lifetime)** 让借用在**控制流图**上按"最后一次使用"结束，而不是按源码文本/词法作用域。

- `once`：`first` 的最后一次使用是 `println!`，之后借用结束，`v.push(0)` 合法。
- `thrice`：循环有**回边 (back edge)**——第 2 轮迭代还要读 `first`，所以 `println!` 那一行是 `v.push(0)` 的**后继**。`push` 执行的那一刻借用仍活着 → 不可变借用与可变借用并存 → `E0502`。

**答案：③ 对**：

- **③ 对**：借用的存活范围在**控制流图**上算，回边让 `println!` 成为 `push` 的后继，所以 `push` 时借用确实还活着。
- **① 错**：编译器拦的不是"`push` 可能扩容、指针失效"这个**实现细节**，而是"不可变借用存在时不能可变借用"这条**通用规则**。把 `v.push(0)` 换成 `v[1] = 0` 仍然是可变借用，同样编译不过。
- **② 错**：不存在"含循环就退回按词法作用域算"的特殊规则——NLL 对两种情况一视同仁，区别只在控制流图上 `first` 的存活长度不同。
- **④ 错**：借用不是按源码文本位置"最后一次出现"算的；编译器没有 bug，是回边让借用确实存活。

## 第 4 题：newtype 模式与规范化保证（40 分）

**场景**：`type UserName = String` 只是**别名**，`login` 无法保证参数真的经过 `user_name` 的规范化（trim + 小写）。

**核心思路**：把 `UserName` 从"别名"改成 **newtype**（`struct UserName(String)`，**私有域**），让构造**只能**走会规范化的 `new`——私有域是封装的根基。

### 4.1：标准 newtype —— 无上述缺陷 ✅

```rust
pub struct UserName(String);   // 域私有
impl UserName {
    pub fn new(raw: &str) -> UserName { UserName(raw.trim().to_ascii_lowercase()) }
    pub fn as_str(&self) -> &str { &self.0 }
}
```

- 域私有 → 外部**只能**通过 `new` 构造 → **无法绕过规范化**。
- `login` 用 `as_str()` 比较，行为不变；API 仍是 `&str` 入参。
- **答案：无上述缺陷。**

### 4.2：`new` 参数从 `&str` 改成 `String` —— 污染 API 表面

- 原 `user_name(raw)` 接受 `&str`；现在 `UserName::new(raw)` 要求 `String`，传 `&str` **编不过**（要先 `.to_string()`）。
- 功能没变、也不能绕过，但**公开 API 的调用方式变了**——调用方代码要跟着改。
- **答案：污染了 API 表面。**

### 4.3：`pub struct UserName(pub String)` —— 能绕过规范化 ❌

- 域标了 `pub`！外部可以直接 `UserName(任意字符串)` 构造，**绕开 `new` 的规范化**，把未规范化的名字传给 `login`。
- 这正是 newtype 要防的事——**私有域一旦公开，封装就破了**。
- **答案：能绕过规范化。**

### 4.4：用 `assert!` 拒绝而不是规范化 —— 悄悄改了语义

- 原版 `user_name` 是"**规范化**"：`"  Bob  "` → `"bob"`（去空白 + 小写）。
- 这版 `new` 是"**拒绝**"：首尾有空白或含大写 → `assert!` **panic**。
- 同一个输入 `"  Bob  "`，原版返回 `"bob"`，新版直接崩溃 → **行为发生了改变**。
- **答案：悄悄改了语义。**

## 小结

- **第 1 题**：`for v in collection` 会移动所有权；想保留集合用 `&v` / 先记 `len` / 改切片引用。`clone` 是唯一的深拷贝，会引入（多处）新堆分配。
- **第 2 题**：部分移动只移走被赋值的那个字段，其余字段仍可读，但不能再**整体**借用；改成借用字段即可解决。
- **第 3 题**：NLL 按控制流图计算借用存活，循环回边让"跨迭代使用"的借用一直存活到下一轮。
- **第 4 题**：newtype 用**私有域**强制"只能经构造函数创建"，从而保证不变量；`pub` 域、改 API 签名、把"规范化"改成"拒绝"都会破坏这一点。
