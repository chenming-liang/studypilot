## 所有权 (Ownership)

> 为什么需要所有权？动态对象在堆上按需分配，但"何时回收"最难判断——用户指定精确但易错，垃圾回收省心但慢。Rust 的选择：用**所有权**在编译期确定每个值的存活与释放。

**定义：** Rust 的所有权由三条规则刻画：

1. 每个值都有**所有者 (owner)**。
2. 同一时刻每个值**只有一个**所有者。
3. 当所有者失效，值也将被**丢弃**。

**所有权与变量绑定**：变量绑定**拥有**数据的所有权——绑定超出作用域时，其数据被**自动释放**（对堆上数据即释放空间）：

```rust
fn foo() {
    // 创建一个 Vec 对象，把所有权交给 v1。
    let mut v1 = vec![1, 2, 3];
    v1.pop();
    v1.push(4);
    // 作用域结束时 v1 离开，它仍拥有 Vec，故可被清理。
}
```

**注意**：所有权几乎都在**编译时**检查，运行时开销很小——这正是它与垃圾回收的关键差异。

**背景：C++ 的对比**。C 的 `new`/`delete`、C++ 的拷贝/移动构造语义解决了构造析构问题，但指针/引用**无法保证所指向的对象始终有效**——空指针 (null pointers)、悬垂指针 (dangling pointers)、双重释放 (double free) 等在运行时出错。C++11 用**智能指针 (smart pointers)**（`unique_ptr`/`shared_ptr`）配合 **RAII** 缓解，但因历史原因无法完全覆盖。

## 移动语义 (Move Semantics)

> 数据不能有多个所有者、拷贝又代价高昂，那么"把值传给另一个变量"时怎么办？——移动所有权，而不是拷贝。

**定义：** 把变量绑定给另一个变量时，数据的所有权**移动 (move)** 过去，原绑定被置为**无效**：

```rust
let v1 = vec![1, 2, 3];
let v2 = v1;           // 所有权移交给 v2
println!("{}", v1[2]); // 错误：使用了已移动的值 `v1`
```

**编译错误**：`error[E0382]: borrow of moved value` 在编译期捕获此问题，并提示可用 `.clone()` 按需拷贝。

**移动是编译期语义**：不涉及运行时的数据搬运，**不引入额外开销**（对比 C++ 的移动构造函数是运行时操作）；移动是**默认行为**（通过绑定/赋值），无需 `std::move` 显式指定。高级所有权管理可用 `std::mem::{replace, take, swap, drop}`。

**Copy 类型**：**Copy 特型 (trait)** 表示类型可以**拷贝**而非移动——通常是轻量级、**按位拷贝**的类型：

- 大多数基本类型是 `Copy`（`i32`、`f64`、`char`、`bool` 等）。
- 包含引用的类型**不是 `Copy`**（如 `Vec`、`String`）。

```rust
let x: i32 = 12;
let y = x; // `i32` 是 `Copy`，所以不移动 :D
println!("x: {}, y: {}", x, y); // 两者都可用
```

**自定义类型的 Copy / Clone（`#[derive]`）**：用 `#[derive(Clone, Copy)]` 属性让编译器**自动生成**这两个 trait 的实现：

- `Copy`：按位拷贝，赋值/传参自动发生；**要求所有字段都必须是 `Copy`**——所以含 `String`、`Vec` 的类型**无法** `derive(Copy)`（编译错误）。
- `Clone`：提供显式的 `.clone()` 深拷贝；只要求字段都实现 `Clone`，不要求 `Copy`。

```rust
#[derive(Clone, Copy)]
struct Point { x: i32, y: i32 }              // 所有字段 Copy → 可以

#[derive(Clone)]
struct Job { name: String, payload: Vec<u8> } // 只能 Clone，不能 Copy
```

**所有权的转移**：函数传参若每次都移交所有权，就得"借了再还"，返回类型越来越长——这引出**借用**：

```rust
fn vector_length(v: Vec<i32>) -> Vec<i32> {
    v // 把所有权还给调用者
}
```

## 借用 (Borrowing)

> 不想移交所有权，只想"临时看看/改改"——用引用**借用**数据。

**定义：** **借用 (borrow)** 即对变量**取引用**来访问其数据，**所有权并不转移**：引用超出作用域时借用结束，原变量仍拥有数据：

```rust
let v = vec![1, 2, 3];
let v_ref = &v;   // 借用 v
assert_eq!(v[1], v_ref[1]);
```

**借用的限制**：存在引用时，**不能移交**该数据的所有权——所有权移交会使引用失效：

```rust
let v = vec![1, 2, 3];
let v_ref = &v;
let v_new = v;   // 错误：`v` 已被借用，无法移出
```

**可变借用 (mutable borrow)**：用 `&mut` 取得**可变引用** `&mut Vec<i32>`，可修改被借数据；引用默认不可变：

```rust
fn push(vec_ref: &mut Vec<i32>, x: i32) {
    vec_ref.push(x);
}
```

**可变借用会改写原数据**：`&mut` 指向与变量**同一块内存**——通过可变引用写入，就是在改被借用的原变量本身（引用只是借用、从不拷贝）：

```rust
let mut a = 5;
let ref_a = &mut a;
*ref_a = 4;          // 写的是 a 所在的内存
// ref_a 不再使用，借用结束（NLL）
println!("{}", a);   // 4 —— 原变量已被改写
```

- **注意**：借用**期间**，原变量 `a` 不能再被直接访问（多读单写），只能走引用 `*ref_a`；借用结束后原变量可见新值。
- **对比**：`Copy` 的拷贝（`let y = x`）得到独立副本，修改不会回流到原变量。

**借用与函数**：函数传参默认会**移动所有权**，用完还得"借了还"（如移动语义里的 `vector_length`），返回类型越来越长；用引用传参则只是**借用**，函数结束后原变量依然可用：

```rust
fn length(vec_ref: &Vec<i32>) -> usize { // 参数是引用：借用，不拥有
    vec_ref.len()
}

fn main() {
    let vector = vec![];
    length(&vector);              // 传 &，借给它
    println!("{:?}", vector);     // 还能用：所有权没丢
}
```

- 借用作用域 = `length` 函数的执行期间，函数一返回**借用即结束**，原变量恢复正常。
- 调用方法时 `vec_ref` 会自动**解引用 (dereference)**（`vec_ref.len()` 等价于 `(*vec_ref).len()`）。

**何时需要显式解引用 `*`**：自动解引用只发生在"读取"场景——方法调用、字段访问、下标访问都会自动取内容；下面两种情形编译器无法替你决定，必须显式写 `*`：

- **写入 / 赋值**：自动解引用不作用于赋值左侧，给引用目标写值必须写 `*`（如上面的 `*ref_a = 4`）。
- **参与运算符 / 比较**：二元运算符不会自动解引用，`&i32` 不能直接与 `i32` 相加或比较，需显式 `*`：

```rust
let x = 12;
let ref_x = &x;
println!("{}", *ref_x + 4); // 必须 *：&i32 不能直接与 i32 相加
if *ref_x == 5 { }          // 必须 *：否则是 &i32 == i32，类型不匹配
```

- 判断口诀：**"读可以省，写和算要显式。"**——读取（方法/字段/下标）自动解引用；写入（赋值左侧）与运算符（`+`/`==` 等）需显式 `*`。

- **注意**：不能 `let vector = *vec_ref;` 解引用后绑定给变量——那会**移出**被引数据的所有权（引用仍存活）。

## 借用规则 (Borrowing Rules)

> 借用带来的核心约束是什么？——"要么多个读者、要么一个写者"。

**定义：** 借用的内在逻辑可归纳为：

1. 不能在对象**不存在**后继续保留对它的引用。
2. 一个对象可同时有**多个不可变引用** `&T`。
3. 或者**仅有一个可变引用** `&mut T`。
4. 以上两者**不能同时存在**。

即"**多读单写**"：要么共享读、要么独占写，二选一。

**"多读单写"的通用解读**：把原变量与引用**一视同仁**，都看作一条**访问路径**；规则约束的是"访问"而非"变量"。每次访问只分两类——**读**或**写**，冲突关系为：**读读共存、读写互斥、写写互斥**：

```rust
let mut v = vec![1, 2, 3];

// ① 读 + 读：共存（&v 是一次读，直接读 v 也是读，不冲突）
let r = &v;
println!("{}, {}", v[0], r[0]);   // 两个读者共存
// r 不再使用，借用结束

// ② 写 + 任何：冲突（&mut v 是独占写，此后任何读/写路径都被拒绝）
let m = &mut v;
// println!("{}", v[0]);  // 错误：读 + 写互斥
// v.push(4);             // 错误：写 + 写互斥
m.push(4);                 // 唯一合法访问
```

- **原变量没有特殊地位**：它只是另一条访问路径——直接读 `v` = 一次读，直接写 `v` = 一次写，按冲突表照常检查，不因是"原变量"而网开一面。
- 借用结束（NLL）后访问路径恢复空闲，原变量的读写权限一并归还。

**非词法生命周期 (NLL, non-lexical lifetime)**（2018 版特性）：对象或引用的寿命取决于**控制流图**而非词法作用域——只要不再使用，生命周期可提前结束，使借用检查更灵活：

```rust
fn main() {
    let v = vec![1, 2, 3];
    let v_ref = &v;
    let v_new = v;   // v_ref 已不再被使用，寿命提前结束，可移动
}
```

**借用的作用：在编译期拦截两类典型内存错误**：

- **迭代器失效**：迭代时修改集合。C++/Java 能写但运行时出错（如 Java 的 `ConcurrentModificationException`）；Rust 在编译期拒绝：

```rust
let mut vs = vec![1, 2, 3, 4];
for v in &vs {
    vs.pop(); // 错误：vs 已作为不可变借用被循环使用，不能再可变借用
}
```

- **use-after-free**（释放后使用）：引用悬垂。Rust 报 `E0597: does not live long enough`：

```rust
let y: &i32;
{
    let x = 5;
    y = &x; // 错误：`x` 存活时间不够长
}
println!("{}", *y);
```

**注意**：通过借用机制，Rust 在**编译时**解决大多数内存安全问题。

**绑定 × 引用组合总表**：访问数据的可变性由两个**正交**维度决定——**绑定**（`let` 还是 `let mut`）与**引用类型**（`&T` 还是 `&mut T`）：

| 绑定 | 引用类型 | 示例 | 效果 |
|---|---|---|---|
| 不可变 | —（直接拥有值） | `let x = 5;` | 不能改 |
| 可变 | —（直接拥有值） | `let mut x = 5;` | 能改 |
| 不可变 | `&T` | `let r = &x;` | `r` 不能重绑，`*r` 不可写 |
| 可变 | `&T` | `let mut r = &x;` | `r` 可换指向，`*r` 仍不可写 |
| 不可变 | `&mut T` | `let r = &mut x;` | `r` 不能重绑，但 `*r` 可写 |
| 可变 | `&mut T` | `let mut r = &mut x;` | `r` 可换指向，`*r` 也可写 |

- **绑定上的 `mut`** 决定"变量能否**换值/换指向**"；**引用类型上的 `&mut`** 决定"能否通过引用**修改底层数据**"——两者独立、可组合。
- 对应到方法：`&mut self` 是"绑定不可变 + 可变引用"（常用写法）；`mut self` 是"可变绑定 + 按值拥有"（消费自己时用，见方法节）。

## 切片与迭代 (Slices & Iteration)

> 切片是"引用序列中一段"的特殊引用；遍历集合有按所有权状态分的三种方式。

**定义：** **切片 (slice)** 是特殊形态的引用，表示序列中的一段；构造语法 `&x[s..t]`（`s`/`t` 可省略，也支持 `&x[s..=t]`）；可变性与引用的约束同样适用：

```rust
let a = [1, 2, 3, 4, 5];
let slice = &a[1..3];
assert_eq!(slice, &[2, 3]);
```

**向量的三种迭代方式**（对应三种所有权状态）：

```rust
for v in &vs      { /* 不可变借用，也可写 vs.iter() */ }
for v in &mut vs  { *v += 1; /* 可变借用，也可写 vs.iter_mut() */ }
for v in vs       { /* 拿走所有权，也可写 vs.into_iter()；之后 vs 无效 */ }
```

## 结构体 (Structs)

> 需要把若干字段"打包"成一个类型——用结构体保存数据。

**定义：** **结构体 (struct)** 用 `name: type` 声明**域 (field)**（成员变量）；像 C/C++ 的结构体，用于**保存数据**。按惯例结构体用 CamelCase、域用 snake_case：

```rust
struct Point {
    x: i32,
    y: i32,
}
let origin = Point { x: 0, y: 0 };
```

**访问与初始化**：域用**点记号**访问；结构体**不能部分初始化**——要么创建时给所有域赋值，要么先声明未初始化再整体赋值：

```rust
let mut p = Point { x: 19, y: 8 };
p.x += 1;

let q: Point;
q = Point { x: 1, y: 2 };
```

- **注意**：结构体**没有域级可变性**——可变性是绑定的属性（内部可变性可用 `Cell` 实现，后续再讲）：

```rust
struct Point {
    x: i32,
    mut y: i32, // 非法！
}
```

**访问权限（可见性）**：三条规则——① 结构体本身默认私有，`pub` 才对外可见；② 结构体的**域**默认私有，`pub` 才公开；③ **私有域**只有"结构体所在模块内"的代码能访问。

把模块想成一堵墙：**墙内**（模块里的 `new`、`impl` 方法）能访问私有域；**墙外**（`main`、其他模块）只能看到标了 `pub` 的东西：

```rust
mod foo {
    pub struct Point {
        pub x: i32,   // 墙外能读
        y: i32,       // 私有：墙外看不见
    }

    pub fn new(x: i32, y: i32) -> Point {
        Point { x, y }  // 墙内：能访问私有域 y
    }
}

fn main() {
    let p = foo::new(1, 2);  // 只能通过公开的 new 构造
    println!("{}", p.x);     // OK：x 是 pub
    // println!("{}", p.y);  // 错误：y 私有
}
```

**推论（封装）**：由于初始化必须给**所有**域赋值、而私有域墙外看不到，**含私有域的结构体墙外无法直接构造**（写 `foo::Point { x: 12, y: 12 }` 会报"y 是私有的"）。于是外部对象只能走模块公开的接口（构造函数 `new`、`pub` 方法）——内部状态对外不可见、不可改，这正是封装的用意。

**更新语法 (struct update syntax)**：初始化时用 `..s` 从 `s` 继承未指定的域（两个结构体类型必须一致）：

```rust
struct Foo { a: i32, b: i32, c: i32, d: i32, e: i32 }
let mut x = Foo { a: 1, b: 1, c: 2, d: 2, e: 3 };
let x2 = Foo { e: 4, ..x };
x = Foo { a: 2, b: 2, e: 2, ..x }; // 便于批量更新多个域
```

- **注意**：`..s` 必须放在字面量的**最后**（官方语法称"以 `..` 收尾"）——它表示"其余字段从 `s` 继承"，编译器需要先确定显式指定的字段；`..` 之后不能再写字段：
  ```rust
  let x3 = Foo { ..x, e: 4 };        // 错误：..x 必须在最后
  let x3 = Foo { e: 4, ..x, f: 5 };  // 错误：..x 之后不能再有字段
  ```

**拷贝还是移动？** 取决于被继承的域的类型——`Copy` 域**拷贝**（原结构体仍可用）；非 `Copy` 域**移动**，源发生**部分移动**、被移走的域失效：

```rust
struct Bar { name: String, id: i32 }
let b = Bar { name: "hi".to_string(), id: 1 };
let b2 = Bar { id: 2, ..b };   // name（String）被移动走
// println!("{}", b.name);    // 错误：b.name 已被移动
println!("{}", b.id);          // 可以：id 是 Copy 且没被继承
```

## 元组结构体与单位元结构体 (Tuple & Unit Structs)

> 结构体的两种简化形态：有名字无域名，以及完全无域。

**元组结构体 (tuple struct)**：有结构体名字、**没有域的名字**，按数字 `x.0` 访问，也可 `match` 匹配：

```rust
struct Color(i32, i32, i32);
let mut c = Color(0, 255, 255);
c.0 = 255;
match c {
    Color(r, g, b) => println!("({}, {}, {})", r, g, b),
}
```

**用途：newtype 模式**——用**只有一个域的元组结构体**包一层，创建**新类型**而非别名：即使底层结构一模一样（都是 `i32`），`Meters` 和 `Yards` 也**不是同一种类型**，混用会被编译期拦截：

```rust
struct Meters(i32); // 与 Yards 不同型，不可直接比较/相加
struct Yards(i32);

type MetersAlias = i32; // 别名：可与 YardsAlias 混用
type YardsAlias  = i32;
```

- **对比 `type` 别名**：`MetersAlias` 就是 `i32` 的另一个名字，能与同为 `i32` 的 `YardsAlias` 混用——别名不产生新类型、不做隔离。

**单位元结构体 (unit struct)**：零大小、无域、可实例化，用作**标记类型**：

```rust
struct Unit;
let u = Unit;
```

## 枚举 (Enums)

> 数据"可以是几种类型之一"——用枚举表达这种多选一。

**定义：** **枚举 (enum)** 是**和类型 (sum type)**（相对地，结构体/元组是**积类型 (product type)**），比 C/C++/Java 的枚举强得多：每种**变体 (variant)** 可无数据（单位元变体）、有命名域（结构体变体）、或有有序无名域（元组变体）：

```rust
enum Resultish {
    Ok,
    Warning { code: i32, message: String },
    Err(String),
}
```

- **注意**：枚举体里每一项都必须是**变体**——类型不能"裸奔"直接写在枚举体里，只能作为变体的**载荷**（`Variant(类型)` 或 `Variant { 域: 类型 }`）。若写 `enum E { i32, i64 }`，这里的 `i32`/`i64` 只是**变体名**（恰好是合法标识符；小写变体名会触发 `non_camel_case` 警告），定义出的是两个**无载荷**变体，跟类型无关。

**作用：表达"多选一"且能携带数据的状态集合**。枚举的变体是**封闭集合**，这个特性带来三个价值：

- **让"非法状态"无法被表示**：如 `Shape::Circle(f64)` 必带半径、`Shape::Rectangle { w, h }` 必带宽高，类型系统强制带对数据，构造不出"数据缺失"的非法形状。
- **配合 `match` 穷尽匹配**：编译器能检查所有变体是否都被处理，漏一个就编译报错——杜绝"忘了某个分支"的运行时 bug。
- **标准库两大台柱就是枚举**：`Option<T>`（`Some`/`None`，可空值的安全写法）与 `Result<T, E>`（`Ok`/`Err`，错误处理）——猜数游戏里 `guess.trim().parse()` 返回 `Result`，用 `match` 分 `Ok`/`Err` 处理。

**使用**：变体在枚举自己的名字空间中（`Resultish::Ok`），可用 `use Resultish::*` 引入；枚举可 `match` 匹配；**构造器 (constructor)** 可像函数一样使用（`Resultish::Ok`），后续讲迭代器/闭包时很有用：

```rust
match make_request() {
    Resultish::Ok => println!("Success!"),
    Resultish::Warning { message, .. } => println!("Warning: {}!", message),
    Resultish::Err(s) => println!("Failed: {}", s),
}
```

## 递归类型与 Box (Recursive Types & Box)

> 想定义递归的 `List`，直接写会怎样？——编译器会报"无穷大小"。

**定义：** 可以定义递归类型，如函数式风格的 `List`：

```rust
enum List {
    Nil,
    Cons(i32, List),
}
```

**问题**：结构体/枚举默认**内联存储**，直接递归产生**无穷大小**——`error[E0072]: recursive type List has infinite size`。

**Box**：**定义：** `Box<T>` 是指向**堆上对象**的指针、作为对象的**唯一所有者**（不能创建别名）；超出作用域**自动销毁**；用 `Box::new()` 创建。递归经 `Box` 等**间接层 (indirection)** 指向堆上数据，打破循环：

```rust
let boxed_five = Box::new(5);

enum List {
    Nil,
    Cons(i32, Box<List>), // OK!
}
```

**为什么不用原始指针 / 引用**：间接层不止 `Box` 一种，但各有取舍——

- **原始指针 `*const List`**：语法上可行（`Cons(i32, *const List)` 大小同样固定），但它**不拥有数据**（不会自动释放，需手动管理，易泄漏/双重释放）、**解引用必须 `unsafe`**（编译器不再保证内存安全）。
- **引用 `&List`**：`&` 只是借用，必须有一个外部存活的 owner；递归结构想"自己持有自己"时没有这个 owner，只能借不持有，难以构建可变链表。
- **`Box` 是"拥有型指针"**：既是指针（固定大小、打破内联），又拥有数据（自动释放），又安全（借用检查器管着解引用）——递归类型的正解。

| 方式 | 固定大小 | 拥有数据、自动释放 | 安全解引用 |
|---|---|---|---|
| `List`（直接内嵌） | ✗ 无限大小 | — | — |
| `&List` | ✓ | ✗ 只借用 | ✓ |
| `*const List` | ✓ | ✗ 不拥有 | ✗ 要 unsafe |
| **`Box<List>`** | ✓ | ✓ | ✓ |

- **注意**：递归必须经间接层（`Box`/`Rc`/`&`）间接存储，否则无限大小。

## 方法 (Methods)

> 把操作数据的行为挂到类型上——用 `impl` 定义方法。

**定义：** 结构体/枚举的方法定义在 `impl` 块中，通过**点记号**访问；可用 `pub` 公开方法（`impl` 块本身不需 `pub`）：

```rust
impl Point {
    pub fn distance(&self, other: &Point) -> f32 {
        let (dx, dy) = (self.x - other.x, self.y - other.y);
        ((dx.pow(2) + dy.pow(2)) as f32).sqrt()
    }
}
```

**方法的所有权：`self` 的三种形态**决定方法所需的所有权种类：

- `&self`：**借用**对象（尽量用，类比 C++ 常成员函数）。
- `&mut self`：**可变借用**对象（需修改时，类比普通成员函数）。
- `self`：**获得所有权**（消耗对象，可返回其他值）。

```rust
impl Point {
    fn distance(&self, other: &Point) -> f32 { /* ... */ }
    fn translate(&mut self, x: i32, y: i32) {
        self.x += x; self.y += y;
    }
    fn mirror_y(self) -> Point {
        Point { x: -self.x, y: self.y }
    }
}
```

## 关联函数 (Associated Functions)

> 没有"接收者"的函数，如何挂在类型上？——关联函数，扮演构造函数的角色。

**定义：** **关联函数 (associated functions)** 与方法类似但**没有 `self` 参数**，用**名字空间语法** `Point::new()` 调用（而非 `Point.new()`），类似 C++ 静态成员函数：

```rust
impl Point {
    fn new(x: i32, y: i32) -> Point { Point { x, y } }
}
let p = Point::new(1, 2);
```

- **注意**：Rust **没有内置构造函数语法**、不会自动构造；约定以 `new` 作构造函数。
**实现限制**：

**不能重载**——同一作用域里一个名字只能对应一个定义，即使参数类型/个数不同也不行（与 C++/Java 不同）。所以"多种构造方式"只能用**不同名字**：`Vec::new()` 与 `Vec::with_capacity(100)` 都是构造函数但名字不同。Rust 偏好"一个名字一个含义"的显式性——重载会让"这次调哪个"要靠参数去猜，复杂化类型推断。

**不能继承**——结构体/枚举没有类继承，方法不会从"父类型"自动获得。复用靠两种方式：

- **合成 (composition)**：把别的类型当自己的**域**装进来，复用靠"持有"而非"继承"：

```rust
struct Animal { name: String }
struct Dog {
    animal: Animal,   // 合成：Dog 里装一个 Animal
    breed: String,
}
```

- **特型 (trait)**：定义**共享行为**、多个类型各自实现（类似 Java 的 interface），提供"基本继承"；其中**默认方法 (default methods)** 最接近"继承"——trait 里给方法写默认实现，实现者不写就用默认：

```rust
trait Speak {
    fn name(&self) -> String;      // 必须实现
    fn speak(&self) {              // 默认实现：可以不写
        println!("{} makes a sound", self.name());
    }
}
impl Speak for Dog {
    fn name(&self) -> String { "Dog".into() }
    // speak() 用 trait 的默认版
}
```

## 模式匹配 (Pattern Matching)

> 解构结构化数据：把字段按需取出来绑定。

**定义：** 用 `match` 对结构体**解构 (destructure)**；域可乱序、可改绑定名（`y: y1`）、可用 `..` 忽略其余：

```rust
// 例 1：绑定所有域
match p {
    Point { x, y } => println!("({}, {})", x, y),
}

// 例 2：只绑定 y，.. 忽略其余域（这里即忽略 x）
match p {
    Point { y, .. } => println!("{}", y),
}
```



**按引用匹配**：`ref` 使绑定按**引用 (bind by reference)**而非按值（按值会取走所有权）；`ref mut` 则以可变引用匹配（被匹配对象须 `mut`）：

```rust
match x {
    ref r => println!("Of type &i32: {}", r),
}
match x {
    ref r if x == 5 => println!("{}", r),
    ref mut r => *r = 5,
}
```

**if let / while let / let else**——"只想匹配一个分支"时的便捷语法：

- **`if let`**：单个模式匹配 + 不匹配时的处理：

```rust
if let Resultish::Err(s) = make_result() {
    println!("Total and utter failure: {}", s);
} else {
    println!("ok.");
}
```

- **`while let`**：循环直到匹配失败：

```rust
let mut v = vec![1, 2, 3];
while let Some(x) = v.pop() { println!("{}", x); }
```

- **`let else`**：期望正常匹配、失败时做处理并提前返回：

```rust
let Some(x) = make_result() else {
    println!("Total and utter failure.");
    return Err(());
};
println!("ok.");
Ok(x)
```

**内部绑定 `@`**：把匹配的**一部分**绑定到变量，用于复杂嵌套结构：

```rust
match x {
    a @ A::None              => println!("a is A::{:?}", a),
    ref a @ A::Some(B::None) => println!("a is A::{:?}", *a),
    A::Some(B::Some(b @ 1..=2)) => println!("b is {:?}", b),
    A::Some(b @ B::Some(_))  => println!("b is B::{:?}", b),
}
```

**使用场合**：不止 `match`——`let`/`if let`/`while let` 绑定、`for` 循环的循环变量（如 `for (i, x) in v.iter().enumerate()`）、**函数/闭包参数**（如 `fn tuple_add((a, b): (i32, i32)) -> i32`）都可用模式。

## 小结

- **所有权与借用**：一个变量同时只能有多个不可变引用、或一个可变引用；函数参数与返回值遵循与变量绑定相同的规则。
- **结构化数据**：结构体（积类型）、枚举（和类型）。
- **模式匹配**：可在各种场景解构数据。
